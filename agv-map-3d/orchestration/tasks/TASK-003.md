## 任务描述

### 可验证结果

任意 `unknown` 输入只有经过逐层、逐字段校验后，才能成为仅包含渲染管线实际消费字段的原始地图数据。错误响应包、错误提取路径、非法判别联合或字段类型均被结构化拒绝，不存在未经验证的类型断言。

### 输入

- SPEC 第 2.1、2.2、5.1、5.3 第 1、2、5、6、7、8、11 项，以及第 14.1、15.2、16 章。
- TASK-002 交付的固定身份样本和唯一生成副本。
- TASK-001 交付的领域、适配和应用层依赖边界。

### 输出

- 唯一的 `unknown` 到受校验原始地图数据边界，严格按 `response.data.currentMapInfoVersion.mapJson` 提取。
- 对响应状态、地图元数据、四个集合字段、节点字段、边公共字段及 LINE/BEZIER 判别联合的逐字段验证。
- 原始数据只保留 SPEC 明确消费的字段；允许存在的额外业务元数据不会进入领域层。
- 节点类型只允许 `node/work/park/charge`，边类型只允许 `LINE/BEZIER`；未知类型没有默认值或默认样式。
- LINE 控制字段必须全部为 `null`；BEZIER 控制字段必须全部为有限数，部分为空直接失败。
- 结构化地图数据错误至少包含稳定错误码、JSON path、可用时的实体 ID 和简体中文可读消息。
- 响应包或提取路径错误使用 `MAP_ENVELOPE_INVALID`；实体字段或判别联合错误使用 `MAP_ENTITY_INVALID`，不得按调用位置生成不稳定错误码。
- 覆盖合法真实样本及各类结构、字段和判别联合失败的自动化验证。

### 实现约束

- 解析边界必须从 `unknown` 开始，禁止先断言为 DTO、把任意字符串强转联合类型或用非空断言跳过验证。
- `mapJson` 是对象而不是 JSON 字符串，不得二次 `JSON.parse`；不得从根对象直接读取 `nodes` 或 `edges`。
- 数字必须是有限的 JavaScript number，禁止接受数字字符串、`NaN` 或 `Infinity`。
- 字段验证与跨实体语义验证职责必须分离；本 TASK 不实现坐标转换、轨迹分组、几何生成或渲染。
- 错误路径不得跳过坏实体、补默认值或返回部分地图。
- 所有关键判别和错误映射使用可单独测试的纯逻辑，不能埋在 React 组件、worker 消息处理或渲染层中。
- 新增或修改的代码必须使用多行简体中文注释说明信任边界、判别联合和错误上下文；不得主动格式化无关代码。
- 自动化验证不得启动浏览器。

### 验证方式

在 `C:\code\ai-opc\agv-map-3d` 中执行：

```powershell
npm run lint
npm test -- --run
npm run build
git -C .. diff --check -- agv-map-3d
```

正常路径：

- 固定真实样本从唯一提取路径成功解析。
- 输出保留节点、边和地图元数据中被消费的字段，额外业务元数据不会穿透到输出契约。
- 四类节点和两类边均被正确判别，LINE 与 BEZIER 控制字段保持各自合法形态。

关键异常路径：

- 使用内存构造或测试临时数据覆盖：根值为 `null`/数组、`code` 或 `message` 错误、提取路径缺失、`mapJson` 为字符串、集合字段非数组。
- 覆盖未知节点/边类型、必需字符串为空或类型错误、布尔字段类型错误、数字字符串、NaN/Infinity、LINE 非空控制点、BEZIER 部分空控制点。
- 每种失败都必须得到对应稳定错误码、准确 JSON path、可用实体 ID 和中文消息；不得得到部分结果。

明确预期结果：真实样本通过；所有未受信输入在适配边界内完成判定，失败不会进入领域、几何、worker 输出或 UI 层。

### 完成标准

- 严格未知输入解析边界及其结构化错误契约已经交付。
- 正常与关键异常路径的自动化验证全部通过。
- TASK-001、TASK-002 的安装、构建和样本供应链行为未被破坏。
- 不存在不安全类型断言、重复解析器、默认类型、部分数据或跨层读取原始 JSON。
- 当前代码状态可以创建仅包含本 TASK 结果的独立 Git checkpoint。
- 代码库可以安全进入 TASK-004。

### 回退边界

回退本 TASK 的 Git checkpoint 时，只移除未知输入解析和结构化字段错误能力；TASK-001 的工程基线及 TASK-002 的哈希样本供应链保持完整，不产生兼容解析分支。
