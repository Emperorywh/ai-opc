## 任务描述

### 可验证结果

真实样本能够以一套分层、可释放的 Three/R3F 资源呈现为完整静态 3D 地图：地面、1 个 ribbon、全部节点与两类箭头数量正确、颜色和层高正确，初始实体 draw call 不超过 5。

### 输入

- SPEC §1.1～§1.3、§5.2、§7～§10、§12.1～§12.2、§13、§15.3～§15.4。
- TASK-001～TASK-013 已交付的唯一 SceneModel、typed array、实例计数、颜色与几何契约。
- TASK-014 已交付的 typed array 到 Three 资源的唯一适配与成对释放能力，TASK-015～TASK-016 已交付的字体门禁和应用加载状态机。
- TASK-017 已交付的内容范围、有限地面和标准初始相机结果。

### 输出

- 只读装配 TASK-014 已完成的渲染资源，并呈现地面、合并 ribbon、3,043 个边箭头、1,767 个节点和 464 个节点箭头。
- 符合 SPEC 的背景、色彩空间、DPR 范围、材质、灯光、深度关系、polygon offset、renderOrder 和无阴影静态环境。
- 静态画布从本任务开始使用 demand 帧模式，资源首次提交和有效 resize 显式请求渲染，不以常驻帧循环维持画面。
- 初始总览不挂载文字对象，地图实体资源保持 5 个或更少 draw call。
- 场景装配在卸载时调用 TASK-014 的资源释放边界；展示层只装配完成的资源或只读描述，不拥有第二套创建/释放逻辑，不解析原始数据、不生成业务几何。
- 静态场景的自动数量/资源断言，以及与规格版本绑定的对应人工视觉基线。

### 实现约束

- typed array 到 Three 资源的转换和释放继续由 TASK-014 独占；R3F 场景层不得重复适配、回读原始 JSON、重算矩阵、拼接 ribbon 或决定颜色业务规则。
- 节点、节点箭头和边箭头分别使用单一实例集合；全部 ribbon 合并为一个 Mesh，不得按实体创建 Mesh、Line 或 React 组件。
- worker 输出的颜色按线性 sRGB 消费，renderer 输出为 sRGB 且不使用 tone mapping；不得在展示层二次转换或用材质分支掩盖错误颜色。
- renderer 固定开启抗锯齿、使用高性能偏好并将 DPR 限制在 `[1,1.5]`；地面、节点、ribbon、箭头材质以及半球光和方向光的类型、强度、颜色与位置必须逐项遵守 SPEC，不创建阴影资源。
- 图层高度、depthTest、depthWrite、polygon offset 与提交顺序遵守 SPEC；renderOrder 不得替代真实深度测试。
- v1 不得加入点击、hover、raycaster 业务逻辑、阴影、网格、车辆、编辑能力或任何旧系统依赖。
- 本任务只交付静态实体场景；标签文字挂载和逐帧朝向属于后续 TASK，不得用预挂载隐藏文字提前实现。
- 静止场景必须保持按需渲染；后续相机、键盘、标签和恢复任务只能增加各自事件的显式渲染请求，不得切换为常驻帧循环。
- 新增或修改的代码必须使用多行简体中文注释说明场景装配、资源消费、深度关系与按需渲染不变量；不得主动格式化无关代码。

### 验证方式

1. 执行 `node --version`，预期为 `v24.16.0`；执行 `npm ci`，预期依赖与 lockfile 一致。
2. 执行 `npm run lint`、`npm test -- --run` 和 `npm run build`；这些命令不得启动浏览器，预期全部成功。
3. 正常路径：以真实样本构建静态资源并通过非浏览器集成断言检查实例数、单一 ribbon、typed array 长度、有限矩阵、资源参数和初始文字数；预期分别为 1,767、464、3,043、1、0，实体 draw call 契约为 `<= 5`。
4. 关键异常路径：模拟未 ready、资源集合缺项、重复挂载/卸载和零尺寸画布；预期不显示部分地图、不重复创建资源，卸载只调用既有所有者的幂等释放边界，场景层不修补缺失资源。
5. 人工视觉验收仅由用户执行，Coding Agent 不运行 Playwright 或启动浏览器：执行项目提供的人工视觉基线入口，使用生产构建、Chrome for Testing `148.0.7778.96`、`1920×1080`、DPR 1，审核初始全图、普通节点、0.04m 最短边、两类精确反向边组及 `1080×1920` 初始图；预期无裁切、共面闪烁、车道覆盖或错误箭头。中文标签和边标签相关基线留待 TASK-022 完成后验收。

### 完成标准

- 静态地图实体数量、资源合并、视觉常量和 draw call 契约全部实现并可验证。
- 自动化检查通过，用户已批准本任务对应的静态视觉基线。
- TASK-001～TASK-017 的数据、几何、范围和相机数学行为没有被破坏。
- 资源适配与场景装配职责清晰，无逐实体组件、重复资源、隐藏 fallback 或跨层耦合。
- 可以创建仅包含 TASK-018 静态呈现结果及其测试/基线/必要文档的 Git checkpoint，安全进入 TASK-019。

### 回退边界

回退 TASK-018 checkpoint 只移除 R3F 静态装配、renderer、地面与场景环境呈现；TASK-014 的 Three 资源、TASK-017 及此前的可验证数据、几何、范围和相机计算仍可独立运行。父级 Git 的 checkpoint 与回退范围仅限 `agv-map-3d` 子目录，不得影响其他目录。
