## 任务描述

### 可验证结果

真实样本的 1,767 个节点被转换为一组可供单一实例化节点资源消费的矩阵和线性颜色数据。节点类型、半径、高度、位置、矩阵布局和颜色空间均符合固定视觉契约，且不创建 Three 或 R3F 对象。

### 输入

- SPEC 第 2.2、5.2、5.3、7.1、7.2、8.1、15.2、15.3 和 16 章。
- TASK-005 交付的不可变场景节点及显式坐标变换。
- TASK-004 交付的节点类型、固定回归实体和样本数量身份。
- TASK-001 交付的唯一配置来源、worker 纯数据输出和渲染适配层边界。

### 输出

- 1,767 个节点对应的实例矩阵和实例颜色 typed array，以及与数组长度交叉一致的只读诊断计数。
- 普通节点半径 `0.10m`，`work/park/charge` 半径 `0.15m`；共享节点基准几何高度 `0.05m`、圆柱分段 `24`。
- 节点实例中心 Y 固定为 `0.035`，从而底面为 `0.010`、顶面为 `0.060`；X/Z 按节点半径缩放，Y 不缩放。
- 实例矩阵使用 Three `Matrix4.toArray` 兼容列主序，组合顺序为 `T × R × S`，平移位于索引 12、13、14。
- 四类节点颜色按 SPEC 固定 hex 选择，并通过标准 sRGB transfer function 写为线性 `[0,1]` RGB 浮点值。
- 全部矩阵、颜色和诊断均为有限数且确定；主线程未来只需填入实例资源，不再读取节点 DTO 或重复计算坐标、半径和颜色。
- 本 TASK 只交付节点本体实例数据，不包含节点朝向箭头、标签、Three Mesh 或场景组件。

### 实现约束

- 所有节点必须共享一组实例数据契约，禁止按四种类型拆分重复数据管线或为每个节点创建对象/组件。
- 视觉与性能常量只能来自配置层的唯一常量表，禁止在几何、worker、渲染或组件内定义同义数值。
- 节点 instance color 必须是线性色，禁止把 8-bit sRGB 直接除以 255 后当作线性值。
- 矩阵必须只包含当前节点本体所需的平移和缩放；普通节点的 `angle = null` 保持领域语义，不得替换为零或偷偷烘焙箭头旋转。
- 生成逻辑只消费统一场景节点，不得回读原始 JSON、再次转换坐标或依赖 React/Three/browser API。
- typed array 长度必须由诊断计数交叉校验：矩阵为 `count × 16`，颜色为 `count × 3`。
- 任一非有限矩阵、颜色或非法领域节点都必须整体失败，不得跳过实例或填默认值。
- 新增或修改的代码必须使用多行简体中文注释说明矩阵列主序、T×R×S、颜色转换和实例数据所有权；不得主动格式化无关代码。
- 自动化验证不得启动浏览器；节点最终材质和视觉外观留给后续场景 TASK 人工验收。

### 验证方式

在 `C:\code\ai-opc\agv-map-3d` 中执行：

```powershell
npm run lint
npm test -- --run
npm run build
git -C .. diff --check -- agv-map-3d
```

正常路径：

- 真实样本诊断为 1,767 个节点，矩阵数组长度为 `1767 × 16`，颜色数组长度为 `1767 × 3`。
- 通过完整 ID 查询固定普通节点和中文充电节点，分别验证场景平移、`0.10/0.15m` 半径缩放和对应线性颜色，不依赖数组下标。
- 任一实例矩阵的索引 12、13、14 分别对应场景 x、`0.035`、场景 z；Y 缩放保持基准高度不变。
- 所有数组元素均为有限数，四类颜色均与标准 sRGB 转线性结果一致。

关键异常路径：

- 绕过正常类型边界注入非有限位置、未知节点类型或非法视觉常量时，节点实例构建必须返回结构化错误且不输出部分数组。
- 自动化验证必须能识别行主序、错误组合顺序、Y 被半径缩放、sRGB 直接除以 255 或重复坐标转换等错误实现。
- 普通节点 angle 为 `null` 时，节点本体数据仍成功生成且不会产生任何节点箭头占位数据。

明确预期结果：后续节点渲染和节点箭头任务可分别消费本 TASK 的节点实例结果与既有领域节点，不需要回读原始数据或复制类型/颜色判断。
