## 任务描述

### 可验证结果

主线程可以把一个已自校验的场景模型一次性适配为数量固定、参数正确且所有权明确的 Three 几何与材质资源，并能幂等释放全部已创建资源。适配过程不解析业务数据、不重新生成几何，也不依赖 R3F 组件生命周期。

### 输入

- SPEC 第 3.3、4.3、5.2、7.3～7.4、8～10、13、15.3 节规定的 rendering 边界、资源参数、实例数量、合并策略和释放责任。
- TASK-012 交付的唯一场景模型、自校验规则、typed array、实例计数与内容 bounds。
- TASK-013 交付的主线程成功消息、缓冲区所有权和失败消息契约。
- TASK-001 固定的 Three 精确版本与非浏览器自动化测试能力。

### 输出

- typed array 到 Three BufferGeometry、实例属性和材质资源的唯一适配能力。
- 一个合并 ribbon 资源、一个节点实例资源、一个节点箭头实例资源和一个边箭头实例资源；后续场景层可直接装配，不需要回读领域实体。
- 符合 SPEC 的节点圆柱和两类箭头基准几何、材质、顶点色、实例色、深度、polygon offset 和提交顺序参数。
- 资源集合的显式所有者和幂等释放契约，包含创建中途失败时的已分配资源清理。
- 覆盖资源数量、属性长度、材质参数、几何 bounds、重复创建/释放和非法模型拒绝的自动化测试。

### 实现约束

- rendering 是 typed array 到 Three 资源的唯一边界；不得解析原始 JSON、访问领域边/节点、重算坐标、轨迹、矩阵、颜色或业务 bounds。
- 全部 ribbon 必须进入一个非索引 BufferGeometry；节点、节点箭头和边箭头各自使用一个实例集合，不得按实体或类型继续拆分资源。
- 节点共享 SPEC 规定的圆柱基准几何；节点箭头和边箭头分别共享各自的单位三角形。实例矩阵和线性 sRGB 颜色直接消费场景模型，不得二次变换。
- ribbon 使用顶点色基础材质并关闭 tone mapping，保留 polygon offset；两类箭头使用白色基色乘实例色的基础材质并关闭 tone mapping；节点使用白色基色乘实例色的标准材质。
- 所有实体保留 depth test；节点箭头关闭 depth write。资源参数和 renderOrder 必须来自统一配置，不得在适配器和场景层各定义一份。
- ribbon 资源必须具备与纯数值结果一致的 bounding box 和 bounding sphere；任何属性长度或有限性不一致必须在创建资源前拒绝。
- Geometry、Material、Texture 及后续可扩展资源都由创建方登记和成对释放；释放操作在 StrictMode 风格的重复调用下必须幂等。
- 创建中途失败时必须释放本次已经创建的资源，禁止提交部分资源集合或把清理责任转嫁给场景层。
- 本任务不创建 Canvas、R3F 图层、Ground、相机、灯光、事件监听器或文字对象；静态场景装配属于后续 TASK。
- 新增或修改的代码必须使用多行简体中文注释说明资源所有权、创建原子性、材质参数与幂等释放不变量；不得主动格式化无关代码。

### 验证方式

在 `C:\code\ai-opc\agv-map-3d` 执行：

```powershell
npm run lint
npm test -- --run
npm run build
```

- 正常路径：用真实样本场景模型创建资源，预期得到一个 ribbon、1,767 个节点实例、464 个节点箭头实例和 3,043 个边箭头实例，各属性长度与诊断一致。
- 正常路径：检查几何、材质、深度、polygon offset、renderOrder、实例矩阵和实例色参数，预期完全符合 SPEC 且 ribbon bounds 与 TASK-012 的数值贡献一致。
- 正常路径：连续创建并释放资源集合 20 次，再对同一集合重复释放，预期每个可释放资源恰好执行一次有效清理，登记数量不增长且不抛异常。
- 关键异常路径：传入长度与诊断不一致、包含 NaN/Infinity、缺失缓冲区或已不可用缓冲区的模型，预期在提交前整体拒绝，并清理创建中途的所有资源。
- 预期结果：三个命令退出码均为 0，资源数量、参数、bounds、所有权和异常清理断言全部通过；验证过程不启动浏览器。

### 完成标准

- 场景模型已能通过唯一 rendering 边界转成后续 R3F 可直接装配的固定资源集合。
- 相关 lint、测试和构建全部通过，此前 TASK 的数组、矩阵、颜色、诊断和 bounds 行为未被破坏。
- 资源创建与释放成对、幂等且可测试，部分创建失败不会泄漏或暴露不完整资源。
- 没有逐实体资源、重复业务计算、原始 JSON 回读、场景层清理兜底或 Three 对象跨入 worker/领域层。
- 当前状态可建立仅覆盖 `agv-map-3d` 子目录的独立 Git checkpoint，并安全进入 TASK-015。

### 回退边界

回退本 TASK 的 Git checkpoint 时，只移除 Three 资源适配、参数配置、资源登记与释放能力；TASK-001～TASK-013 的工程、样本、领域、场景模型和 worker 传输能力保持不变。
