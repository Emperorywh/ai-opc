## 任务描述

### 可验证结果

通过结构解析的数据只有同时满足真实样本身份、集合基线、跨实体引用和几何前置语义，才能成为可供坐标归一化消费的地图输入。任何实体级不一致都会整体拒绝，固定样本不能被同 ID 的不同内容冒充。

### 输入

- SPEC 第 2.1 至 2.6、5.2、5.3 第 3、4、5、7、9、10、11、12 项，以及第 14.1、15.1、15.2、16 章。
- TASK-003 交付的受校验原始地图数据和结构化错误契约。
- TASK-002 交付的固定样本身份。

### 输出

- 地图响应元数据、版本元数据、节点和边的 mapId 全链路一致性校验。
- `zones` 与 `nodeEdgeGroups` 必须为空的范围门禁。
- 节点 ID 与边 ID 各自非空唯一、名称非空、引用存在、无自环，边弦长大于 `1e-9m`。
- 普通节点 angle 必须为 `null`；其余三类必须为有限弧度数值，判断不依赖字符串或精确常量相等。
- 边端点与引用节点的距离分别不超过 `0.05m`，同时明确保留边自身端点为显示几何事实来源。
- 真实样本哈希通过后，对第 2 章全部元数据、数量、类型分布、空集合、source bounds、中文字符集合和数据质量基线进行身份回归。
- 第 2.6 节固定实体均按完整 ID 和数据特征交叉验证，不依赖数组下标。
- 实体语义错误统一产生结构化错误并整体拒绝；该结果不表示轨迹级分组已经完成，也不能提前进入渲染 ready。

### 实现约束

- 哈希不符时必须立即终止样本身份测试，不得继续运行视觉或几何基线并产生误导结果。
- 数量、类型、bounds 和字符集合必须从受校验数据推导，禁止硬编码一份伪造的“通过结果”。
- 边的 `snodeId/enodeId` 只表示拓扑；端点偏差通过后仍禁止用节点坐标覆盖 `sx/sy/ex/ey`。
- 角度判断使用数值运算或明确容差，禁止字符串比较和与 π 常量精确相等。
- 本 TASK 负责地图与实体语义完整性，不实现轨迹 canonical 分组、双车道、三角化或 GPU 数据。
- 任何错误都整体拒绝地图，禁止过滤坏实体、修正 ID、补坐标或输出部分合法集合。
- 新增或修改的代码必须使用多行简体中文注释说明身份基线、跨实体不变量和边坐标所有权；不得主动格式化无关代码。
- 自动化验证不得启动浏览器。

### 验证方式

在 `C:\code\ai-opc\agv-map-3d` 中执行：

```powershell
$expected = 'DCE8427D3516E2F8F571AB66CF97D4A645939EE13CC62C7EB1A04846B376B813'
$actual = (Get-FileHash -LiteralPath '.\data\sampleMap.json' -Algorithm SHA256).Hash
if ($actual -ne $expected) { throw "样本身份不符，停止回归验证：$actual" }
npm run lint
npm test -- --run
npm run build
```

正常路径：

- 真实样本通过元数据、1,767 个节点、3,043 条边、类型分布、空集合、bounds、中文字符和第 2.6 节固定实体交叉验证。
- 最大端点偏差样例通过 `0.05m` 门限，且验证结果证明边终点没有被节点坐标覆盖。
- 普通节点 angle 保持 `null`，464 个非普通节点的 angle 均为有限数。

关键异常路径：

- 使用内存变体覆盖非空 zones/nodeEdgeGroups、mapId 不一致、重复或空 ID、空名称、悬空引用、自环、零长度、错误 angle、端点偏差超过 `0.05m`。
- 保留固定实体 ID但改变其坐标、名称、控制点或类型时，样本身份验证必须失败。
- 改变任一基线数量、类型分布、bounds 或中文字符集合时，必须得到可定位的身份或实体错误，且无部分地图输出。

明确预期结果：只有身份和实体语义全部一致的数据才可交给 TASK-005；轨迹级异常仍由其专属结果处理，不在本 TASK 中用重复算法提前推导。

### 完成标准

- 全部正常及关键异常自动化验证通过。
- TASK-001 至 TASK-003 的行为没有被破坏。
- 没有数组下标身份判断、节点端点覆盖、静默修复、重复校验逻辑或跨层耦合。
- 代码库处于实体级可信且尚未伪称渲染 ready 的一致状态，可创建独立 Git checkpoint。
- 代码库可以安全进入 TASK-005。

### 回退边界

回退本 TASK 的 Git checkpoint 时，只移除地图身份和跨实体语义完整性结果；TASK-003 仍能严格解析字段，TASK-002 仍能验证并同步固定样本，不会留下绕过语义校验的备用入口。
