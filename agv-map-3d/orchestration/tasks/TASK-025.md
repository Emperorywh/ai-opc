## 任务描述

### 可验证结果

系统能够从已校验真实样本确定性生成八倍压力样本，并在固定本地环境中以同一架构、同一视觉语义和不变 draw call 上限达到真实样本与压力样本的全部性能门槛；v1 的自动回归、视觉基线、生命周期和性能证据形成最终闭环。

### 输入

- SPEC §2、§3.2、§11.3～§11.4、§13、§15、§16。
- TASK-001～TASK-024 已完成的样本身份、完整 SceneModel 管线、静态场景、相机/键盘、懒标签、错误恢复和只读诊断。
- 已确认的全局边界：只验证当前本地应用，不包含 CSP 响应头、生产部署或远程服务。

### 输出

- 从哈希匹配的真实样本按 4×2 平铺确定性生成压力数据：ID 使用 `tile-{index}:` 前缀，所有引用同步改写，平移固定为 `(col×187.84m, row×95.32m)`。
- 压力数据严格得到 14,136 个节点、24,344 条边、38,480 个标签候选、3,712 个节点箭头和 24,344 个边箭头，并通过与真实样本相同的契约、坐标和几何管线。
- 可重复的本地性能测量入口与记录格式，覆盖环境、五次冷启动中位数、10 秒帧时间、标签查询、heap、draw call、首次可见与 idle 帧行为。
- 真实样本和压力样本的性能报告、完整固定视觉基线批准记录、20 次生命周期记录，以及与 SPEC 版本绑定的最终验收说明。
- 若当前文字渲染不能达到预算，在不改变标签语义、400 上限和视觉验收的前提下完成必要的长期架构调整及对应回归；不得以降级规则伪造通过。

### 实现约束

- 压力样本只能由哈希通过的真实样本确定性派生，不成为第二事实来源，不手工维护，不提交为可编辑业务数据。
- 八个 tile 的所有实体 ID 与拓扑引用必须同步改写，场景平移只发生一次；不得复制粘贴八份逻辑或为压力数据增加专用渲染分支。
- 真实与压力场景都必须保持实体 draw call `<= 5`、标签语义和 400 上限；禁止减少必要实体、降低验收帧率、缩小渲染尺寸、默认隐藏标签或加入低清 fallback。
- 性能优化必须尊重既有 domain→adapters/geometry/labels→application/workers→rendering→scene/camera/ui 依赖方向和资源所有权，不得形成巨型组件、隐式缓存或第二套状态。
- 视觉测试固定使用生产构建和 Chrome for Testing `148.0.7778.96`；性能固定使用 Windows 11、Chrome `150.0.7871.125` 64-bit、1920×1080、DPR 1、16GB、RTX 3060 或同级独显。两个环境的结果不得混算。
- 所有 Chrome、Playwright、WebGL 和性能执行仅由用户人工启动；Coding Agent 只能准备代码、测试入口和记录模板，不得自动启动浏览器。
- 新增或修改的代码必须使用多行简体中文注释说明压力数据确定性、性能度量边界、优化不变量与禁止降级规则；不得主动格式化无关代码。

### 验证方式

1. 执行 `node --version`，预期为 `v24.16.0`；执行 `npm ci`，预期严格按最终 lockfile 安装成功。
2. Coding Agent 仅执行不启动浏览器的 `npm run lint`、`npm test -- --run` 和 `npm run build`；预期全部通过，且完整回归覆盖 TASK-001～TASK-024。
3. 正常路径自动验证：从真实样本生成两次压力数据并比较内容与诊断，预期输出完全确定、五项规模精确、引用无悬空、坐标只平移一次，并通过同一严格数据/几何管线。
4. 关键异常路径自动验证：修改真实样本哈希、制造 tile ID 冲突、漏改引用或改变平铺参数；预期生成在进入性能/视觉测量前确定性失败，不保留部分压力数据或误导性报告。
5. 固定视觉基线仅由用户人工执行：使用指定 Chrome for Testing、视口和 DPR 运行项目提供的视觉入口，审核 SPEC §15.4 的七类截图及阈值；预期全部批准，失败时不得临时放宽阈值。
6. 真实样本性能仅由用户人工执行：在指定性能环境冷启动 5 次并连续采样交互 10 秒；预期首次实体可见 `<=2.0s`、400 标签挂载 `<=200ms`、帧时间 P95 `<=16.7ms`/P99 `<=25ms`、标签查询 P95 `<=8ms`、steady heap `<=150MB`、idle 5 秒不持续提交帧。
7. 压力样本性能仅由用户人工执行：预期实体首次可见 `<=5s`、标签隐藏时帧时间 P95 `<=22.2ms`、steady heap `<=350MB`、实体 draw call `<=5`；同时复核 20 次挂载/卸载后资源计数不单调增长。

### 完成标准

- 压力样本生成确定、规模精确、无第二数据源，自动化异常测试与完整非浏览器回归全部通过。
- 用户已批准最终七类视觉基线、真实样本性能、压力样本性能和 20 次生命周期记录；任一硬门槛未达到时本 TASK 保持未完成，不能创建通过 checkpoint。
- TASK-001～TASK-024 的所有可验证结果未被性能调整破坏，SPEC §16 的完成定义全部满足。
- 没有降低语义或门槛、隐藏内容、fallback、重复压力逻辑、跨层耦合、持续空转、NaN、裁切或共面闪烁。
- 可以在父级 Git 中创建仅覆盖 `agv-map-3d` 子目录的 TASK-025 最终 checkpoint，代码库处于完整、一致、可运行、可验证状态。

### 回退边界

回退 TASK-025 checkpoint 只移除八倍压力样本生成、最终性能测量入口、必要性能调整和最终验收记录；TASK-024 及此前的完整真实样本功能仍保留，但重新处于最终性能与发布完成定义尚未闭环的状态，父级仓库其他目录不受影响。
