## 任务描述

### 可验证结果

场景成功 ready 后能够得到一次结构稳定、只读且可审计的诊断快照，准确汇总各阶段耗时、实体与几何数量、当前标签数、draw call 和 near/far；采集诊断不会改变状态机、渲染决策或资源所有权。

### 输入

- SPEC §5.2、§14.2、§15.3、§16。
- TASK-001～TASK-016 已交付的 SceneModel 诊断计数、worker/application 阶段边界和 ready 状态。
- TASK-017～TASK-023 已交付的 near/far、场景资源、标签挂载数、draw call 契约和安全生命周期。

### 输出

- ready 后生成一次不可变诊断快照，至少包含解析、验证、几何构建、GPU 资源创建耗时，节点/箭头/标签候选/ribbon 顶点数量，当前已挂载标签数、实体 draw call 和 near/far。
- 每个指标从拥有该事实的模块通过显式只读数据汇集，不通过场景遍历、原始 JSON 回读或全局可变对象反推。
- 计时值采用一致单位且为有限非负数；数量与 SceneModel/资源/可见集交叉一致，near/far 满足既有不变量。
- error 或未 ready 时不伪造完整快照；重新加载产生新的独立快照，历史对象不会被后续可变状态篡改。
- 诊断契约、一致性、不可变性、重复加载隔离和失败路径的自动化测试及必要使用说明。

### 实现约束

- 诊断层只能汇总只读度量，不得影响几何、排序、标签上限、相机、invalidate、错误处理或性能分支。
- 指标所有权保持分层：worker 阶段、rendering 资源、labels 可见集、camera 裁剪各自提供自己的数值；禁止诊断模块跨层抓取内部可变对象。
- 不得把 renderer、scene、camera、Geometry、Material、Text 或 worker 实例暴露为全局诊断状态。
- 不得常驻轮询或逐帧收集；SPEC 要求的是 ready 后一次快照，后续能力若需实时监控必须先扩展规格。
- 诊断失败不得改变 ready 场景；但内部不一致必须在测试和开发诊断中明确暴露，禁止静默修正计数。
- 不引入远程遥测、网络上报、部署监控或 CSP/托管配置。
- 新增或修改的代码必须使用多行简体中文注释说明指标所有权、快照时机、不可变性与非干扰不变量；不得主动格式化无关代码。

### 验证方式

1. 执行 `node --version`，预期为 `v24.16.0`；执行 `npm ci`，预期成功。
2. 执行 `npm run lint`、`npm test -- --run` 和 `npm run build`；命令不得启动浏览器，预期全部通过。
3. 正常路径：以真实样本 ready 数据生成快照并交叉验证计数；预期节点 1,767、节点箭头 464、边箭头 3,043、标签候选 4,810、实体 draw call `<= 5`、初始已挂载标签 0，所有耗时有限非负且 `0 < near < far`。
4. 关键异常路径：模拟未 ready、error、中途取消、重复 ready、计数不一致和调用方尝试修改快照；预期未完成状态不产生伪完整数据，重新加载快照彼此隔离，不一致被显式发现，已发布快照不可变且不影响场景。
5. 本任务无需浏览器自动执行；用户可人工查看开发环境暴露的只读结果，预期与自动断言一致，但人工查看不是 checkpoint 的替代验证。

### 完成标准

- 诊断快照字段完整、来源清晰、数值一致、对象不可变且仅在 ready 后产生。
- 正常与异常路径自动化验证通过，诊断采集未改变渲染和状态行为。
- TASK-001～TASK-023 的全部自动化与人工已批准结果保持有效。
- 不存在全局可变 Three 对象、跨层反查、逐帧轮询、远程遥测或诊断驱动业务分支。
- 可以创建仅包含 TASK-024 只读诊断能力及其测试/文档的 Git checkpoint，安全进入 TASK-025。

### 回退边界

回退 TASK-024 checkpoint 只移除 ready 后诊断快照及其汇集契约；TASK-023 及此前的加载、渲染、交互、错误恢复和内部基础计数保持完整。父级 Git 的 checkpoint 与回退范围仅限 `agv-map-3d` 子目录，不得影响其他目录。
