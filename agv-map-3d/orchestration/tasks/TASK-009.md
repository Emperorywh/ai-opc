## 任务描述

### 可验证结果

经过严格校验和坐标归一化的全部作业节点都生成一个位置、朝向、尺寸和对比色可确定验证的节点箭头实例；普通节点不生成箭头。真实样本稳定得到 464 个节点箭头，且结果保持为与 Three、React 和浏览器 API 无关的纯数据。

### 输入

- SPEC 第 2.2、2.5、5.2、7、8.2、15.2 节规定的节点类型、角度、半径、颜色、层高、基准三角形和验收规则。
- TASK-005 交付的不可变领域节点、一次性场景坐标和显式变换结果。
- TASK-008 交付的节点实例顺序、节点类型对应半径、线性 sRGB 颜色及统一视觉常量。
- 此前 TASK 已交付的结构化数据错误和纯数学边界。

### 输出

- 面向全部 `work`、`park`、`charge` 节点的箭头实例矩阵和实例颜色数据，普通 `node` 明确不产生箭头。
- 可供后续统一场景范围计算使用的节点箭头真实几何范围贡献。
- 节点角度到场景方向、实例矩阵和黑白最佳对比色的纯数据契约。
- 覆盖真实样本计数、三个基准角度、矩阵布局、颜色选择和异常输入的自动化测试。

### 实现约束

- 箭头判定只能使用 `type !== "node"`；不得读取未定义字段，也不得把普通节点的 `null` 角度替换为零。
- 所有节点箭头共享 SPEC 规定的局部朝 `+X` 基准三角形；节点角度只能在实例矩阵中应用一次，不得预旋转顶点后再次旋转。
- `0`、`+π/2`、`-π/2` 必须分别指向 `+X`、`-Z`、`+Z`；角度计算使用数值与容差，禁止字符串比较或精确匹配特殊常量。
- 实例位置使用节点场景 X/Z 和固定世界高度 `0.066m`，X/Z 按该节点半径等比缩放。
- 矩阵必须采用列主序 `T × R × S`，平移位于索引 12、13、14；所有输出均为有限数。
- 箭头颜色只能在 `#111111` 和 `#FFFFFF` 中按 WCAG 相对亮度选择与节点基色对比度更高者；同类节点结果必须稳定，并以线性 sRGB 浮点值输出。
- 本任务不得创建 Three 对象、React 状态或渲染组件，不得复制节点颜色、半径、矩阵编码或坐标转换规则。
- 无法形成有限矩阵、有效角度或有效范围时必须整体失败，禁止跳过实体或使用默认朝向。
- 新增或修改的代码必须使用多行简体中文注释说明角度映射、矩阵布局、对比色与异常不变量；不得主动格式化无关代码。

### 验证方式

在 `C:\code\ai-opc\agv-map-3d` 执行：

```powershell
npm run lint
npm test -- --run
npm run build
```

- 正常路径：对真实样本构建节点箭头，断言实例数为 464、矩阵长度为 `464 × 16`、颜色长度为 `464 × 3`，且不存在 NaN 或 Infinity；使用三个基准角度验证最终方向。
- 正常路径：逐类验证黑白候选色的 WCAG 对比度计算，预期每种节点类型总是选择对比度更高且稳定的颜色。
- 关键异常路径：构造作业节点角度为空、非有限或矩阵结果非有限的输入，预期返回结构化几何错误且不产生部分实例数组。
- 关键异常路径：构造普通节点 `angle = null`，预期正常通过且箭头数不增加；不得将其当成朝向零的箭头。
- 预期结果：三个命令退出码均为 0，真实样本计数、方向、颜色、矩阵和异常断言全部通过。

### 完成标准

- 真实样本稳定生成 464 个可实例化节点箭头，位置、角度、尺寸、颜色和范围均可由自动化断言验证。
- 相关 lint、测试和构建全部通过，此前 TASK 的样本、解析、领域转换、轨迹、ribbon 与节点实例行为未被破坏。
- 节点箭头规则保持在纯数据/纯数学边界内，没有 Three、React、原始 JSON 或重复坐标转换耦合。
- 没有默认角度、临时颜色、重复常量、跳过坏实体或其他 fallback 逻辑。
- 当前状态可建立仅覆盖 `agv-map-3d` 子目录的独立 Git checkpoint，并安全进入 TASK-010。

### 回退边界

回退本 TASK 的 Git checkpoint 时，只移除节点朝向箭头的数据生成、范围贡献及其验证；TASK-001～TASK-008 已交付的工程基线、样本供应链、严格解析、领域地图、轨迹、ribbon 和节点实例能力保持不变。
