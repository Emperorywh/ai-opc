## 任务描述

### 可验证结果

本地字体成功预载后，系统只为 TASK-021 当前可见集差量创建最多 400 个始终朝向相机的标签；初始全图文字数为 0，静止场景不持续提交帧，所有必要变化都能显式触发一次渲染。

### 输入

- SPEC §4.2～§4.3、§7.3～§7.4、§11、§13、§15.2～§15.4。
- TASK-015 已交付的本地 WOFF 字体、许可证、字形清单、构建期缺字校验、preload 及字体就绪/失败信号。
- TASK-016 的显式加载状态机、字体 ready 门禁和稳定失败提交边界。
- TASK-018 的静态场景资源与 TASK-021 的确定性目标集合、差量和查询调度。
- 已确认的部署边界：系统仅本地运行，本任务不实现或验证 CSP 响应头及生产部署配置。

### 输出

- 将 TASK-015～TASK-016 已交付的字体就绪门禁接入标签渲染：只有既有门禁成功后才允许创建文字对象，失败信号不产生任何部分标签。
- 仅针对可见集差量创建和销毁文字对象，任意时刻挂载数不超过 400；初始标准 fit 后挂载数为 0。
- 节点与边标签分别遵守既有锚点、局部偏移、nowrap、字号、颜色和 SDF 契约，且使用同一 lane offset 结果。
- 单一帧协调职责在实际渲染帧中批量同步当前标签的 camera quaternion；集合变化走声明式状态，逐帧朝向不触发 React 状态更新。
- demand 帧调度：controls change、文字同步、资源首次提交、resize 和键盘操作显式请求渲染，静止时不常驻 60 FPS；后续 context restore 必须接入同一显式入口。
- 对字体门禁集成、差量挂载、数量上限、朝向协调、invalidate 触发和清理的非浏览器自动化测试，以及标签相关固定视觉基线。

### 实现约束

- 必须消费 TASK-015 的单一本地字体实现；禁止重复打包字体、复制 glyph 校验/preload，也禁止远程字体、系统字体 fallback、Unicode CDN、运行时字体替换或 Canvas 文本压缩。
- 本地字体预载成功是 ready 的必要条件；标签不得在字体成功前挂载，也不得以隐藏形式预创建全部 4,810 个对象。
- 文字参数固定为 `fontSize=0.20`、`sdfGlyphSize=64`、`gpuAccelerateSDF=false`、`whiteSpace=nowrap`、无 `maxWidth`、白色；文字关闭 depth test、depth write 与 tone mapping，不得通过替代参数改变既定视觉语义。
- 标签根变换保持 identity；不得为每个标签各自注册帧回调、controls 监听或 Billboard 控制器。
- 文字对象、事件监听和相关资源由创建方成对释放；不得把 Troika 对象或 Three 可变对象暴露为全局状态。
- demand 调度必须显式、可推导，不能用常驻帧循环掩盖遗漏的 invalidate；不得通过降低标签上限或静默隐藏来满足帧预算。
- 仅本地运行的确认只排除 CSP 响应头与部署验证，不放宽本地字体、无外部 fallback、字形完整性和 worker 所有权要求。
- 新增或修改的代码必须使用多行简体中文注释说明字体门禁接入、差量挂载、批量朝向与 demand 帧不变量；不得主动格式化无关代码。

### 验证方式

1. 执行 `node --version`，预期为 `v24.16.0`；执行 `npm ci`，预期成功。
2. 执行 `npm run lint`、`npm test -- --run` 和 `npm run build`；这些自动命令不得启动浏览器，预期全部通过。
3. 正常路径：在非浏览器测试中模拟 TASK-015 字体就绪信号、0→若干→400→较少的可见集变化和相机帧；预期只处理差量、上限不突破、朝向批量更新且规定事件各触发必要 invalidate。
4. 关键异常路径：传入 TASK-015 的 `FONT_GLYPH_MISSING`/`FONT_ASSET_FAILED` 信号、重复同步回调、快速可见集变化和卸载后迟到回调；预期不进入标签可用状态、不留下部分标签、不重复创建或泄漏资源，也不在本层重新解释字体错误。
5. 人工视觉与帧调度验收仅由用户执行，Coding Agent 不运行 Playwright、Chrome 或性能采样：用户使用生产构建和 Chrome for Testing `148.0.7778.96`、固定视口/DPR 审核中文充电节点与贝塞尔边基线，并复核 TASK-018 的全套基线；预期字体、锚点、曲线 lane、箭头与标签正确，初始标签为 0，放大后标签始终面向相机且不超过 400。用户另检查静止 5 秒不持续提交帧。

### 完成标准

- 既有字体门禁已正确接入，标签差量挂载、统一朝向与 demand 调度完整交付。
- 非浏览器自动化验证全部通过，用户已批准标签相关及最终固定视觉基线和静止帧行为。
- TASK-001～TASK-021 的行为、静态基线、相机与可见集规则没有被破坏。
- 没有远程或系统字体 fallback、全量隐藏 Text、逐标签帧回调、常驻帧循环、资源泄漏或跨层耦合。
- 可以创建仅包含 TASK-022 字体门禁集成、按需标签与帧调度结果的 Git checkpoint，安全进入 TASK-023。

### 回退边界

回退 TASK-022 checkpoint 只移除既有字体门禁到文字渲染的接入、文字对象挂载、朝向同步和 demand 帧协调；TASK-015 的字体资产/preload、TASK-016 的状态门禁和 TASK-021 的可见 ID 集合保持完整。父级 Git 的 checkpoint 与回退范围仅限 `agv-map-3d` 子目录，不得影响其他目录。
