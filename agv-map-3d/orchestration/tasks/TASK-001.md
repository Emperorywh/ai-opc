## 任务描述

### 可验证结果

`agv-map-3d` 子目录成为父级 Git 仓库中可独立安装、检查、测试和构建的 clean-room 地图查看器工程基线。依赖版本、包管理方式、模块边界和验证入口均明确且可重复执行；此时不要求交付任何地图业务能力。

### 输入

- SPEC 第 1.3、3.1、3.2、3.3、13 和 16 章。
- 当前 `agv-map-3d` 中已有的 React、TypeScript、Vite 工程骨架。
- 已确认的全局边界：实际实现只发生在 `C:\code\ai-opc\agv-map-3d`；父级 Git 仓库仅以该子目录作为本任务的 checkpoint 和回退范围。
- 已确认的部署边界：系统只在本地运行，不交付 CSP 响应头或生产部署验证。

### 输出

- 可通过 npm 锁定安装的独立工程，提交唯一有效的 npm lockfile，并支持 CI 使用 `npm ci`。
- SPEC 固定依赖全部使用精确版本；Troika 作为直接依赖，且应用与 drei 解析到同一固定版本。
- 稳定的静态检查、自动化测试和生产构建命令；基础命令在没有地图业务实现时也能成功执行。
- 明确且受约束的分层依赖方向：领域层不依赖 React、R3F、Three 或浏览器 API；原始输入适配、几何、标签、应用编排、worker、渲染资源、场景、相机和 UI 职责相互隔离。
- clean-room 基线中不存在旧 Umi、Konva、G6、Ant Design、旧地图模块、兼容层、deprecated 分支或 fallback 行为。
- 与工程实际命令和本地运行方式一致的必要开发说明。

### 实现约束

- Coding Agent 必须先检查任务执行时的实际工程和依赖树，再自主决定具体配置位置和模块结构，不得照搬当前模板的偶然组织方式。
- Node.js、运行依赖和开发依赖必须遵守 SPEC 第 3.2 节的精确版本，禁止范围版本、`latest`、自动升级和第二套包管理锁定状态。
- 模块依赖只能沿 SPEC 规定的方向流动；禁止通过路径别名、聚合导出或工具模块隐藏反向依赖。
- 工程基线不得引入原始 JSON 全局状态、全局可变单例、隐藏缓存或尚未被当前结果需要的业务占位实现。
- 不得为了通过基线构建而保留演示资源、临时 patch、空 catch、跳过检查或降低编译严格度。
- 新增或修改的代码必须用多行简体中文注释说明模块职责、关键不变量和非直观约束；不得主动格式化无关代码。
- 自动化验证不得启动浏览器；本任务没有视觉验收项。

### 验证方式

在 `C:\code\ai-opc\agv-map-3d` 中执行：

```powershell
node --version
npm ci
npm ls --depth=0
npm ls troika-three-text
npm run lint
npm test -- --run
npm run build
git -C .. diff --check -- agv-map-3d
git -C .. status --short -- agv-map-3d
```

正常路径：

- `node --version` 必须为 SPEC 固定版本。
- `npm ci` 必须仅依据 npm lockfile 完成；依赖树检查不得出现缺失或无效依赖，且完整 Troika 解析树只能包含 SPEC 固定版本。
- lint、测试和构建全部以退出码 0 结束，且不启动浏览器。
- Git 检查只显示 `agv-map-3d` 范围内与本 TASK 相关的变更，`diff --check` 无空白错误。

关键异常路径：

- 使用不符合固定版本的 Node.js 或篡改任一依赖版本后，版本门禁或干净安装必须明确失败。
- 人为构造跨层反向依赖后，静态检查或架构验证必须失败，而不是允许其进入构建产物。
- 引入任一旧系统依赖或第二套 lockfile 后，工程基线验证必须失败。

明确预期结果：工程具备可重复验证的空业务基线；失败均返回非零退出码和可定位原因，不以忽略、降级或浏览器人工观察代替自动验证。

### 完成标准

- 可验证工程基线已经交付，固定依赖和 npm lockfile 一致。
- 上述非浏览器自动化命令全部通过。
- 分层依赖方向和 clean-room 禁令具有自动化或可审计证据。
- 没有业务功能占位、临时逻辑、重复配置、兼容代码或跨层耦合。
- 父级 Git 工作区中，本任务变更可仅以 `agv-map-3d` 子目录创建独立 checkpoint。
- 代码库可以安全进入 TASK-002。

### 回退边界

回退本 TASK 的 Git checkpoint 时，只移除 `agv-map-3d` 内本任务建立的工程、依赖和验证基线；不会修改父级仓库其他子目录。由于本任务是线性序列起点，不存在需要保留的更早业务能力。
