## 任务描述

### 可验证结果

每条领域边都获得保持自身行驶方向的确定性采样中心线、累计弧长和最终车道偏移；精确反向重合的业务边被正确分组并左右错开，拓扑反向但几何不精确反序的边保持独立轨迹。

### 输入

- SPEC 第 2.3、2.4、5.3 第 10、13 项、9.1、9.2、9.3、10.2 中的中心线复用约束，以及第 15.2、16 章。
- TASK-005 交付的统一场景坐标领域节点、领域边和显式变换。
- TASK-004 交付的固定反向边样例和实体级语义不变量。

### 输出

- LINE 固定两个点、标准三次 BEZIER 固定 33 个点/32 段的方向性采样结果。
- 基于 `1e-6m` 容差的无向候选分桶与原始双精度逐项确认，准确区分单边轨迹和精确反向成对轨迹。
- 真实样本固定得到 979 个双车道组、1,958 条成对边和 2,064 条唯一物理轨迹；977 组直线、2 组贝塞尔，868 组 `false/true`、111 组 `false/false`。
- 18 对仅拓扑反向但几何不精确反序的边不进入双车道组。
- 每条边沿自身行驶方向左法线应用 `0` 或 `0.03m` 的车道中心偏移；成对中心线间距 `0.06m`，业务边不去重、不合并。
- 偏移后中心线、累计弧长、局部切线和 lane offset 形成唯一只读几何描述，供 ribbon、边箭头和边标签共同消费。
- 三重轨迹、同向重复、混合边类型、零切线及不支持的 U 形折返以结构化几何错误整体拒绝。

### 实现约束

- `isBackEdge` 只能决定颜色，禁止参与重合判断、方向推断、点序反转、箭头反转或车道分配。
- LINE canonical 序列为 `[S,E]`；BEZIER 为 `[S,C1,C2,E]`，反向序列必须按 SPEC 明确顺序比较。
- 量化 key 只能缩小候选范围，必须使用原始 number 坐标二次确认最大误差不超过 `1e-6m`。
- 贝塞尔的 32 段/33 点在实现、测试和诊断中必须一致，禁止自适应采样或按视觉效果改变段数。
- 曲线内部法线使用相邻归一化切线之和；和长度小于 `1e-9` 时必须报错，禁止任取相邻段或零角度降级。
- 输出是纯数值和不可变描述符，不创建 Three Geometry、Material、Object3D、React 状态或组件。
- ribbon、箭头和标签不得在后续自行重复推导 lane offset；本 TASK 输出是唯一车道事实来源。
- 新增或修改的代码必须使用多行简体中文注释说明 canonical 匹配、双精度确认、左法线和异常不变量；不得主动格式化无关代码。
- 自动化验证不得启动浏览器。

### 验证方式

在 `C:\code\ai-opc\agv-map-3d` 中执行：

```powershell
npm run lint
npm test -- --run
npm run build
git -C .. diff --check -- agv-map-3d
```

正常路径：

- 真实样本断言 979/1,958/2,064 及直线、贝塞尔和两种颜色组合的固定数量。
- 固定 `false/true`、`false/false` 和 0.04m 最短反向边对均正确成组，中心线间距为 `0.06m`。
- 18 个非精确反序拓扑边对均保持各自中心线。
- 每条 BEZIER 恰有 33 点、32 段；所有采样点、法线、弧长和偏移结果均为有限数。

关键异常路径：

- 构造同向重复、三重轨迹、混合 LINE/BEZIER 轨迹组，预期整体返回 `MAP_GEOMETRY_INVALID`。
- 构造相邻切线和小于 `1e-9` 的 U 形折返、零切线或采样后退化中心线，预期明确失败且无部分车道输出。
- 构造落在同一量化桶但原始误差大于 `1e-6m` 的边，预期不得误分组。

明确预期结果：所有业务边仍各自存在且方向不变；只有精确反向几何决定双车道，颜色和拓扑不能改变结论。
