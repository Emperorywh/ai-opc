## 任务描述

### 可验证结果

实体级可信地图被一次性转换为以场景重心为原点、以米为世界单位、使用 `x/z` 平面坐标的不可变领域数据。节点、边端点和贝塞尔控制点共享同一显式变换，后续模块无需也不得再次解释原始地图坐标。

### 输入

- SPEC 第 2.3、5.2、6.1、6.2、15.2 和 16 章。
- TASK-004 交付的地图身份与实体语义完整数据。
- TASK-003 交付的原始字段边界和 TASK-001 的分层依赖约束。

### 输出

- 根据全部节点、边端点和贝塞尔控制点计算的 source bounds，以及由其中心得到的显式场景变换。
- 地图二维点按 `(mapX, mapY) → (mapX, 0, -mapY)` 映射后统一减去场景原点的不可变领域节点和领域边。
- 领域坐标只表达 `x/z`；原始地图 y 不会继续穿透到几何、标签、应用或 R3F 层。
- 地图元数据和绝对世界原点作为只读变换信息保留，便于诊断和可逆定位，但不形成第二套坐标来源。
- 节点、边端点和控制点在 JavaScript number 精度下转换；只有后续 GPU 数据写入阶段才允许转 Float32。
- 三个固定坐标例子、场景居中范围、最大端点偏差保留和“只转换一次”均有数学回归验证。

### 实现约束

- origin 必须从已验证 source bounds 显式计算并传递，禁止把 `81.82`、`12.54` 或任何样本中心散落为魔法数。
- 所有平面坐标必须经过同一纯转换规则；禁止几何、标签或组件各自取负、交换轴、平移或回读原始 JSON。
- 边显示几何继续使用边自身坐标，不能在归一化时吸附到引用节点。
- worldY 是后续渲染高度，不能混入当前二维领域转换，也不能把场景 z 当作原始地图 y。
- 内部计算和测试不得人为舍入；显示层未来可以格式化，但不得反向污染领域数据。
- 输出必须不可变且无 Three、R3F、React、worker 消息或浏览器对象。
- 新增或修改的代码必须使用多行简体中文注释说明轴映射、origin 所有权、精度和单次转换不变量；不得主动格式化无关代码。
- 自动化验证不得启动浏览器。

### 验证方式

在 `C:\code\ai-opc\agv-map-3d` 中执行：

```powershell
npm run lint
npm test -- --run
npm run build
git -C .. diff --check -- agv-map-3d
```

正常路径：

- 固定普通节点 `(0.16,-21.29)` 转为约 `(81.98,33.83)`。
- 固定中文充电节点 `(-139.35,13.60)` 转为约 `(-57.53,-1.06)`。
- 固定直线起点 `(-1.82,-21.30)` 转为约 `(80.00,33.84)`。
- 真实样本 origin 推导为 `(-81.82,0,-12.54)`，转换后 bounds 以原点为中心且一米仍等于一个世界单位。

关键异常路径：

- 最大端点偏差固定样例转换后，边终点与节点位置的原有差异仍保持，证明没有节点坐标覆盖。
- 自动化验证对重复取负、重复平移、把 z 再解释为地图 y 或写入前舍入的实现必须失败。
- 非有限 origin、退化 source bounds 或绕过实体级可信输入的调用必须以明确错误失败，不得输出 NaN/Infinity。

明确预期结果：后续任务只消费统一场景坐标和显式变换；不再需要原始坐标分支，也不存在第二次转换机会。

### 完成标准

- 一次性坐标转换和不可变领域地图已经交付。
- 固定例子、bounds、精度、端点事实来源和单次转换测试全部通过。
- TASK-001 至 TASK-004 的行为未被破坏。
- 不存在样本魔法数、重复轴变换、原始 JSON 回读、Float32 过早量化或跨层耦合。
- 代码库在统一坐标语义下保持一致，可创建独立 Git checkpoint。
- 代码库可以安全进入 TASK-006。

### 回退边界

回退本 TASK 的 Git checkpoint 时，只移除场景坐标变换和不可变领域地图能力；TASK-004 交付的原始地图身份与实体语义校验仍完整可用，不会影响样本供应链或解析边界。
