# AGV 3D 地图展示 — 规格说明

> 本规格基于 `map.json`（中环大地图 V76）真实数据结构与一轮完整产品访谈制定。
> 版本：1.0  ·  日期：2026-07-13

---

## 1. 目标与范围

### 1.1 目标
将 AGV 地图拓扑（节点 + 有向路径）以**高质量 3D 可视化**形式呈现于调度大屏，作为静态展示与态势呈现用途。核心价值是"看得清、看着酷、长时间稳定运行"。

### 1.2 范围（本期做）
- 渲染完整地图拓扑：1768 个节点 + 3045 条有向路径（直线 + 三次贝塞尔）。
- 倾斜沙盘视角，深色科技发光风格，反射地面 + 网格 + 雾效。
- 节点按类型用形状 + 颜色 + 朝向区分；路径用贴地扁带 + 双车道侧向偏移 + 方向流动光效。
- 相机轨道控制（旋转 / 缩放 / 平移）与初始自动框选。
- 首屏加载进度 + 场景淡入。

### 1.3 非目标（本期不做）
- **无任何业务交互**：不做点击详情、类型筛选、搜索定位、连通性高亮。
- **无任何文字标签**：节点 / 路径不渲染 name 等文字（含 HTML 叠层图例 / 比例尺 / 指北针 / 标题水印，本期一律不做，画面纯净优先）。
- **无动态实体**：不接入 AGV 实时位置、路径规划、状态高亮等动态数据。
- 不做地图编辑、导出、量测等功能。

> 上述非目标可在后续迭代启用，架构上保持图层化以便扩展，但本期不实现。

## 3. 数据模型

### 3.1 数据来源
- 文件：`map.json`（约 6.2 MB），内置为静态资源，构建期打包。
- 取数路径：`data.currentMapInfoVersion.mapJson`，包含四个集合：

| 集合 | 本期数量 | 本期是否渲染 |
|---|---|---|
| `nodes` | 1768 | ✅ |
| `edges` | 3045 | ✅ |
| `zones` | 0（结构存在，空） | ⛔ 本期无数据，预留图层位 |
| `nodeEdgeGroups` | 0（结构存在，空） | ⛔ 本期无数据，预留图层位 |

### 3.2 节点结构（关键字段）
```ts
interface MapNode {
  id: string;          // 唯一标识
  name: string;        // 显示名（本期不渲染）
  type: 'node' | 'work' | 'charge' | 'park';
  x: number;           // 2D 横坐标，单位米
  y: number;           // 2D 纵坐标，单位米
  angle: number | null; // 朝向弧度，null 表示无朝向
  // 其余字段（actions / userDefinedProperties 等）本期渲染不使用
}
```
节点类型分布：`node` 1304 · `work` 389 · `charge` 11 · `park` 64。

### 3.3 边结构（关键字段）
```ts
type EdgeType = 'LINE' | 'BEZIER';

interface MapEdge {
  id: string;
  edgeType: EdgeType;
  // LINE：起点(sx,sy) → 终点(ex,ey)
  // BEZIER：三次贝塞尔 P0=(sx,sy) P1=(cx,cy) P2=(dx,dy) P3=(ex,ey)
  sx: number; sy: number;
  ex: number; ey: number;
  cx: number | null; cy: number | null;  // 贝塞尔第一控制点
  dx: number | null; dy: number | null;  // 贝塞尔第二控制点
  snodeId: string; enodeId: string;       // 有向：起点节点 → 终点节点
  sfacing: number | null;                 // 起点朝向弧度
  efacing: number | null;                 // 终点朝向弧度
  isBackEdge: boolean;                    // 是否反向边（与某正向边几何重合）
  cost: number;                           // 边代价（长度相关，本期不渲染）
}
```
- 边类型分布：`LINE` 2936 · `BEZIER` 109。
- `isBackEdge = true` 共 879 条，与对应正向边在几何上重合 → 需双车道偏移（见 §7.2）。
- 本期 `loadType` 全为 0，不作为渲染维度。

### 3.4 场景度量
- 坐标范围：x ∈ [-165.74, 2.10]（宽 167.84 m）· y ∈ [-25.12, 50.20]（高 75.32 m）。
- 宽高比约 **2.23 : 1**（很扁的横向地图）。
- 真实尺度，1 单位 = 1 米。

## 4. 坐标系与场景构建

### 4.1 2D → 3D 映射
- 地图为 2D 平面坐标，映射到 three.js 的 **XZ 平面**：`(x, y) → (x, 0, -y)`。
  - 取 `z = -y` 使地图"上方向"(y+) 对应屏幕"远方"，符合直觉。
  - 高度轴 Y 留给节点几何厚度、扁带离地间隙、阴影。
- 朝向角 `angle` / `sfacing` / `efacing` 为 XY 平面弧度，绕 Y 轴应用：`rotationY = -angle`（与 z=-y 映射保持手性一致）。

### 4.2 居中归一化
- 计算节点 AABB 中心 `(cx, cy)`，整体平移使地图中心落于世界原点 `(0,0,0)`。
- 不做缩放（保留 1 单位 = 1 米的真实尺度），相机通过 framing 适配（见 §8）。

### 4.3 场景层级
```
Scene
├─ 地面层  ReflectiveGround + Grid + Fog
├─ 路径层  EdgesMesh（LINE 合并几何 + BEZIER 合并几何，双车道扁带）
├─ 节点层  NodeInstances（按类型 4 组 InstancedMesh + LOD）
└─ 光照    DirectionalLight(主光/阴影) + AmbientLight + 环境贴图
```

## 5. 视觉设计

### 5.1 配色（冷蓝青主调）
| 元素 | 颜色（建议 HSL / 色名） | Emissive 强度 |
|---|---|---|
| `node` 普通节点 | 蓝 `hsl(210, 90%, 60%)` | 中 |
| `work` 工位 | 青 `hsl(180, 90%, 55%)` | 高 |
| `charge` 充电 | 黄 `hsl(48, 100%, 60%)` | 高 |
| `park` 停靠 | 绿 `hsl(140, 80%, 55%)` | 高 |
| 路径扁带 | 冷蓝 `hsl(200, 85%, 55%)` | 中 |
| 流动光点 | 亮青白 `hsl(185, 100%, 75%)` | 极高 |
| 背景 | 深蓝黑 `#05080F` | — |
| 地面 / 网格 | 半透明深蓝 + 青色网格线 | 低 |

> 数值为初版基线，落地后可在统一调色板常量中微调；`charge`(11) 与 `park`(64) 数量少，用更高饱和 / 更强 Emissive 突出。

### 5.2 材质
- 节点：`MeshStandardMaterial`，`emissive` 设为类型主色，`emissiveIntensity` 按上表，`roughness≈0.4`、`metalness≈0.3`，配合 Bloom 形成辉光。
- 路径扁带：`MeshStandardMaterial`，`emissive` 冷蓝中低强度，`roughness≈0.6`，承载流动光效（见 §7.4）。
- 反射地面：`MeshStandardMaterial` 低粗糙度或基于 `Reflector`（three examples）的镜面反射，透明度约 0.15~0.25，叠加程序化网格纹理。

### 5.3 光照
- 主光：`DirectionalLight`，倾斜入射，开启阴影（`PCFSoftShadowMap`），投射节点到地面的柔和阴影。
- 环境光：低强度 `AmbientLight` 补底。
- 环境贴图：程序化或内置一张冷色 PMREM 环境贴图，赋予材质反射感。

### 5.4 后处理（质量优先）
- **Bloom**：让 Emissive 节点 / 流动光点产生辉光晕，是"科技发光"风格的核心。
- 实现方式：引入 `@react-three/postprocessing`（推荐，与 R3F 9 / React 19 兼容），或退用 `three/examples/jsm/postprocessing/EffectComposer`。
- 参数取向：较大 `luminanceThreshold`（仅高 Emissive 区域发光），适中 `intensity`，避免整屏发糊。
- 抗锯齿：渲染器开启 `antialias: true`（MSAA）；若用后处理管线，补 SMAA。

### 5.5 地面环境
- **反射地面**：承载节点投影与路径倒影，强化空间纵深感。
- **科技网格**：程序化网格线，随距离衰减透明度，提供尺度参照。
- **远景雾效**：`FogExp2` 或线性 `Fog`，深蓝色，远景淡入背景，遮蔽地图边界突兀感。

## 6. 节点渲染

### 6.1 类型 × 形状 × 颜色 × 朝向
| 类型 | 几何形状 | 朝向处理 | 颜色 |
|---|---|---|---|
| `node`（angle 多 null） | 立方体（无方向性） | 不表达朝向 | 蓝 |
| `work`（有 angle） | 三角锥 / 楔形（有指向） | 绕 Y 轴转 `-angle`，尖端指向朝向 | 青 |
| `charge`（有 angle） | 带方向极体（如双锥 / 十字极体） | 绕 Y 轴转 `-angle` | 黄 |
| `park`（有 angle） | 带朝向方块（长方体 + 指向切角） | 绕 Y 轴转 `-angle` | 绿 |

- 朝向表达原则：**朝向即形状指向**，带 `angle` 的节点本体即有方向性几何，无需额外箭头标记；`angle = null` 的 `node` 用对称无方向形状。
- 节点尺寸基准：在 168 m × 75 m 地图上，节点有效尺寸约 **0.4~0.6 m**，确保拉近可见、拉远不致互相重叠糊成一团。各类型尺寸可微调（`charge`/`park` 略大以突出）。
- 节点底部紧贴或微离地面（Y ≈ 几何半高），保证阴影正确投射。

### 6.2 实例化与 LOD
- 每种节点类型一组 `InstancedMesh`（共 4 组），通过实例矩阵放置位置 / 旋转 / 缩放，**单类型单 DrawCall**。
- LOD 分 3 级（基于相机距离 / 屏幕占比切换）：
  - 近：完整类型几何 + 朝向 + Emissive。
  - 中：简化几何（统一低面数），保留颜色区分。
  - 远：退化为小球 / 点，仍按类型着色，保证拓扑完整可见。
- 由于是静态场景、节点无增删，实例矩阵在加载时一次性构建并 `instanceMatrix.needsUpdate`。

## 7. 路径渲染

### 7.1 扁带几何
- 路径渲染为**贴地扁平带**（宽度约 0.3~0.5 m，厚度可忽略或微凸），而非立体管道，以控制几何量。
- 扁带沿路径切线的**法线方向**生成顶点（ribbon），贴地（Y≈0，微离地避免与地面 Z-fighting）。

### 7.2 双车道侧向偏移（核心难点）
- 问题：879 条反向边与正向边几何完全重合，直接渲染会 Z-fighting 闪烁、且丢失有向性。
- 方案：
  - 每条边沿其切线法线方向偏移固定距离 `OFFSET`（建议 ≈ 0.2~0.3 m，约为扁带半宽的量级）。
  - **正向边**偏移到切线一侧（如右侧），**反向边**（`isBackEdge`）偏移到另一侧，形成平行双车道。
  - 直线段：法线恒定，整段等距平移。
  - 贝塞尔段：沿曲线逐点法线偏移，保证双车道全程平行不交叉。
- 效果：每段道路视觉上为两条平行扁带，正反向各自一条，互不重叠。

### 7.3 直线与贝塞尔统一处理
- **LINE**：直接由 `(sx,sy)→(ex,ey)` 两点构造，法线为方向向量旋转 90°。
- **BEZIER**：三次贝塞尔 `B(t) = (1-t)³P0 + 3(1-t)²t·P1 + 3(1-t)t²·P2 + t³·P3`，按弧长自适应采样（曲率大处密、平直处疏），生成折线后再做 §7.1 扁带 + §7.2 偏移。
- 采样精度：质量优先，单条贝塞尔采样点数上限较高（如按弧长每 0.2~0.3 m 一个点），保证曲线平滑。
- 合并优化：所有 LINE 边的扁带顶点合并进单个 `BufferGeometry`，BEZIER 同理合并，**两类各一个 mesh / DrawCall**。

### 7.4 方向流动光效
- 在扁带材质上叠加**沿路径方向流动的光点 / 扫光**：
  - 正向边光点沿 `snode → enode` 方向流动；
  - 反向边光点沿反方向流动，与双车道视觉对应。
- 实现取向（二选一，按实现成本定）：
  - 着色器方案：自定义 `ShaderMaterial` 或 `onBeforeCompile` 注入，以弧长 UV 为相位、`uTime` 驱动周期性高亮沿带流动；正反向通过 attribute 控制相位方向。
  - 纹理平移方案：沿带的滚动纹理 + 透明度调制，简单但精度稍低。
- 流动速度缓慢、稳定（大屏长时间观看不打扰），光点亮度过阈值以触发 Bloom。

## 8. 相机与控制

### 8.1 视角
- 倾斜沙盘：初始相机俯角约 **40°~50°**，距地图适当距离，呈工厂沙盘模型观感。
- 限制 `OrbitControls` 的 `maxPolarAngle`（避免视角压到地面以下）与 `minPolarAngle`（避免完全正俯失去 3D 感），允许用户在一定俯角区间内自由旋转。

### 8.2 初始框选
- 加载完成后，根据地图 AABB 与近截面计算相机位置 / `fov` / `target`，使整张地图（宽 168 m）在 **16:9 横屏**下横向铺满、垂直居中。
- 以缓动动画过渡到该 framing（与场景淡入协同）。

### 8.3 控制行为
- `OrbitControls`：启用旋转 / 缩放 / 平移，设置合理 `min/maxDistance` 与阻尼 `enableDamping`。
- 无任何业务交互（点击 / 悬停均不触发功能）。

### 8.4 画幅适配
- 目标 16:9 / 超宽横屏大屏；监听 `resize` 更新相机 `aspect` 与渲染尺寸。
- 极端比例（如嵌入窄窗）不作为本期优化目标，但保证不破图（letterbox 可接受）。

## 9. 性能策略

| 手段 | 应用 |
|---|---|
| InstancedMesh | 节点按类型 4 组，单类型单 DrawCall |
| 几何合并 | LINE 扁带合并为一 mesh，BEZIER 扁带合并为一 mesh |
| LOD | 节点 3 级；远距退化降低面数 |
| 静态场景 | 节点矩阵、路径几何一次性构建，运行期不更新（仅 `uTime` 驱动光效） |
| 后处理收口 | Bloom 仅作用于高 Emissive，控制 overdraw |
| 帧率目标 | 4K 下稳定 ≥ 30 fps，1080p 下 ≥ 60 fps（调度大屏独显基线） |

## 10. 加载体验

- `map.json`（6.2 MB）`import` 后需解析 + 构建几何，耗时不可忽略。
- 分阶段进度反馈：
  1. 解析 JSON（0~40%）
  2. 构建节点实例矩阵（40~60%）
  3. 构建路径扁带几何（60~90%）
  4. 场景就绪 + 淡入（90~100%）
- 表现：深色背景上的极简进度指示（数字百分比即可，**不用 HTML 复杂叠层**），完成后 Canvas 整体 `opacity` 淡入。

## 11. 边界与健壮性

| 情况 | 处理 |
|---|---|
| 边引用的 `snodeId`/`enodeId` 不存在 | 跳过该边（不渲染），不中断 |
| 孤岛节点（无连接边） | 照常渲染（全量展示原则） |
| BEZIER 控制点为 `null` | 退化为直线处理 |
| BEZIER 控制点与端点重合（退化为点/直线） | 退化为对应形态，避免生成零长度几何 |
| `angle` 为 `null` | 节点不应用旋转（用无方向形状，仅 `node` 类型常态） |
| 坐标异常（NaN / Infinity） | 过滤该节点 / 边并计数，不中断 |
| `zones` / `nodeEdgeGroups` 为空 | 对应图层不渲染，预留模块位 |

> 不做 legacy / fallback 兼容；异常数据按"跳过 + 计数"原则静默处理，开发期通过日志暴露计数。

## 12. 非功能要求

- **运行环境**：1080p~4K 调度大屏，独立 GPU，鼠标键盘，浏览器长时间运行（Chrome / Edge 最新版）。
- **稳定性**：无内存泄漏（静态场景无持续分配；`uTime` 仅更新 uniform），可 7×24 小时运行。
- **打包**：Vite 构建，`map.json` 随包内置；体积大但可接受（本期不拆 CDN / 不懒加载）。
- **可维护性**：高内聚低耦合，渲染 / 数据 / 场景分层；类型字段、配色、尺寸常量集中管理，附简体中文注释。

## 附录 A：访谈决策记录

本规格由 5 轮产品访谈确认，核心决策见 §2 决策摘要。关键张力点（已在规格中平衡）：
- **质量优先 vs 性能**：全量 1768 节点 + Bloom + 4K 负担较重 → 靠 InstancedMesh / 几何合并 / LOD 与 Bloom 收口在大屏独显上达成。
- **双车道偏移 vs 几何量**：偏移避免 Z-fighting 并恢复有向性，代价是贝塞尔需逐点法线偏移 → 以贴地扁带（非管道）+ 合并几何控制成本。
- **无交互 vs 可看性**：用户明确不要任何业务交互与标签 → 仅保留相机轨道控制，靠形状 / 颜色 / 朝向 / 流动光效承载信息。
