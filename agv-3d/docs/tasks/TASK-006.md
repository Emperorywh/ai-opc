# TASK-006 — 建立显式加载状态与会话规则

## 需求

地图加载必须由单一、显式且可验证的状态流驱动，覆盖下载、解析、校验、节点编译、路径编译、场景创建、淡入、就绪和错误。并发、取消和过期结果必须有确定行为，任何错误都不得留下半完成状态。

## 验收标准

- 每次加载只能按规定阶段向前转换，进度始终处于 0～1 且单调不下降，非法转换会被拒绝。
- 同一时间只有一个有效加载会话；启动新会话后，旧会话的进度、成功或失败结果都不能覆盖当前状态。
- 取消或卸载会话后不再接收其结果，也不会进入就绪状态。
- 下载、完整性、解析、结构校验、几何编译和场景资源错误分别稳定映射为 `ASSET_DOWNLOAD_FAILED`、`ASSET_INTEGRITY_FAILED`、`JSON_PARSE_FAILED`、`SCHEMA_VALIDATION_FAILED`、`GEOMETRY_COMPILE_FAILED`、`WEBGL_RESOURCE_FAILED`。
- 错误结果包含错误码、发生阶段、简短中文说明和可供开发定位的详细字段路径；系统不自动重试、降级或切换实现。
- 状态转换、取消和过期结果隔离能够在不启动浏览器的环境中重复验证。
