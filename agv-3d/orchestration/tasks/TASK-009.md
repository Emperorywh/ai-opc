## 任务描述

### 可验证结果

完整 V76 地图能够用固定四个实例批次展示全部 1768 个节点，用户可通过低面数形状、既定颜色和正确朝向区分普通、工作、充电和停车节点，运行期不重建静态实例数据。

### 输入

- SPEC §7.2、§8.1、§8.2、§8.3、§11.1、§13、§16.2 中的节点几何、材质、颜色、批次和方向验收要求。
- TASK-001 至 TASK-008 已交付的节点实例数据包、显式加载体验和完整场景准备入口。
- 任务开始时仓库内已有的节点几何与实例展示；必须审计四类形状尖端、材质生命周期和固定 DrawCall 语义。

### 输出

- 四类低面数节点几何：无方向立方体、`+X` 前向楔形、`+X` 单侧尖端六棱柱、`+X` 前向切角长方体。
- 每类恰好一个实例渲染批次，共四个节点 DrawCall；一次性上传 TASK-005 的实例矩阵，静态运行期间不更新矩阵或重新分组。
- 使用标准物理材质的四类节点视觉：蓝 `hsl(210, 90%, 60%)`、青 `hsl(180, 90%, 55%)`、黄 `hsl(48, 100%, 60%)`、绿 `hsl(140, 80%, 55%)`。
- 节点底部贴合地面上方、保持约 0.5 m 基准宽度和真实比例的完整展示。
- 覆盖几何包围盒、模型前向、四个基准角、材质类型、实例数量、批次数量和资源释放的自动化验证。
- 四类形状、颜色、朝向、遮挡和批次数量的人工视觉验收项。

### 实现约束

- 展示层只消费预编译实例矩阵，不得读取原始 JSON、回查节点领域数据或重新计算坐标与旋转。
- 方向性几何的模型前向只能是 `+X`，世界旋转只能来自预编译矩阵；不得按节点类型添加展示层角度补偿。
- 节点固定使用标准物理材质，颜色、emissive、金属度和粗糙度由视觉职责配置统一提供，不得散落在组件内。
- 四类节点必须始终是四个实例批次；不实现 LOD、Billboard、相机距离重分组或逐节点对象。
- 节点只表达静态拓扑，不增加名称、图例、悬停、点击、筛选或设备状态。
- 本任务创建的几何和材质必须有明确卸载释放路径；释放不得依赖后续 TASK 才能证明。

### 验证方式

- 执行 `pnpm test`，预期节点几何、实例矩阵、方向、主题、资源生命周期及 TASK-001 至 TASK-008 回归测试全部通过。
- 执行 `pnpm lint` 与 `pnpm build`，预期无类型、lint 或生产构建错误。
- 正常路径：加载 V76 完整节点数据；预期四个批次分别包含 1304/389/11/64 个实例，总数 1768，颜色与形状契约一致。
- 方向路径：对工作、充电、停车几何应用 `0、π/2、-π/2、π` 的实例变换；预期尖端世界方向正确，普通立方体不表达方向。
- 关键异常路径：节点包数量与矩阵长度不一致或 GPU 几何创建失败；预期不展示部分节点，并把失败交给既有场景错误边界处理，而不是跳过记录。
- 人工验收：由用户在本地浏览器观察四类形状、颜色、朝向、比例和无额外交互；Coding Agent 不得自动启动浏览器。

### 完成标准

- 四类节点完整、方向正确、批次固定、静态运行且资源可释放。
- `pnpm test`、`pnpm lint`、`pnpm build` 全部通过，TASK-001 至 TASK-008 的行为没有被破坏。
- 不存在逐节点对象、展示层变换算法、散落色值、LOD 占位、重复几何或跨层数据读取。
- 与本任务相关的改动可形成单一独立 Git checkpoint，不混入路径、相机或环境效果。
- 代码库处于一致、可运行、可验证状态，可以安全进入 TASK-010。

### 回退边界

回退本 TASK 的 Git checkpoint 只移除或还原四类节点的 GPU 展示和对应验证；此前的节点编译数据、加载状态、Worker 闭环和错误界面保持完整。
