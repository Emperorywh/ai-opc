## 任务描述

### 可验证结果

全部节点能够按四种类型生成一次性、确定且可转移的实例放置数据，并与路径扁带汇总为完整场景编译包；最终渲染边界精确覆盖节点实体、车道偏移和扁带宽度，成为相机和环境的唯一空间依据。

### 输入

- SPEC §5.2、§6.2、§6.3、§7.1、§7.2、§13.1、§13.2、§16.1、§16.2 中的节点实例、朝向、边界和编译报告契约。
- TASK-001 至 TASK-004 已交付的规范化节点、统一世界空间、车道布局和完整路径几何。
- 任务开始时仓库内已有的节点实例、场景编译、渲染边界和集成测试实现。

### 输出

- 按 `node/work/charge/park` 四类分组的 1768 个节点实例矩阵，数量稳定为 1304/389/11/64，矩阵只表达一次性平移与绕世界 Y 轴旋转。
- 方向性节点统一以模型 `+X` 为前向，并正确应用 `rotationY = angle`；普通节点不表达方向。
- 节点基准宽度 0.5 m、真实米制比例、底部位于地面上方且中心高度等于自身几何半高的放置结果。
- 汇总节点实例、路径几何、最终三维渲染边界和编译统计的完整可转移数据包。
- 稳定编译报告：1768 个节点、3045 条有向车道、998 个双向组、1049 条单向边。
- 覆盖四个基准角、节点尺寸、类型数量、完整边界、统计一致性、转移数据和重复编译确定性的自动化验证。

### 实现约束

- 节点实例编译和渲染边界计算属于纯几何层，不得创建 Three.js 场景对象或读取展示状态。
- 世界朝向必须遵循 `z = -y` 映射：四个基准角 `0、π/2、-π/2、π` 的模型尖端分别指向对应世界方向，不得在展示层二次修正角度。
- 四类节点尺寸由几何职责配置集中提供；实例矩阵不得重复编码静态几何尺寸或运行期缩放策略。
- 最终渲染边界必须在节点和路径编译完成后计算，包含旋转后的节点实体尺寸、扁带宽度和双车道偏移；不得只使用节点坐标或采样中心线。
- 完整数据包只包含可转移数组、边界和统计信息，不包含 React、R3F、Three.js、Worker 或 DOM 实例。
- 编译过程相同输入必须产生字节级稳定结果，不得使用模块级缓存、隐式单例或系统时间。

### 验证方式

- 执行 `pnpm test`，预期节点实例、朝向、渲染边界、场景编译集成和 TASK-001 至 TASK-004 回归测试全部通过。
- 执行 `pnpm lint` 与 `pnpm build`，预期无类型、lint 或构建错误。
- 正常路径：编译 V76 全量模型；预期得到四类正确数量的实例、完整路径、包含所有实体的有限渲染边界和 1768/3045/998/1049 报告。
- 方向路径：分别输入 `0、π/2、-π/2、π` 的方向性节点；预期实例变换后的模型 `+X` 尖端与地图角度映射一致，普通节点不随角度分支变化。
- 关键异常路径：输入无法形成有限边界或子编译产生非法几何；预期整次场景编译失败，不返回部分数据包。
- 一致性路径：逐一确认所有节点实体和路径顶点落入最终边界，并重复编译比较全部数组和报告。验证不启动浏览器。

### 完成标准

- 完整场景编译包、节点实例、最终渲染边界和统计报告均符合 SPEC 且可独立验证。
- `pnpm test`、`pnpm lint`、`pnpm build` 全部通过，TASK-001 至 TASK-004 的行为没有被破坏。
- 节点、路径、边界和统计同源于一次编译，不存在展示层补算、重复模型、隐式状态或跨层耦合。
- 与本任务相关的改动可形成单一独立 Git checkpoint，不混入加载状态或可视化图层修改。
- 代码库处于一致、可运行、可验证状态，可以安全进入 TASK-006。
