## 任务描述

### 可验证结果

所有车道中心线能够被确定地编译为一份可转移、可直接创建单一 GPU 路径几何的扁带数据；直线、曲线和尖锐折角均有效，每条有向边仍保留独立可审计的弧长、流向和顶点区间。

### 输入

- SPEC §5.2、§6.1、§7.1、§7.5、§7.6、§11.1、§13.1、§16.1 中的渲染包、扁带、流向和性能预算契约。
- TASK-001 至 TASK-003 已交付的严格模型、米制世界空间和稳定车道布局。
- 任务开始时仓库内已有的扁带编译和集成测试；已有几何合法性检查必须按全部属性与索引契约重新审计。

### 输出

- 扁带宽 0.22 m、离地高度 0.015 m 的合并路径几何数据，包含位置、地面法线、按米累计的路径弧长、流向、32 位索引和每条有向边的顶点区间。
- 对普通折角使用 miter join、对超过半带宽 2 倍上限的折角使用确定性 bevel join 的稳定展开结果。
- 3045 条有向边与顶点区间之间稳定、可审计的一一对应，路径报告与车道分组统计一致。
- 全部大数组均为可转移的 TypedArray/ArrayBuffer 纯数据，不包含 Three.js 实例或浏览器对象。
- 覆盖直线、曲线、尖角、容差、有限性、索引范围、弧长方向、流向、全量计数和字节级确定性的自动化验证。

### 实现约束

- 中心线侧移和扁带展开必须先在地图 XY 平面完成，再统一映射到世界 XZ 平面；不得在展示组件中重算偏移或接缝。
- 每个采样点的切线与法线必须由相邻有效点稳定推导；超过 miter 上限时按唯一规则切换 bevel，不得生成尖刺、裂缝或依赖浮点偶然顺序的几何。
- 双向组共享规范弧长坐标并通过 `+1/-1` 表达相反流向；单向边沿自身 source→target 累计弧长且流向为 `+1`。
- 每条边的标识与顶点范围对应关系必须在编译结果或同源报告中可推导，不能在合并时丢失或依赖隐含遍历知识。
- 输出前必须验证位置、法线、弧长属性、流向属性和索引全部有限，属性长度一致，索引与每条边的顶点区间均不越界。
- 几何编译保持纯函数和字节级稳定，不读取场景、相机、时间或全局可变缓存。

### 验证方式

- 执行 `pnpm test`，预期扁带单元测试、V76 全量编译测试及 TASK-001 至 TASK-003 回归测试全部通过。
- 执行 `pnpm lint` 与 `pnpm build`，预期无类型、lint 或生产构建错误。
- 正常路径：编译直线、平滑曲线、常规折角和 V76 全量车道；预期得到一个合并数据包、3045 个有向边区间、正确弧长与流向，全部属性有限且索引有效。
- 关键异常路径：构造零长度段、非有限中间结果、越界索引或超过 miter 上限的尖角；预期非法几何被拒绝并产生可定位编译错误，尖角合法输入稳定转为 bevel。
- 确定性路径：相同输入与配置重复编译并逐字节比较所有 TypedArray；预期完全一致。验证不创建浏览器场景。

### 完成标准

- 单一合并路径数据完整表达全部车道和逐边区间，所有合法性与确定性测试通过。
- `pnpm test`、`pnpm lint`、`pnpm build` 全部通过，TASK-001 至 TASK-003 的行为没有被破坏。
- 不存在逐边材质预留、展示层几何算法、重复坐标转换、临时修补或无法释放的场景对象。
- 与本任务相关的改动可形成单一独立 Git checkpoint，不混入节点或 R3F 展示修改。
- 代码库处于一致、可运行、可验证状态，可以安全进入 TASK-005。

### 回退边界

回退本 TASK 的 Git checkpoint 只移除或还原路径扁带编译、可转移路径数据和对应验证；TASK-001 至 TASK-003 的数据、采样和车道分组结果保持完整。
