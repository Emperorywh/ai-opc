## 任务描述

### 可验证结果

所有通过校验的 LINE 与三次 BEZIER 路径都能转换为方向稳定、误差受控且字节级确定的采样结果，并与全部节点共同建立唯一的地图中心和米制世界坐标基准，供后续车道、节点、边界和场景共享。

### 输入

- SPEC §6、§7.1、§7.3、§12、§13.1 中的坐标映射、采样误差、确定性和集中配置要求。
- TASK-001 已交付的严格领域模型和边自身权威几何。
- 任务开始时仓库内已有的采样、坐标转换和相关测试实现；Coding Agent 必须先检查其实际误差语义和边界行为。

### 输出

- LINE 与三次 BEZIER 的统一有序采样结果，始终从源节点方向指向目标节点方向并完整保留首尾端点。
- 同时受最大弦长 0.25 m、最大平坦度误差 0.01 m、最大递归深度 12 约束的确定性 BEZIER 细分能力。
- 由全部节点位置和完整路径采样点联合 AABB 计算的地图中心。
- `map(x, y) → world(x - centerX, height, -(y - centerY))` 的统一坐标转换，保持 1 world unit = 1 m，不做整体缩放。
- 覆盖端点、顺序、误差、最大段长、零长度段、联合中心、坐标符号和重复执行稳定性的自动化验证。

### 实现约束

- 采样与坐标转换必须是纯计算能力，不读取相机、场景、React 状态、系统时间或随机源，也不得创建 Three.js 对象。
- LINE 只产生起点和终点；BEZIER 使用三次公式和确定性递归细分，LINE/BEZIER 的差异在采样边界内消解。
- 三项采样约束必须同时成立；达到递归深度上限仍无法满足误差或弦长时，不得返回假合格结果或退化为 LINE，应终止该次几何编译并提供可定位错误。
- 任意相邻采样点距离为 0 都属于几何编译错误，不得删除重复点后继续，也不得静默跳过整条边。
- 原始数据中的 `cost` 不属于规范化几何契约，不得参与 LINE 或 BEZIER 的采样密度和误差决策。
- 地图中心必须同时纳入节点与所有路径采样点；不得只依据节点、端点或展示层边界计算。
- 几何与坐标参数按职责集中并携带清晰单位，不得在算法或展示组件中散落魔法数。

### 验证方式

- 执行 `pnpm test`，预期采样、坐标、配置、V76 集成和 TASK-001 的全部回归测试通过。
- 执行 `pnpm lint` 与 `pnpm build`，预期无类型、lint 或构建错误。
- 正常路径：分别对 LINE、常规三次 BEZIER 和 V76 全量边进行采样；预期端点完整、方向为 source→target、非末级段满足弦长与平坦度约束，联合中心有限且坐标映射符合 XZ 地面约定。
- 关键异常路径：输入产生相邻重合点的路径，以及在深度上限内无法满足约束的病理曲线；预期几何编译失败，错误可定位到相关边或采样段，不产生部分采样结果。
- 确定性路径：对同一模型和同一配置重复执行至少两次，逐项比较采样点、中心与世界坐标；预期结果完全一致。验证不启动浏览器。

### 完成标准

- 路径采样与世界空间基准的可验证结果全部实现，自动化测试覆盖正常、边界和失败路径。
- `pnpm test`、`pnpm lint`、`pnpm build` 全部通过，TASK-001 的数据边界行为没有被破坏。
- 纯计算边界保持高内聚，不存在展示状态依赖、重复坐标转换、临时容错或无法解释的阈值。
- 与本任务相关的改动可形成单一独立 Git checkpoint，不混入车道分组或后续展示修改。
- 代码库处于一致、可运行、可验证状态，可以安全进入 TASK-003。

### 回退边界

回退本 TASK 的 Git checkpoint 只移除或还原确定性采样、地图中心和世界坐标结果；TASK-001 的资产契约、严格校验和规范化领域模型必须保持完整可用。
