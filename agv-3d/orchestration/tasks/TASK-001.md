## 任务描述

### 可验证结果

系统具备唯一、严格且可审计的 V76 地图输入边界：构建资产的字节数与 SHA-256 可核验，原始数据能够一次性完成完整校验，合法数据被规范化为与浏览器和渲染技术无关的领域模型，非法数据不会产生任何可供后续编译的结果。

### 输入

- SPEC §1、§2.3、§3、§4、§5.1、§13.1、§14.1、§16.1 中的数据资产、原始 DTO、严格校验、规范化、技术基线和非兼容约束。
- 项目根目录当前的 V76 地图资产，以及任务开始时仓库内已有的数据契约、校验、规范化和测试实现；已有实现只作为待审计基线。
- 当前包管理、TypeScript、Vitest、lint 与生产构建能力。

### 输出

- 可核验的自托管地图资产契约：6,516,343 bytes，SHA-256 为 `DE2B1158FEFDC274673FB7F1813D8F193961359926B238B0CC334350A87FC567`，取数路径固定为 `data.currentMapInfoVersion.mapJson`。
- 对原始节点、边、空区域集合和空节点边组执行一次性问题收集的严格校验能力；失败结果包含稳定问题类别和明确字段路径，成功与失败互斥。
- 只保留渲染契约字段的规范化领域模型；契约外字段被显式丢弃，边自身几何坐标保持为权威数据。
- V76 数据契约自动化验证，覆盖 1768 个节点、3045 条边、四类节点分布 1304/389/11/64、LINE/BEZIER 分布 2936/109、`isBackEdge = true` 为 879、空扩展集合、引用完整性和审计指纹。
- 数据基线审计证明缺失节点引用、非法坐标和重复 ID 均为 0；483 条边端点与节点坐标不完全一致且最大差异为 0.03 m，该事实不会触发吸附或校验错误。
- 与本结果相关的必要契约说明，明确资产变更时必须同步更新指纹、审计统计与测试。

### 实现约束

- 领域模型不得依赖 React、R3F、Three.js、Worker API、DOM 或其他浏览器对象；数据边界之外的层不得重新解释原始 JSON。
- `id`、封闭类型、参与渲染的有限数值、节点角度规则、节点引用、唯一有向节点对、LINE 非零长度、BEZIER 完整有限控制点以及空 `zones`/`nodeEdgeGroups` 都是硬约束。
- 校验必须收集本次输入中所有可独立发现的问题，不得在首个坏记录处停止，也不得跳过坏记录继续产出不完整地图。
- 边端点与引用节点坐标不一致不属于错误；不得把边端点吸附到节点坐标。
- `isBackEdge` 只属于原始 DTO 审计信息；其存在性和字段形状遵守原始契约，但其值不得改变校验结论、规范化结果或后续布局决策。
- 不引入旧格式兼容、字段猜测、默认值填充、静默降级、自动修复或未来图层占位模型。

### 验证方式

- 执行 `pnpm test`，预期全部数据契约、校验、规范化和既有回归测试通过。
- 执行 `pnpm lint` 与 `pnpm build`，预期无类型、依赖方向、lint 或生产构建错误。
- 执行 `Get-Item .\map.json | Select-Object Length` 和 `Get-FileHash .\map.json -Algorithm SHA256`，预期分别得到 6,516,343 和指定 SHA-256。
- 正常路径：输入当前 V76 资产，预期无校验问题，审计统计与 SPEC 完全一致，并产出只含契约字段的完整领域模型。
- 关键异常路径：分别注入空/重复 ID、重复有向节点对、非法类型、NaN/Infinity、错误角度、缺失引用、零长度 LINE、无效 BEZIER 控制点、非空扩展集合和缺失必需字段；预期一次返回全部可发现问题，字段路径准确，且不返回领域模型。
- 边界路径：改变边端点与节点坐标差异或翻转 `isBackEdge` 值；预期前者保留边坐标且不报错，后者不改变规范化结果。验证只使用命令行测试，不启动浏览器。
