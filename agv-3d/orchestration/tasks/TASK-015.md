## 任务描述

### 可验证结果

完整渲染数据包能够按确定步骤创建为 GPU 场景资源，并将总进度真实推进 90%～98%；创建过程要么全部成功并等待首帧，要么释放本次所有已创建资源并进入 `WEBGL_RESOURCE_FAILED`，正常卸载和 StrictMode 重复挂载也会回到加载前资源基线。

### 输入

- SPEC §5.3、§5.4、§8、§10.1、§10.2、§11.3、§13.2、§16.3 中的场景准备进度、GPU 错误、资源释放和重复挂载要求。
- TASK-001 至 TASK-014 已交付的完整渲染包、应用状态边界、节点/路径/环境/反射/后处理资源及各自释放职责。
- 任务开始时仓库内已有的 R3F 挂载与局部 dispose 逻辑；必须审计“部分创建失败”和“应用层统一状态”的闭环。

### 输出

- 场景资源创建的确定性步骤模型，每个已完成步骤对应 90%～98% 区间内的真实单调进度，不用计时器伪造。
- 对节点几何/材质、路径几何/材质、程序化环境纹理、PMREM、反射 RenderTarget、后处理内部目标及其他显式 GPU 资源的统一所有权与释放边界。
- 任一资源创建或首帧前准备失败时，向应用层提交结构化失败事实并稳定进入 `WEBGL_RESOURCE_FAILED`，不展示半成品场景。
- 创建失败时释放本次已成功创建的全部资源，正常卸载时释放完整资源集并移除相机、可见性、resize 等监听。
- StrictMode 重复挂载、连续多次加载/卸载和失败注入后 Worker 数量、监听数量与 GPU 资源计数回到同一基线的验证能力。
- 覆盖每个创建步骤、失败注入、幂等清理、重复挂载和资源计数回归的自动化验证。

### 实现约束

- 资源所有权必须显式且单一；每种资源只能由一个生命周期边界负责释放，既不能泄漏也不能重复 dispose。
- 场景创建进度只反映已实际成功完成的确定步骤；不得根据时间、帧数或估算值推进 90%～98%。
- 展示层只上报创建进度、成功或失败事实，状态采纳和错误转换仍由 TASK-006 的应用层用例负责。
- 任一失败必须撤销本次已创建资源，不得依赖 React 自动清理碰运气，也不得保留半场景等待后续 TASK 修复。
- Worker 生命周期与 GPU 生命周期边界清晰：场景创建失败不能复活已结束 Worker，卸载必须同时使后台执行单元和 GPU 资源归零。
- 不使用全局可变资源注册表、隐式缓存、模块级单例、重复清理分支或运行时 fallback。

### 验证方式

- 执行 `pnpm test`，预期场景创建步骤、应用状态、失败映射、资源释放、重复挂载及 TASK-001 至 TASK-014 回归测试全部通过。
- 执行 `pnpm lint` 与 `pnpm build`，预期无类型、依赖方向、lint 或生产构建错误。
- 正常路径：按确定步骤创建完整场景；预期进度从 90% 单调到 98%，所有资源只创建一次，状态停留在等待首帧的准备阶段。
- 关键异常路径：在每类 GPU 资源创建完成前后分别注入失败；预期进入 `WEBGL_RESOURCE_FAILED`，错误阶段准确，本次已创建资源全部释放，覆盖层持续遮挡场景。
- 生命周期路径：连续执行多次成功挂载/卸载、失败后卸载和 StrictMode 重复挂载；预期 Worker、监听、geometry、material、texture、PMREM、reflection target 和 postprocessing target 计数均回到同一加载前基线。
- 人工辅助验收：由用户在浏览器开发工具中观察重复挂载/卸载资源计数；Coding Agent 不得自动启动浏览器。

### 完成标准

- 场景创建进度真实、失败原子回滚、正常卸载和重复挂载资源基线均得到验证。
- `pnpm test`、`pnpm lint`、`pnpm build` 全部通过，TASK-001 至 TASK-014 的行为没有被破坏。
- 不存在双重所有权、部分场景、伪造创建进度、依赖自动回收、全局资源状态或跨层错误处理。
- 与本任务相关的改动可形成单一独立 Git checkpoint，不混入首帧淡入或目标机性能记录。
- 代码库处于一致、可运行、可验证状态，可以安全进入 TASK-016。

### 回退边界

回退本 TASK 的 Git checkpoint 只移除或还原统一场景创建事务、90%～98% 进度、失败回滚和资源基线验证；TASK-001 至 TASK-014 各图层原有功能与局部释放能力保持可运行。
