## 任务描述

### 可验证结果

场景资源完成创建后先以不可见状态实际成功渲染首帧，随后在 500 ms 内把真实进度从 98% 推进到 100% 并平滑露出完整场景；系统减少动态效果时可跳过过渡时长，但仍严格保持“首帧成功后才显示”的顺序。

### 输入

- SPEC §5.3、§10.1、§10.2、§13.3、§16.3 中的 preparing/ready 状态、首帧、淡入、错误和减少动态效果要求。
- TASK-001 至 TASK-015 已交付的完整场景、真实加载界面、应用生命周期边界和原子化资源创建。
- 任务开始时仓库内已有的 Canvas 创建回调、CSS opacity 或定时器逻辑；必须区分“渲染器已创建”与“首帧已成功提交”。

### 输出

- 在资源创建完成后以 `opacity: 0` 挂载完整场景，并能确认实际首帧成功渲染的生命周期事实。
- 首帧成功后才进入 fading，固定 500 ms 淡入，总进度按实际动画进展从 98% 单调到 100%，完成后进入 ready 并移除加载覆盖层。
- 尊重 `prefers-reduced-motion`：可以立即完成视觉过渡，但首帧确认、状态顺序和完整场景原子性不变。
- 首帧失败、淡入开始前失败或卸载时取消动画/定时工作并进入既有统一错误或取消路径的能力。
- 覆盖首帧门槛、500 ms 进度、减少动态效果、错误前不泄露场景、卸载清理和终态状态的自动化验证。
- 无空白、闪烁、半成品暴露和过渡异常的人工界面验收项。

### 实现约束

- “渲染上下文或 Canvas 已创建”不等同于首帧成功；只有确认完整场景实际完成首帧渲染后才能开始淡入。
- 淡入固定为 500 ms，进度必须与真实淡入过程同源且单调，不得在开始时直接跳到 100% 或使用无关计时器伪造场景创建进度。
- 场景在首帧前完全不可见，加载覆盖层保持；首帧或淡入前失败不得短暂暴露节点、路径、环境或上一次场景。
- 展示层只报告首帧与动画进展事实，应用层负责 `fading → ready/error` 状态采纳。
- 动画帧、定时器、媒体查询监听和其他副作用在卸载或会话失效时必须清理，旧会话完成回调不得影响新状态。
- 500 ms、减少动态效果和可见性规则集中表达，不在样式与逻辑中形成不可推导的重复常量。

### 验证方式

- 执行 `pnpm test`，预期首帧门槛、淡入进度、状态转换、减少动态效果、清理及 TASK-001 至 TASK-015 回归测试全部通过。
- 执行 `pnpm lint` 与 `pnpm build`，预期无类型、lint 或生产构建错误，控制台无未处理 Promise rejection。
- 正常路径：完成资源创建但尚未渲染首帧；预期场景透明、进度不超过 98%。提交首帧成功后，预期 500 ms 内进度单调到 100%，随后 ready 且覆盖层移除。
- 关键异常路径：在首帧前、首帧回调中、淡入中途分别失败或卸载；预期不显示半成品，所有动画副作用清理，错误/取消状态不被旧完成回调覆盖。
- 减少动态效果路径：模拟系统设置开启；预期首帧成功后可立即显示并完成，但不能跳过首帧门槛。
- 人工验收：由用户在本地浏览器观察加载到完整场景的过渡、减少动态效果、错误界面、无闪烁和无空白；Coding Agent 不得自动启动浏览器。

### 完成标准

- 首帧门槛、真实淡入进度、ready 时序、减少动态效果和异常清理全部可验证。
- `pnpm test`、`pnpm lint`、`pnpm build` 全部通过，TASK-001 至 TASK-015 的行为没有被破坏。
- 不存在把创建回调误作首帧、重复时长常量、伪进度、旧会话定时器、半成品泄露或展示层越权状态转换。
- 与本任务相关的改动可形成单一独立 Git checkpoint，不混入目标机性能优化或验收记录。
- 代码库处于一致、可运行、可验证状态，可以安全进入 TASK-017。

### 回退边界

回退本 TASK 的 Git checkpoint 只移除或还原首帧门槛、500 ms 淡入、98%～100% 进度和对应验证；TASK-001 至 TASK-015 的完整场景、资源原子性和加载错误能力保持可运行。
