## 任务描述

### 可验证结果

沙盘地面使用唯一的真实平面反射方案呈现节点和路径倒影，反射目标固定为 1024×1024 并带一次粗糙模糊；反射平面范围由最终渲染边界推导，不随主画布 DPR 或分辨率膨胀。

### 输入

- SPEC §3、§6.3、§8.1、§8.4、§11.1、§13.3、§16.2 中的平面反射、范围、性能预算和视觉验收要求。
- TASK-001 至 TASK-012 已交付的完整拓扑、统一环境边距、深色环境和受控相机。
- 已确认的全局依赖决策：使用 `@react-three/drei` 10.7.7 提供的平面反射能力，不设计自研或替代反射管线。

### 输出

- 深色、不透明、唯一的真实平面反射地面，能够反射节点与路径且不冒充普通低粗糙度材质。
- 固定 1024×1024 的反射 RenderTarget 和一次粗糙模糊，主画布分辨率、DPR 或 resize 不改变该预算。
- 由 `renderBounds + 环境边距` 推导的反射平面尺寸与位置，与 TASK-012 的网格和雾共享空间基准。
- 反射资源在创建失败、正常卸载和重复挂载时均可确定释放，不遗留额外 RenderTarget。
- 覆盖反射预算、空间推导、resize 不变性、唯一地面和释放行为的自动化验证。
- 反射质量、模糊程度、拓扑清晰度和无重复地面的人工视觉验收项。

### 实现约束

- 平面反射必须使用 SPEC 已确认的单一方案；不得用普通材质高光、屏幕截图、环境贴图或第二套反射作为 fallback。
- 场景中只能存在一个承担地面反射职责的平面；网格保持独立图层，不得复制地面或与反射材质交叉修改内部对象。
- 反射 RenderTarget 固定 1024×1024，不得绑定 Canvas DPR、CSS 尺寸或 4K 主渲染尺寸。
- 反射平面范围必须从最终渲染边界和统一环境边距推导，不得写死坐标或依赖相机 framing。
- 反射材质、纹理和 RenderTarget 必须有确定释放路径；本任务自身即可验证卸载，不依赖后续资源任务补救。
- 不以动态关闭反射、降低地图数量或运行时降级作为性能策略。

### 验证方式

- 执行 `pnpm test`，预期反射配置、范围推导、resize 不变性、资源释放及 TASK-001 至 TASK-012 回归测试全部通过。
- 执行 `pnpm lint` 与 `pnpm build`，预期依赖被锁定且无类型、lint 或生产构建错误。
- 正常路径：创建 V76 沙盘并多次改变 Canvas 尺寸和 DPR；预期反射平面持续覆盖环境，RenderTarget 始终为 1024×1024，节点与路径可形成粗糙倒影。
- 关键异常路径：反射资源创建中断、组件重复挂载/卸载；预期已创建的反射资源全部释放，不留下第二个地面或持续增长的 RenderTarget 数量。
- 静态检查：确认不存在普通材质伪反射、自研替代方案、主分辨率绑定和远程纹理请求。
- 人工验收：由用户在本地浏览器观察倒影真实性、一次粗糙模糊、网格独立性、拓扑清晰度和无重复地面；Coding Agent 不得自动启动浏览器。

### 完成标准

- 真实平面反射、固定预算、空间推导和释放路径全部实现并可验证。
- `pnpm test`、`pnpm lint`、`pnpm build` 全部通过，TASK-001 至 TASK-012 的行为没有被破坏。
- 不存在假反射、替代管线、分辨率膨胀、重复地面、运行时降级或未释放 RenderTarget。
- 与本任务相关的改动可形成单一独立 Git checkpoint，不混入 Bloom/SMAA 或全局资源事务修改。
- 代码库处于一致、可运行、可验证状态，可以安全进入 TASK-014。

### 回退边界

回退本 TASK 的 Git checkpoint 只移除或还原真实反射地面、固定 RenderTarget、模糊和对应验证；TASK-001 至 TASK-012 的深色环境、网格、雾、光照、拓扑和相机保持完整。
