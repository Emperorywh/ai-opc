## 任务描述

### 可验证结果

完整 V76 拓扑能够用一个合并路径 Mesh 和一个路径材质展示全部 3045 条有向边，并以长期稳定、方向正确的流动高亮清楚表达每条边从 source 到 target 的方向。

### 输入

- SPEC §7.5、§7.6、§8.1、§8.2、§8.3、§11、§13、§16.1、§16.2 中的路径属性、着色器、流向、批次和长期运行要求。
- TASK-001 至 TASK-009 已交付的合并路径数据、应用生命周期、加载界面和节点场景。
- 任务开始时仓库内已有的路径几何挂接、着色器和相位逻辑；必须审计流向公式、页面可见性和逐帧分配。

### 输出

- 将可转移路径属性零拷贝挂接为单一静态几何，并由一个自定义路径材质完成一个路径 DrawCall 的展示能力。
- 基础路径色 `hsl(200, 85%, 55%)` 与流动高亮色 `hsl(185, 100%, 75%)`，所有颜色和流光参数集中定义。
- 基于每顶点弧长与流向属性的 source→target 周期高亮；双向组相反流动，单向边沿自身方向流动，`isBackEdge` 不参与任何翻转。
- 重复距离 2.0 m、速度 0.4 m/s、周期 5 s 的有界相位；页面不可见时暂停业务更新，恢复后不累计超大 delta。
- 每帧只更新一个流光 uniform，不重建几何、材质、数组或临时向量。
- 覆盖属性挂接、单一材质、流向公式、有界相位、可见性恢复、24 小时数学模拟和资源释放的自动化验证。
- 单双向间距、流向、长时间连续性和无 Z-fighting 的人工视觉验收项。

### 实现约束

- 展示层只消费 TASK-004 的路径数据，不得重算 BEZIER、车道配对、侧移、弧长或流向。
- 全部路径只能使用一个合并几何和一个路径材质；不得创建逐边 Mesh、逐边材质或按类型复制着色器。
- 着色器以统一弧长属性计算高亮，并以流向属性表达正反方向；不得读取 `isBackEdge` 或边 ID 做视觉分支。
- 流光相位始终有界，长时间运行不得积累无界 elapsed 或浮点超大值；页面隐藏与恢复的状态必须显式且可推导。
- 帧循环除相机阻尼外只允许一次流光 uniform 写入，不得产生逐帧临时对象或更新静态几何。
- 路径不显示名称、连通性高亮、规划结果、点击或悬停交互；本任务创建的几何和材质必须可确定释放。

### 验证方式

- 执行 `pnpm test`，预期路径几何、着色器、流光时钟、全量扁带及 TASK-001 至 TASK-009 回归测试全部通过。
- 执行 `pnpm lint` 与 `pnpm build`，预期无类型、lint 或生产构建错误。
- 正常路径：加载 V76 路径包；预期一个路径批次覆盖 3045 条有向车道，998 个双向组间距 0.36 m，1049 条单向边无侧移，流光全部 source→target。
- 关键异常路径：流向为负的反向车道、页面隐藏后长时间恢复、无效属性长度或资源创建失败；预期反向流动正确、恢复不跳跃，无效数据不产生部分路径。
- 长期路径：在 Node 测试中模拟至少 24 小时相位推进；预期相位和 uniform 值始终有限有界，周期首尾连续。
- 人工验收：由用户在本地浏览器观察双车道无 Z-fighting、单向边无侧移、双向流向相反和长时间动画连续；Coding Agent 不得自动启动浏览器。

### 完成标准

- 单一合并路径、唯一材质、有向流光、有界帧更新和资源释放全部符合预算。
- `pnpm test`、`pnpm lint`、`pnpm build` 全部通过，TASK-001 至 TASK-009 的行为没有被破坏。
- 不存在逐边对象、重复流向算法、无界时间、帧内分配、审计标记分支或非目标交互。
- 与本任务相关的改动可形成单一独立 Git checkpoint，不混入相机、环境或后处理能力。
- 代码库处于一致、可运行、可验证状态，可以安全进入 TASK-011。

### 回退边界

回退本 TASK 的 Git checkpoint 只移除或还原路径 GPU 展示、流光材质、可见性相位和对应验证；TASK-001 至 TASK-009 的编译数据、加载体验和节点展示保持完整。
