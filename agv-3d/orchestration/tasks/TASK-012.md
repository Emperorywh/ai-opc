## 任务描述

### 可验证结果

完整拓扑被置于统一的深色科技沙盘环境中，具备由最终渲染边界推导的背景、环境范围、距离衰减网格、线性雾、本地环境光照和节点阴影；环境不会遮蔽远端拓扑，也不会与节点或路径图层互相修改内部对象。

### 输入

- SPEC §6.3、§8.1 至 §8.4、§11.1、§12、§13.3、§16.2 中的场景层级、主题、光照、网格、雾、阴影和环境范围要求。
- TASK-001 至 TASK-011 已交付的完整拓扑场景、最终渲染边界、相机 framing 和受控资源生命周期入口。
- 任务开始时仓库内已有的临时背景或最小照明；这些只作为待替换基线，不保留第二套环境实现。

### 输出

- 背景固定为 `#05080F` 的深色场景环境，以及由渲染边界加统一环境边距推导的地面、网格、雾和阴影覆盖范围。
- 独立网格图层，透明度随距地图中心距离衰减，不依赖相机或硬编码世界坐标。
- 线性雾，初始 framing 下完整拓扑仍可辨识，路径自定义材质与节点标准材质均正确参与雾效。
- 一个带阴影的方向光和一个低强度环境光；阴影贴图固定 2048×2048，只有节点投射阴影。
- 完全本地、程序化生成的环境光照资源及 PMREM，不请求远程 HDR、纹理或 CDN。
- 覆盖环境空间推导、雾范围、阴影预算、单一灯光配置、本地资源和卸载释放的自动化验证。
- 背景、网格、雾、光照、节点阴影和远端拓扑辨识度的人工视觉验收项。

### 实现约束

- 环境、路径、节点、相机和后处理保持独立图层边界；图层不得查询或修改其他图层内部的 Three.js 对象。
- 地面、网格、雾、阴影和后续反射范围只从 `renderBounds + 统一环境边距` 推导，不得写死 V76 世界坐标。
- 颜色、雾、灯光、阴影和环境参数按视觉/性能职责集中；不得在组件中散落重复值。
- 方向光只能有一个带阴影实例，环境光只能承担低强度补光；只有节点 `castShadow`，路径与网格不得投射阴影。
- 环境纹理与 PMREM 必须本地程序化生成并具有显式释放路径；不得下载远程 HDR，也不得保留临时最小照明形成重复光照。
- 不创建 `zones`、`nodeEdgeGroups` 或未来实时图层的空组件、空 store 或 feature flag。

### 验证方式

- 执行 `pnpm test`，预期环境范围、主题、阴影/PMREM 预算、资源释放及 TASK-001 至 TASK-011 回归测试全部通过。
- 执行 `pnpm lint` 与 `pnpm build`，预期无类型、lint 或生产构建错误，构建产物不包含远程环境资源请求。
- 正常路径：以 V76 `renderBounds` 创建环境；预期网格、雾、灯光和阴影范围均覆盖完整拓扑并使用统一边距，方向光/环境光数量符合契约。
- 关键异常路径：改变渲染边界尺寸和中心、重复挂载后卸载环境；预期所有环境范围同步推导，无硬编码裁切，程序化纹理与 PMREM 得到释放。
- 静态检查：确认只有节点投射阴影、阴影贴图为 2048×2048、没有远程 HDR/CDN URL、没有第二套临时光照或未来图层占位。
- 人工验收：由用户在本地浏览器观察网格距离衰减、线性雾、节点阴影、深色背景和远端拓扑辨识度；Coding Agent 不得自动启动浏览器。

### 完成标准

- 深色环境、网格、雾、本地环境光照和节点阴影完整呈现，范围与资源生命周期均可验证。
- `pnpm test`、`pnpm lint`、`pnpm build` 全部通过，TASK-001 至 TASK-011 的行为没有被破坏。
- 不存在硬编码环境范围、远程资源、重复灯光、图层互查、未释放 PMREM 或未来占位模块。
- 与本任务相关的改动可形成单一独立 Git checkpoint，不混入平面反射或后处理实现。
- 代码库处于一致、可运行、可验证状态，可以安全进入 TASK-013。

### 回退边界

回退本 TASK 的 Git checkpoint 只移除或还原深色环境、网格、雾、本地环境光照、阴影和对应验证；TASK-001 至 TASK-011 的拓扑、加载、节点、路径和相机能力保持完整。
