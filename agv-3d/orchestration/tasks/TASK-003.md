## 任务描述

### 可验证结果

全部有向边能够仅依据反向拓扑与几何等价性，确定地形成双向车道组或单向车道组；双向车道使用稳定规范方向分居共享中心线两侧，单向边严格保持在自身中心线上。

### 输入

- SPEC §4.2、§7.1、§7.4、§7.6、§13.1、§16.1 中的反向边审计、配对、偏移和流向不变量。
- TASK-001 至 TASK-002 已交付的严格领域模型、唯一有向节点对保证、确定性采样与坐标基准。
- 任务开始时仓库内已有的车道分组能力和 V76 集成测试；已有结果必须按 SPEC 的“33 个等参数点且独立于渲染采样”语义重新审计。

### 输出

- 反向拓扑候选的唯一匹配和几何等价比较能力。
- 双向组稳定的规范方向、共享中心线、两条有向边标识、`+0.18 m`/`-0.18 m` 车道偏移及相反流向记录。
- 无法配对的有向边形成偏移为 0、流向为 source→target 的独立单向组。
- V76 全量审计结果：979 对完全反向且几何完全一致的边，加上 19 对反向拓扑存在且中心线偏差不超过 0.02 m 的边，共形成 998 个双向组；其余形成 1049 个单向组，累计 3045 条有向车道记录，所有原始有向边恰好覆盖一次。
- 覆盖容差边界、输入顺序、规范方向、几何差异、单向偏移、审计标记隔离和重复执行稳定性的自动化验证。

### 实现约束

- 配对先按相反 source/target 查找唯一候选，再把两条原始路径统一到相同方向，以 33 个等路径参数点比较；该比较不得复用或依赖渲染自适应采样密度。
- 最大对应点偏差不超过 0.02 m 才能成组；容差不得通过四舍五入、吸附或放宽阈值实现。
- 双向组规范方向固定为较小节点 ID 指向较大节点 ID；结果不得受输入遍历顺序影响。
- 双向组只使用规范方向边的中心线作为共享中心线；两条边的标识和各自 source→target 流动方向必须保留。
- 单向边偏移必须精确为 0；不得为了视觉对齐而侧移。
- `isBackEdge` 不得进入配对、偏移、规范方向或流向分支；改变其值后布局结果必须不变。
- 分组属于几何层纯计算，依赖方向只能指向领域层，不得读取展示状态或创建场景对象。

### 验证方式

- 执行 `pnpm test`，预期车道单元测试、V76 全量分组测试及 TASK-001 至 TASK-002 回归测试全部通过。
- 执行 `pnpm lint` 与 `pnpm build`，预期无类型、lint 或构建错误。
- 正常路径：对完全反向一致、偏差恰好在容差内和 V76 全量路径执行分组；预期形成稳定双向组，车道中心间距为 0.36 m，并得到 998/1049/3045 统计。
- 关键异常路径：反向拓扑不存在、反向几何偏差超过 0.02 m、自环或候选已不满足成组条件；预期相关边分别成为偏移 0 的单向组，不丢边、不重复成组。
- 不变量路径：反转输入顺序并任意翻转所有 `isBackEdge` 值；预期规范方向、共享中心线、车道偏移、流向和全量统计完全一致。验证不启动浏览器。

### 完成标准

- 全部有向边形成可审计、确定且符合容差的车道布局，V76 统计与 SPEC 一致。
- `pnpm test`、`pnpm lint`、`pnpm build` 全部通过，TASK-001 至 TASK-002 的行为没有被破坏。
- 不存在基于审计标记的魔法分支、重复配对算法、隐式顺序依赖、吸附或兼容逻辑。
- 与本任务相关的改动可形成单一独立 Git checkpoint，不混入扁带或展示实现。
- 代码库处于一致、可运行、可验证状态，可以安全进入 TASK-004。

### 回退边界

回退本 TASK 的 Git checkpoint 只移除或还原车道分组、规范方向、偏移和对应验证；此前的数据校验、路径采样与世界坐标能力保持不变。
