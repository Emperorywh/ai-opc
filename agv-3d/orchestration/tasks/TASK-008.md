title: 提供真实加载进度与统一错误呈现
---

## 任务描述

### 可验证结果

用户在地图准备期间始终看到与应用状态一致的简体中文阶段和整数百分比；任一下载、解析、校验、编译或场景资源错误都会切换到统一、稳定且可定位的错误界面，加载中和失败时绝不暴露不完整地图。

### 输入

- SPEC §5.3、§10、§13.3、§16.3 中的加载阶段、真实进度、统一错误界面和人工验收要求。
- TASK-001 至 TASK-007 已交付的完整后台加载闭环、显式状态流和结构化错误。
- 任务开始时仓库内已有的展示派生、加载/错误视图和覆盖层样式；已有界面逻辑只作为待审计基线。

### 输出

- 七个活跃阶段对应的唯一简体中文名称，以及由状态进度直接派生的 0～100 整数百分比。
- 加载状态下只展示阶段名称、百分比和与其同源的简洁进度反馈，不增加业务叠层。
- 错误状态下展示稳定错误码、发生阶段和简短中文说明；结构化详情保留给开发日志，不在用户界面暴露冗长字段路径。
- 覆盖层选择规则：未启动/加载/准备时显示加载界面，error 显示错误界面，ready 才移除覆盖层。
- 覆盖正常加载、百分比单调、所有稳定错误码、ready/error 终态和展示文案完整性的自动化验证。
- 加载、错误和遮挡不完整场景的人工界面验收项。

### 实现约束

- 展示层只读取应用层只读状态并派生显示模型，不重新计算阶段、不平滑伪造进度、不直接推进状态机。
- 百分比必须与 0～1 进度同源且不回退；解析阶段不得通过动画伪造连续处理进度。
- loading、preparing 和 error 时，任何已创建或半创建的场景都必须被完全遮挡；error 后不显示节点、路径或上一次成功场景。
- 错误界面不得提供自动重试、跳过坏记录、兼容入口、降级按钮或替代实现。
- 用户可见文案为简体中文；错误码保持稳定英文标识，详细字段路径仅进入结构化开发信息。
- 不引入点击详情、搜索、筛选、图例、名称、标题或其他本期非目标。

### 验证方式

- 执行 `pnpm test`，预期展示派生、状态进度、错误映射和 TASK-001 至 TASK-007 回归测试全部通过。
- 执行 `pnpm lint` 与 `pnpm build`，预期无类型、lint 或生产构建错误。
- 正常路径：按完整事件序列推进状态；预期七个阶段名称依次出现、整数百分比与状态一致且单调，只有 ready 后覆盖层消失。
- 关键异常路径：在六类稳定错误对应阶段注入失败；预期立即显示对应错误码、实际阶段和中文说明，详细路径可在开发日志定位，且不显示不完整地图。
- 终态路径：error 或 ready 后继续提交旧进度；预期界面不回到加载状态。
- 人工验收：由用户自行在本地浏览器观察阶段文案、百分比、错误卡片和全屏遮挡效果；Coding Agent 不得自动启动浏览器或执行浏览器自动化。

### 完成标准

- 真实加载进度和统一错误呈现均与应用状态一一对应，正常与异常路径可重复验证。
- `pnpm test`、`pnpm lint`、`pnpm build` 全部通过，TASK-001 至 TASK-007 的行为没有被破坏。
- 展示组件保持薄层，没有重复状态、伪进度、自动重试、半成品泄露或业务交互扩张。
- 与本任务相关的改动可形成单一独立 Git checkpoint，不混入节点、路径或环境场景实现。
- 代码库处于一致、可运行、可验证状态，可以安全进入 TASK-009。

### 回退边界

回退本 TASK 的 Git checkpoint 只移除或还原加载/错误显示模型、界面和对应验证；TASK-001 至 TASK-007 的数据、几何、状态和后台加载闭环保持完整。
