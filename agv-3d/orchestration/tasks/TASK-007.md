## 任务描述

### 可验证结果

应用外壳首次提交后能够立即启动唯一的后台加载会话，在 Worker 中完成自托管地图下载、完整性校验、解析、严格校验、规范化和几何编译，并以真实进度和零拷贝渲染数据包驱动应用状态进入场景准备；取消或卸载会彻底终止后台工作。

### 输入

- SPEC §3、§4.1、§5.1、§5.2、§5.4、§10.1、§10.2、§13.2、§14.2、§16.3 中的资产加载、Worker 数据流、错误、转移和生命周期要求。
- TASK-001 至 TASK-006 已交付的数据/几何能力、完整渲染包契约以及唯一加载会话和应用边界。
- 任务开始时仓库内已有的资产 URL、完整性校验、Worker 协议、后台编译和 React 启动绑定；必须审计固定字节基线的下载进度、依赖方向和终止语义。

### 输出

- 应用外壳首次渲染后无需用户操作即可启动的本地地图加载闭环，地图不是功能懒加载，也不请求 CDN。
- Worker 内的完整流程：流式下载 → 解析前字节数/SHA-256 校验 → JSON 解析 → 严格校验与规范化 → 节点和路径几何编译。
- 真实阶段事件：下载以已读取字节/6,516,343 计算，解析只报告开始/完成，校验、节点和路径阶段按已处理记录数报告。
- 成功时包含节点实例、合并路径、渲染边界和编译报告的完整数据包；所有大 TypedArray 的 ArrayBuffer 所有权一次性转移到主线程，不复制等量数组。
- 下载、完整性、解析、结构校验、几何编译和不可预期执行错误到应用稳定错误码的确定映射。
- 组件卸载、会话取消和 StrictMode 重复挂载时中止下载、终止 Worker、清理事件监听并隔离过期消息的能力。
- 覆盖成功事件序列、全部错误来源、真实进度、转移列表、中止、过期消息和无未处理 Promise rejection 的自动化集成验证。

### 实现约束

- 数据流必须保持 `资产 URL → Worker 下载/解析/校验/编译 → Transferable 数据包 → 主线程`；R3F 组件不得读取原始 JSON，主线程不得重复编译几何。
- 下载阶段的分母固定使用资产契约字节数，不能因缺失或错误的 `Content-Length` 把首个分块误报为 100%；实际字节总数最终仍由完整性校验裁决。
- 完整性校验必须发生在 UTF-8 解码和 JSON.parse 之前；指纹不一致立即失败，不进入后续阶段。
- Worker 编排只依赖领域与纯几何能力；浏览器运行时细节和主线程通信适配不得造成 Worker、domain 或 geometry 对 application/infrastructure 的反向依赖。
- 应用层通过 TASK-006 的协作边界消费编译事件，不直接依赖 Worker API 或基础设施具体类。
- 每次成功消息只转移本次数据包拥有的 ArrayBuffer；转移后 Worker 不再访问已分离缓冲，不建立隐式缓存。
- 同一会话只拥有一个有效 Worker；取消以确定方式终止在途下载和计算，不自动重试、不复用已终止 Worker、不保留 fallback 实现。

- 执行 `pnpm test`，预期 Worker 核心、加载用例、会话、V76 全量编译及 TASK-001 至 TASK-006 回归测试全部通过。
- 执行 `pnpm lint` 与 `pnpm build`，预期 Worker 入口和地图资产被生产构建正确打包，无类型、依赖方向或构建错误。
- 正常路径：以当前 V76 字节驱动完整后台流程；预期事件顺序严格、进度单调、报告为 1768/3045/998/1049，成功数据包在主线程保持同一转移后缓冲引用。
- 关键异常路径：分别模拟网络失败、字节数错误、SHA-256 错误、JSON 语法错误、结构校验失败、几何编译失败和 Worker 未捕获错误；预期只进入对应统一 error，不产生成功数据包或半成品结果。
- 生命周期路径：下载和编译中途取消、卸载或启动新会话；预期旧 Worker 被终止、监听被清理、过期消息被忽略、后台执行单元最终归零且无未处理异步拒绝。
- 下载边界：模拟缺失/错误 Content-Length 和多分块响应；预期进度仍按 6,516,343 固定基线单调计算，最终完整性校验决定成败。验证在 Node/命令行环境完成，不启动浏览器。
