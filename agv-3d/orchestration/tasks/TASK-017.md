## 任务描述

### 可验证结果

完整地图在实际部署目标机上以全部效果开启达到 1080p 与 4K 的 P95 帧时间指标，并通过至少 24 小时浸泡、连续交互、resize 和卸载验证；验收结果包含可复现的硬件、软件、物理渲染尺寸和资源趋势记录。

### 输入

- SPEC §1、§2、§11、§13.2、§13.3、§14.1、§15、§16、§17 中的总体目标、非目标、技术基线、固定预算、帧率、稳定性、交付物、验收和未来扩展边界。
- TASK-001 至 TASK-016 已交付的完整可运行 AGV 3D 地图、全部效果、资源生命周期和自动化门禁。
- 实际部署目标机、目标浏览器以及人工验收权限；目标机是帧率与 24 小时稳定性的唯一硬件基线。

### 输出

- 固定运行预算被实际满足：4 个节点 DrawCall、1 个路径 DrawCall、1 个路径材质、1024×1024 反射目标、2048×2048 阴影贴图、主画布最大 3840×2160 总像素、运行期静态几何更新 0 次、每帧业务更新仅一个有界流光 uniform。
- 1920×1080 和 3840×2160 两组目标机性能记录；每组预热 30 秒后连续采样 5 分钟，分别达到 P95 ≤ 16.7 ms 和 P95 ≤ 33.3 ms。
- 性能记录包含 GPU、显存、驱动、浏览器版本、操作系统缩放和实际物理渲染尺寸，并说明采样方法和效果开关状态。
- 至少 24 小时浸泡记录，证明 JavaScript Heap、`renderer.info.memory` 和 Worker 数量不呈单调增长趋势。
- 连续旋转/缩放/平移、反复 resize、页面隐藏/恢复和场景卸载结果；卸载后 Worker 为 0、事件监听移除、GPU 资源回到加载前基线。
- 为达到指标所需的架构内性能修正及其自动化回归验证；不得牺牲完整地图、既定视觉效果或模块边界。
- 最终编译统计、性能记录、浸泡记录和人工视觉/交互验收结论。

### 实现约束

- 性能测试期间必须保持流光、Bloom、SMAA、反射、阴影、网格、雾和 OrbitControls 阻尼开启，节点与路径数量完整。
- 不得通过运行时关闭效果、降低节点/路径数量、切换简化实现、加入设备降级分支或降低固定反射/阴影预算达标。
- 连续交互和 resize 不得创建新几何或材质；静态数据不得重新下载、解析、校验或编译。
- 页面可见时持续渲染，隐藏时暂停流光业务更新；恢复后相位保持有界，不累计超大 delta。
- 性能优化必须保持既定分层和依赖方向，不得把几何算法移入展示层、引入全局缓存、复制渲染数据包或产生巨型组件。
- 验收记录必须来自实际目标机真实测量，不得用开发机估算、合成数字或单帧截图替代。
- 不新增未来实时 AGV、规划、区域、搜索或多地图占位；后续能力只能通过独立图层与应用用例接入。
- 不新增点击详情、悬停提示、筛选、定位、图例、比例尺、指北针、标题水印、地图编辑、导出或量测，也不接入设备实时状态和旧地图/后端兼容协议。

### 验证方式

- 执行 `pnpm test`，预期全部自动化测试通过，且编译报告稳定为 1768 个节点、3045 条有向车道、998 个双向组、1049 条单向边。
- 执行 `pnpm lint` 与 `pnpm build`，预期生产构建通过，无校验警告、被跳过记录或未处理 Promise rejection。
- 正常性能路径：由用户在目标机分别以实际 1920×1080、3840×2160 物理渲染尺寸预热 30 秒、采样 5 分钟；预期 P95 分别不高于 16.7 ms、33.3 ms，全部效果和完整数据保持开启。
- 长期路径：由用户在目标机连续运行至少 24 小时并定期记录 Heap、GPU 资源和 Worker；预期各指标无单调增长趋势，页面隐藏/恢复后动画连续有界。
- 交互/卸载路径：持续操作相机并反复 resize，随后卸载场景；预期不新建静态几何/材质，Worker 归零、监听移除、GPU 资源回到加载前基线。
- 视觉与交互最终验收：由用户确认类型、朝向、流向、Bloom、反射、阴影、网格、雾、framing、控制、resize、加载、淡入和错误界面。Coding Agent 只准备可验收构建和记录方式，不得自动启动浏览器。

### 完成标准

- 1080p/4K P95、24 小时稳定性、运行预算、卸载基线和最终人工验收均有真实记录且全部达标。
- `pnpm test`、`pnpm lint`、`pnpm build` 全部通过，TASK-001 至 TASK-016 的行为和视觉效果没有被破坏。
- 代码库不存在为达标引入的运行时降级、重复资源、跨层耦合、临时性能 patch、未解释警告或未来占位。
- 与本任务相关的性能修正、自动化验证和验收记录可形成单一独立 Git checkpoint，不混入无关功能。
- 代码库与验收记录共同构成 SPEC 规定的完整可交付状态，可安全结束本线性任务序列。

回退本 TASK 的 Git checkpoint 只移除本任务内的性能修正与目标机验收记录，不移除 TASK-001 至 TASK-016 已完成的功能场景；回退后系统仍可运行，但不再声明已达到目标机帧率与 24 小时稳定性验收。
