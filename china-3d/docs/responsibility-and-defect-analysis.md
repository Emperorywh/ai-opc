# 中国 3D 地势图责任划分与缺陷分析

> 分析日期：2026-07-31  
> 分析对象：`docs/SPEC.md`、`.apex-coding-agent/plans/1.json`、`china-3d` 实际源码及当前效果截图  
> 文档性质：项目复盘与重构立项依据，不是正式测绘或审图结论

## 1. 结论摘要

当前成果属于典型的“工程验收全绿，产品视觉验收失败”。

数据资产、GPU 位移、行政区边界、标签组件和自动化测试均已实现，但默认画面没有达到规格中“真实、立体、精致、标签可读”的核心目标。当前效果中的平面感和文字不可读不是主观审美分歧，而是可以由渲染尺度直接推导出的确定性问题。

综合责任划分如下：

| 责任层 | 建议占比 | 核心责任 |
|---|---:|---|
| 规格说明 | 45% | 米制平面坐标与 `k=2.0` 垂直夸张存在尺度矛盾；未定义屏幕空间可读性和构图指标；默认省会文字策略与实际期望不一致 |
| 编码与最终验收执行 | 40% | 未做屏幕空间校准；默认相机、字号、光点和地形高度组合后必然不可读、不可感知；最终验收产生明显假阳性 |
| task 拆分与验收设计 | 15% | 拆分覆盖较完整，但机械继承错误数值，验收偏重组件存在和技术正确性，缺少可量化的感知质量门槛 |

责任占比用于说明问题来源和整改优先级，不代表任何人员绩效认定。

## 2. 当前效果判定

### 2.1 明确失败项

1. 默认视角下没有形成可感知的地形隆起，青藏高原主要依赖分层设色被识别，而不是依靠真实三维轮廓、视差和明暗关系被识别。
2. 省名虽然已创建为 3D 文本对象，但默认屏幕字号过小，不能满足“始终可读”。
3. 省会光点只表现为数像素的小点，视觉层级过弱。
4. 省界高亮远强于地形起伏和标签，画面更接近平面行政区底图。
5. 主图覆盖完整南海范围，导致大陆主体被进一步压缩；默认构图上方留白过多，核心视觉焦点不集中。
6. 验收文档宣称“地形起伏明显、标签可读”，与当前最终效果直接矛盾。

### 2.2 不应误判为缺失的功能

以下能力在代码和资产层面确实存在，不能简单归类为“没有开发”：

- 4096²、16 位 DEM 高程资产存在且抽样地势关系正确。
- vertex shader 已执行 GPU 高程位移。
- 34 个省名文本、34 个省会光点及对应字体子集均存在。
- 省界、政治要素、南海附图、海拔图例和合规角标均已装配。
- 构建、单元测试和资产校验均通过。

因此，主要问题不是数据缺失或组件漏装，而是视觉尺度契约、默认参数和验收方法失效。

## 3. 量化证据

### 3.1 默认渲染尺度

根据当前源码计算：

| 指标 | 当前值 | 来源 |
|---|---:|---|
| 主图世界宽度 | 7,124,447 m | `src/lib/projection.ts`、`src/three/terrain-layout.ts` |
| 默认相机距离 | 10,367,348 m | `src/three/camera-constraints.ts` |
| 默认垂直 FOV | 42° | `src/three/camera-constraints.ts` |
| 默认垂直夸张系数 | 2.0 | `src/config/terrain-config.ts` |
| 生产 DEM 实测最高点 | 6,180 m | `pnpm verify:assets` |
| 省名字号 | 32,384 m | `src/config/place-labels.ts` |
| 省会名字号 | 20,356 m | `src/config/place-labels.ts` |
| 省会光点直径 | 27,830 m | `src/config/place-labels.ts` |

以 1080px 高画布、对象位于默认观察目标附近估算：

```text
每公里对应像素 ≈ 1080 / (2 × 相机距离 × tan(FOV / 2)) × 1000
              ≈ 0.13569 px/km
```

得到：

| 视觉对象 | 默认屏幕尺寸 | 结论 |
|---|---:|---|
| DEM 实测最高点位移：6180m × 2 | 约 1.68px | 无法形成稳定、清晰的三维轮廓 |
| 编码理论最高点位移：9000m × 2 | 约 2.44px | 即使达到编码上限仍明显不足 |
| 省名字高 | 约 4.39px | 不具备正常阅读条件 |
| 省会名字高 | 约 2.76px | 默认视角下基本不可读 |
| 省会光点直径 | 约 3.78px | 只能表现为小点或小方块 |

这组结果与当前截图完全一致，证明平面感和标签不可读是默认配置的必然结果。

## 4. 规格说明层缺陷

### SPEC-01：水平尺度与垂直尺度存在根本矛盾

严重级别：阻断

规格要求平面使用 EPSG:3857 米制坐标，同时规定：

```text
世界 y = 真实海拔 h × k
k 默认 2.0，可配置范围 1.5–3.0
```

全国宽度为数千公里，而地形高度只有数公里。两者保持同一米制尺度且只放大两倍时，默认全景相机中地形隆起只能占约 1–2px。

这使“适度夸张、青藏高原明显隆起、凸显西高东低”等视觉目标无法同时成立。

### SPEC-02：缺少屏幕空间视觉指标

严重级别：高

规格只描述“明显”“精致”“始终可读”，没有定义：

- 默认分辨率和默认视角下的最小地形起伏像素。
- 省名、省会名的最小字高。
- 省会点的最小直径。
- 中国大陆主体的画面占比。
- 省界、地形、标签之间的视觉优先级。
- 可被人工读取的指定省名验收样本。

因此，实现可以在结构上满足全部条目，却在视觉上完全失败。

### SPEC-03：主图范围与核心构图目标冲突

严重级别：中高

规格要求主 3D 图覆盖 `72°E–136°E、3°N–54°N`，同时还要求右下角南海附图。

完整南海范围会扩大主图包围盒、压缩大陆主体，并迫使默认相机拉远。附图已经承担南海局部展示职责，但规格没有重新平衡主图的视觉焦点。

### SPEC-04：省会文字展示策略与实际期望不一致

严重级别：中

规格允许省会名称仅在 hover 或 tooltip 中显示，默认只显示“省名 + 省会光点”。因此当前默认画面不显示省会名称，并不完全属于编码漏做。

如果产品期望默认展示北京、成都、广州等省会城市名称，应先修改规格，明确常驻、分级显示、缩放阈值和密集区域避让策略。

## 5. task 层缺陷

### TASK-01：机械继承了错误的垂直比例

严重级别：高

TASK-006 将 `k=2.0、范围 1.5–3.0` 作为不可偏离的验收条件，没有重新核验该参数与米制主图、相机距离及屏幕分辨率的关系。

### TASK-02：验收描述正确，但缺少可执行的感知门槛

严重级别：高

task 已写明：

- 开发预览应看到西高东低起伏。
- 34 个省名应始终可读。
- 最终截图应看到地形、标签和其他主要图层。

但没有把这些目标转化为可测试的默认视角像素指标。因此，“场景中创建了文本对象”和“截图中存在亮色像素”被错误地当成“文字可读”。

### TASK-03：复用姊妹项目造成确认偏差

严重级别：中

计划预先将姊妹项目描述为“既有完整实现”和“已验证资产/参考实现”，降低了对视觉方案重新质疑和校准的概率。

资产复用本身没有问题，但“资产已验证”不能推导出“视觉实现已达到当前规格目标”。

### TASK-04：最终截图验收粒度不足

严重级别：高

TASK-016 只要求主要图层“可见”，没有要求：

- OCR 或人工读取指定省名。
- 地形轮廓与平面基线的最小像素差。
- 默认画面主体占比。
- 标签与省界的对比度、遮挡和层级。
- 与参考视觉或设计基线做差异对照。

## 6. 编码与执行层缺陷

### CODE-01：垂直位移公式技术正确、视觉错误

严重级别：阻断

shader 正确实现了 `y=h×k`，CPU 高程、边界贴地和标签贴地也保持同一公式。架构一致性没有问题，但它一致地执行了一个无法产生足够立体感的视觉尺度。

这属于“实现符合公式，但公式不符合产品目标”。

### CODE-02：世界空间字号没有经过屏幕空间校准

严重级别：阻断

省名字号按主图宽度 `/220` 推导，省会名字号按 `/350` 推导。该比例在默认相机下分别只有约 4.39px 和 2.76px。

代码只验证了字号为正、省名字号大于省会名字号，却没有验证默认画面是否可读。

### CODE-03：省会光点尺寸和表现层级不足

严重级别：高

省会光点默认直径约 3.78px，且可选光柱被配置为关闭。点位数据正确，但视觉存在感不足，无法形成“省会城市光点”的明确层级。

### CODE-04：默认相机与主体构图没有联合校准

严重级别：高

相机距离、仰角、FOV、主图包围盒、垂直比例和标签字号分别有独立配置与测试，但没有一个统一的“默认镜头感知质量”契约。

各模块局部正确，组合结果整体失败。

### CODE-05：省界视觉权重压过地形和标签

严重级别：中高

浅色发光省界在截图中最清晰，而地形隆起和省名不可读，导致视觉语义从“真实 3D 地势图”退化为“带高程着色的平面行政区地图”。

### CODE-06：最终验收产生假阳性

严重级别：阻断

`docs/acceptance-review-record.md` 宣称：

- 青藏高原隆起明显。
- 省名标签与省会光点可读。
- 最终视觉验收通过。

但其截图自动化证据主要统计：

- 非背景像素。
- 雪顶颜色像素。
- 省界亮色像素。
- “标签/光点”合并后的近白亮像素。

近白像素无法区分省名、光点、省界和雪山，也不能证明任何文字可读。当前截图已经直接否定该验收结论。

### CODE-07：测试数量与用户结果脱节

严重级别：高

当前验证结果：

| 检查项 | 结果 |
|---|---|
| `pnpm build` | 通过 |
| `pnpm test` | 43 个测试文件、883 个用例通过 |
| `pnpm verify:assets` | 全部通过 |

这些测试证明了数据、契约、公式和组件装配的技术正确性，但没有证明默认画面的立体感、可读性和构图质量。

## 7. 架构层评价

当前源码的数据契约、高程 Provider、准备层、渲染层、配置层和状态流总体具有明确边界。主要问题不是巨型函数、重复逻辑或跨层耦合，也不是字体或地理数据没有加载。

准确评价应当是：

> 编码结构较完整，数据与状态架构基本合理；视觉尺度架构缺失，最终感知质量不合格。

不能因为测试数量多、模块拆分细，就认定产品目标已经实现；也不能因为视觉失败，就误判所有底层工程都需要推倒重写。

## 8. 整改原则与优先级

### P0：先修订规格中的视觉尺度契约

不要直接在现有范围内把 `k=2` 临时改成另一个魔法数字。应明确：

1. 地理米制坐标与渲染坐标的转换层。
2. 独立于真实海拔的视觉垂直比例。
3. 默认相机下最大地形起伏的目标屏幕像素。
4. 主图是否必须同时承载完整南海真实位置。

### P0：建立默认镜头的屏幕空间验收标准

建议至少加入：

- 省名字高不低于 14–16px。
- 常驻省会名不低于 11–13px；如果仍采用 hover-only，规格必须明确。
- 省会点直径不低于 6–8px。
- 青藏高原相对东部平原的可见轮廓差不低于约 40px。
- 中国大陆主体占默认画布的明确比例。
- 人工或 OCR 能读取一组指定省名。

具体阈值应由新的视觉基线截图确认，而不是直接把本节建议当成最终常量。

### P1：联合重构地形、相机和标签尺度

地形垂直比例、默认相机、标签字号、标签浮高和光点大小必须由同一个默认镜头质量模型联合推导，避免继续出现“每个模块都正确、组合后不可用”。

### P1：重建视觉验收

最终验收至少应同时包含：

- 结构与数据契约测试。
- 默认视角截图基线。
- 屏幕空间几何测量。
- 指定文字可读性检查。
- 人工视觉复核结论。

颜色像素数量只能作为辅助证据，不能作为“3D 明显”或“文字可读”的证明。

## 9. 最终判定

1. 当前成果不满足 `SPEC §12.1` 的“地形真实、起伏明显”。
2. 当前成果不满足 `SPEC §12.4` 的“省名 Billboard 始终可读”。
3. 默认不显示省会名称基本符合现有规格和 task，但不符合当前提出的实际产品期望，需先修改需求。
4. task 的模块拆分总体完整，不是主要失败原因；其主要问题是验收设计缺少感知质量指标。
5. 编码层没有漏掉核心组件，但没有完成默认画面的视觉校准，最终验收结论失真。
6. 后续应先修订规格和验收契约，再重构视觉尺度体系；不建议继续在现有参数上做零散补丁。
