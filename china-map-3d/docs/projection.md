# 统一米制投影与世界坐标转换（TASK-007）

本文档说明 china-map-3d 的**统一投影领域层**：经纬度如何确定性变换到 EPSG:3857 平面米坐标、
以地图中心为基准的主图世界坐标，以及南海 2D 附图的视口映射。所有渲染层（地形 mesh、省界描边、
标签光点、附图 overlay、hover 反查）只能通过 `src/lib/projection.ts` 完成坐标变换，不得各自
重写墨卡托公式或按图层微调坐标（SPEC §3.3、§13）。

> 适用范围：纯地理坐标变换。不承载业务数据映射、不下钻、不绑定业务数值（见 SPEC「非目标」）。

---

## 1. 分层与依赖方向

```
                  ┌──────────────────────────────────────────┐
   契约层          │ src/geo-contracts                        │  纯 TS，零渲染依赖
  （公共稳定面）   │   CHINA_MAIN_MAP_EXTENT、LonLatCoordinate │
                  │   ↑ 只能单向依赖                          │
                  ├──────────────────────────────────────────┤
   运行时访问层    │ src/lib/projection.ts（本 TASK）          │  依赖契约层 + d3-geo
  （投影权威）     │   ↑ 只能单向依赖                          │
                  ├──────────────────────────────────────────┤
   渲染 / 交互层   │ src/components（后续 TASK）               │  Three.js / React
                  │   地形 / 省界 / 标签 / 附图 / hover        │
                  └──────────────────────────────────────────┘
```

**强约束**：
- 投影领域层 `src/lib/projection.ts` 只依赖契约层与 d3-geo，**禁止** import React / Three.js /
  R3F 场景对象或 UI 状态。渲染层单向依赖本模块，反向依赖即违规。
- 离线 DEM 生产层（`scripts/dem/mercator.ts`）保留其闭式墨卡托原语用于无重依赖重投影；
  本模块的 d3-geo `geoMercator` 与该闭式公式基于同一 EPSG:3857 定义（R = 6378137 球面墨卡托），
  在主图范围内数值等价（自动化测试以 ≤1mm 容差断言），二者不构成竞争性「两套投影」——
  运行时唯一权威是本模块，离线原语仅服务于 DEM 流水线且被证明一致。

## 2. 坐标系与单位（全仓唯一契约）

| 维度 | 约定 |
|---|---|
| 源坐标基准 | EPSG:4326（WGS84 经纬度，单位度） |
| 平面投影 | EPSG:3857（Web 墨卡托，单位米） |
| 球体半长轴 | R = 6378137 米（EPSG:3857 定义常数） |
| 主图地理范围 | 经度 72°E–136°E、纬度 3°N–54°N（含端点，南端覆盖曾母暗沙 ≈3.58°N） |
| 地图中心 | (经度 104°E, 纬度 28.5°N) = 主图四至经纬度中点 |
| 世界 x | Mx − Mxc，单位米，+X 指向正东 |
| 世界 z | Myc − My，单位米，+Z 指向正南（故 −Z 指向正北） |
| 世界 y | 真实高程（米），由地形顶点着色器施加垂直夸张 k（y = h·k）；本模块不产出/不消费 y |
| 世界原点 | (0, 0, 0) = 地图中心在海平面 |

**关键说明**：
- d3-geo 的 `geoMercator` 按**屏幕坐标惯例**输出（y 向下为正），即 d3_y = −真实北距。本模块在
  领域能力边界统一取负，对外只暴露「北距向北递增」的工程语义 EPSG:3857 (Mx, My)。消费者无需
  感知 d3 的 y 翻转——这是本模块封装的一部分，不是「魔法修补」。
- 世界 z 取 `Myc − My`（+Z = 南）而非直接 `My − Myc`，是为了让 SPEC §4.1 的「相机置于地图东南
  上方看向中心」自然成立：相机位于 (+X, +Y, +Z) 即东—南—上方，俯瞰西北，青藏高原（西、高）
  落在画面左上、东部平原（东、低）落在右下，凸显西高东低。
- **y 专用于高程**：禁止用 x/z 承载高程语义；也禁止把夸张后的 world-y 当真实海拔用于分层设色
  （SPEC §3.1，会导致整图颜色偏移 k 倍）。

## 3. API 概览（`src/lib/projection.ts`）

| 导出 | 语义 | 失败条件 |
|---|---|---|
| `projectToMercator(lon, lat)` | 通用前向：经纬度 → EPSG:3857 (Mx, My) | 非有限、经度越 [-180,180]、纬度越墨卡托有效上限 |
| `projectToWorld(lon, lat)` | 主图前向：经纬度 → 中心化世界 (x, z) | 上述 + 主图范围 [72,136]×[3,54] 外 |
| `invertMercator(x, y)` | 通用反向：EPSG:3857 → 经纬度 | 非有限、d3 不可逆 |
| `invertWorld(x, z)` | hover 反查：世界 (x, z) → 经纬度 | 非有限（不再次裁剪范围，忠实还原） |
| `projectToInset(lon, lat, extent)` | 附图视口映射：经纬度 → 归一化 (u, v) ∈ [0,1]² | 非有限、墨卡托域外、附图四至外、附图四至畸形 |
| `MAIN_MAP_WORLD_BOUNDS` | 主图四至的世界包围盒（缓存常量） | — |
| `MAIN_MAP_CENTER` | 地图地理中心 (104, 28.5) | — |
| `MAIN_MAP_EXTENT` | 主图范围（同契约层常量） | — |

**结果类型**：所有变换返回 `ProjectionResult<T>` 判别联合——成功带 `value`，失败带稳定 `code` 与
简体中文 `message`。**失败绝不静默映射到世界原点或钳制**（SPEC 约束 + 验证方式 4）。

**缓存**：`geoMercator` 实例、主图中心墨卡托坐标、主图世界包围盒均在模块加载时一次性计算并
冻结为模块级常量，所有消费者复用同一份（确定性单例，无隐式可变状态）。

## 4. 反向查询不变量

- `invertMercator` 是 `projectToMercator` 在「有限且合法」输入上的数值逆运算；
  `invertWorld` 是 `projectToWorld` 的数值逆运算。任一前向合法点经对应反变换后，经纬度误差
  落在浮点量化容差内（自动化测试以 1e-7° 声明）。
- `invertWorld` **不再次校验**经纬度是否落在主图范围——反查的职责是「忠实还原坐标」，是否属于
  某省由上游拾取逻辑判定；范围越界不应让反查静默失败或钳制。

## 5. 南海附图与主图共享同一墨卡托

附图是独立于 3D 主世界的 2D overlay（SVG/Canvas，SPEC §3.8）。`projectToInset` 内部对附图四至
西南角、东北角与目标点都调用同一 `projectToMercator`，再在墨卡托平面线性归一化：
`u = (Mx − Mx_sw)/(Mx_ne − Mx_sw)`、`v = (My − My_sw)/(My_ne − My_sw)`。

- 视口方向沿用**标准地图阅读方向**：u 随经度向东递增（左→右），v 随纬度向北递增（下→上）。
  这与 3D 世界 z（+Z = 南）不同，但二者内部都走同一 `projectToMercator`——同一南海点位在主图
  与附图来自**同一墨卡托结果**，仅视口映射不同（验证方式 3 以此断言）。
- 线性归一化等价于「附图本身也是一张墨卡托子图」，不引入第二套投影。
- SVG overlay 消费时自行把 v 翻转成屏幕 y（屏幕 y 向下）。

## 6. 地形网格 UV 对齐契约（供 TASK-008）

统一投影只冻结「世界 (x, z) ↔ EPSG:3857 (Mx, My) ↔ 经纬度 (lon, lat)」三者的确定关系。
heightmap 像素布局（见 `scripts/dem/build-heightmap.ts`）：**行 0 = 北、列 0 = 西**，即像素
(row=0, col=0) 对应西北角 (72°E, 54°N)。

地形 mesh（TASK-008）用 `MAIN_MAP_WORLD_BOUNDS` 确定 `PlaneGeometry` 的世界尺寸与定位，并据此
对齐 UV：纹理 u 对应列（西→东，与世界 +X 一致），纹理 v 对应行（北→南，需配合纹理 flipY 使
UV.v 与世界 z 方向一致）。具体 UV wiring 属于地形 mesh 的实现职责，但必须保证「按顶点世界坐标
反查到的经纬度，与该顶点 UV 采样 heightmap 得到的高程」在地理上自洽——这是避免地形与省界/标签
错位的不变量。

## 7. 已接受的墨卡托特性（不修形）

| 特性 | 说明 | 处置 |
|---|---|---|
| 高纬放大 | 54°N 处墨卡托放大因子 ≈1.66，北方（黑龙江 / 内蒙古北部）视觉偏胖 | SPEC §3.3、§13 明确接受；**不**按纬度做形状修形、**不**切换阿尔伯斯投影、**不**做近似补偿 |
| 有效纬度上限 | ≈85.0511°N/S（y 趋向无穷） | 主图范围 [3°N, 54°N] 远离奇异点；越界输入显式失败 |
| 纬度非线性 | 地理中心 (104°E, 28.5°N) 不是墨卡托 Y 范围中点，世界 z 关于原点不对称（北侧 −Z 量级大于南侧 +Z） | 固有特性，正确反映「北方被放大」；`MAIN_MAP_WORLD_BOUNDS` 如实呈现不对称 |

> 与国标阿尔伯斯投影图对照时形状会不同（北方偏胖）——这是 SPEC 已确认接受的权衡，正式发布
> 以审图号为准（SPEC §8、§13）。
