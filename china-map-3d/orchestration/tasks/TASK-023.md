## 任务描述

### 可验证结果

完整地图在目标独显设备上以生产默认 2048² 网格运行时，1080p 和 4K 场景均达到持续 60fps 目标或给出不可伪造的阻塞证据；DPR、显存、draw call、逐帧分配和可选 4096² 档位均有明确预算与测量记录。

### 输入

- SPEC §2“运行平台/网格精度”、§7.1–§7.5、§12.9–§12.10、§13。
- TASK-009 的默认 2048² 与可选 4096² 网格配置。
- TASK-013、TASK-014、TASK-017、TASK-022 的统一帧循环、边界 draw call、遮挡降频和恢复生命周期。
- TASK-021 的完整可见页面。

### 输出

- 生产渲染 DPR 上限不超过 2，1080p/4K 尺寸切换不突破明确的渲染目标和显存预算。
- 记录目标设备 GPU、浏览器、分辨率、DPR、网格档位、稳定采样时长、fps 分布、显存可观测指标和关键 draw call。
- 默认 2048² 档完成 1080p 与 4K 持续帧率验收；4096² 仅作为显式可选档，在实测满足预算时才启用，不得自动升级。
- 对逐帧几何/纹理/大对象分配、重复材质、重复纹理、边界 draw call 和标签遮挡频率进行审计，必要优化纳入本 TASK。
- 保持高精资产单次离线加载、常驻复用，不引入运行时流式网络或自动低清 fallback。

### 实现约束

- 60fps 是目标独显设备上的人工性能验收项，不得用降低生产默认到 2048² 以下、隐藏必要地图要素或缩小渲染尺寸伪造通过。
- 若 4K 默认档无法达到目标，必须保留真实测量、明确选择降级/阻塞/优化决策，并将结论写入测量记录；不得以“能运行”替代完成。
- 性能调优必须尊重现有模块边界；不得为减少调用而把资产、领域、交互和渲染重新合成巨型组件。
- 禁止逐帧创建几何/纹理、大数组或新的 Clock；DPR 上限、网格档位和遮挡检查频率必须显式配置。
- 不自动启动浏览器；性能测量由用户在目标环境手动执行并记录。
- 新增或修改的代码必须用多行简体中文注释解释预算、缓存所有权、降频和测量边界；不得主动格式化无关代码。

### 验证方式

1. 执行 `pnpm test`，预期 DPR 上限、生产默认/上限网格档位、无自动升级和性能配置边界测试通过。
2. 执行 `pnpm lint` 与 `pnpm build`，预期最终生产构建通过。
3. 人工运行生产构建，在目标独显设备以 1080p、DPR 上限内、2048² 默认档持续采样，预期达到稳定 ≥60fps，并记录完整环境和分布数据。
4. 人工在同一设备以 4K、DPR 上限内、2048² 默认档持续采样，预期达到稳定 ≥60fps；同时旋转相机、经过密集标签区和南海区域，不能只测静止空闲帧。
5. 人工可选测试 4096² 档，预期不满足预算时保持为未启用可选档；检查内存、draw call 和长时间采样无持续增长。不得自动启动浏览器。

### 完成标准

- DPR 上限、网格档位、资源复用和逐帧分配不变量全部被自动化或审计验证。
- 目标设备上 1080p/4K 默认档达到 SPEC 的持续 ≥60fps，并保留可复核测量记录。
- 若 4K 默认档未达到 60fps，必须基于测量记录选择以下决策之一并记录：
  - 将 4K 场景显式标记为「可选档位/未达标」，默认仍保持 1080p 或 2048² 配置；
  - 在不对地图要素做隐藏或缩小渲染尺寸的前提下，启用已批准的优化（如进一步降低 DPR 上限、提高遮挡降频间隔、减少边界 draw call 分组）并重新测量；
  - 保持本 TASK 阻塞，直至目标硬件或渲染方案调整后再验收。
  不得以自动降低生产默认网格精度、隐藏必要地图要素或运行时网络低清 fallback 伪造通过。
- 构建、lint、测试和完整回归人工验收通过，TASK-001 至 TASK-022 的结果均未被性能优化破坏。
- 没有隐藏要素、降低默认精度、运行时网络、自动低清 fallback、重复资源或跨层耦合。
- 可以创建仅包含性能预算固化、必要优化和测量记录的最终 Git checkpoint；代码库处于完整、一致、可运行、可验证状态。

### 回退边界

回退本 TASK 只会移除最终性能预算配置、必要调优和测量记录；TASK-022 的完整功能与恢复能力仍保留，但重新处于性能目标未验收状态。
