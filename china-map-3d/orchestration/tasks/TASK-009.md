## 任务描述

### 可验证结果

默认脚手架页面被替换为独立大屏 3D 地图场景，生产 heightmap 在 GPU 顶点阶段驱动连续地形网格起伏；青藏高原、主要盆地和东部低地的相对高差可直接观察，垂直夸张系数可在 1.5–3.0 内配置。

### 输入

- SPEC §1、§2“形态本质/用途/垂直夸张/网格精度”、§3.2、§3.3、§7.1–§7.3、§12.1、§13。
- TASK-003 的生产高程资产。
- TASK-007 的米制世界坐标范围。
- TASK-008 的真实米制解码语义，供 CPU/GPU 一致性验证。
- 当前默认 Vite 页面，可在本 TASK 内进行支撑结果所需的架构重构。

### 输出

- 一个覆盖目标地理范围的连续地形网格，平面顶点与 UV 为基础，GPU vertex shader 采样真实 16 位高程并施加位移。
- 默认网格分段为 2048²，允许通过显式配置调整，上限 4096²；默认垂直夸张 `k=2.0`，合法范围 1.5–3.0。
- CPU 和 GPU 对相同 UV 的解码与高程语义一致，`y` 使用真实海拔乘夸张系数，不受后续颜色映射影响。
- 大屏页面具备清晰的场景装配边界，资产访问、领域计算、渲染和 DOM overlay 不能混成巨型组件。
- 在自动化/低资源环境可使用显式测试配置降低网格预算，但生产默认值不得被偷偷改低。

### 实现约束

- 绝对禁止在 JS/CPU 为高精网格逐顶点采样并写入 position；位移必须发生在 GPU shader。
- 必须保持 16 位端到端高程精度，不得因纹理载入链路静默退化为 8 位。
- 地形渲染层单向依赖资产、坐标和高程契约；不得自行读取 GeoJSON、维护 hover 或加载外网。
- 本 TASK 只要求可观察的真实起伏；完整分层设色、氛围、海面和边界由后续 TASK 交付，不得预埋重复实现。
- 不加入业务数据颜色、高度、tooltip、下钻或移动端响应逻辑。
- 新增或修改的代码必须用多行简体中文注释解释 GPU 位移、纹理精度、网格预算和配置边界；不得主动格式化无关代码。

### 验证方式

1. 执行 `pnpm test`，预期 CPU/GPU 共享的高程解码参数、夸张范围和网格配置边界测试通过，非法配置被拒绝。
2. 执行 `pnpm lint` 与 `pnpm build`，预期独立大屏场景可生产构建，且无 CPU 高精顶点生成路径。
3. 人工执行 `pnpm dev` 后自行打开页面，不得由自动化启动浏览器；预期可看到连续中国地形，青藏高原明显高于东部，主要盆地相对周边凹陷。
4. 人工切换 `k=1.5`、`2.0`、`3.0`，预期只改变垂直起伏，不改变平面位置或真实高程解码。
5. 检查生产默认配置，预期分段为 2048²；测试配置与生产配置边界清楚。

### 完成标准

- GPU 位移地形已可见且地势相对关系正确，配置不变量有自动化覆盖。
- 构建、lint、测试全部通过，前八个 TASK 的资产和领域行为无回归。
- 页面架构具备清晰的场景、领域和资产边界，没有巨型组件或跨层读取。
- 没有 CPU 顶点位移、8 位降级、临时平面 fallback 或旧模板业务残留。
- 人工视觉验收记录完成后，可以创建只包含 GPU 地形结果及必要重构的 Git checkpoint，代码库可安全进入 TASK-010。

### 回退边界

回退本 TASK 只会移除独立大屏场景和 GPU 地形呈现，恢复此前页面；资产、投影和 CPU 高程查询仍完整可用。
