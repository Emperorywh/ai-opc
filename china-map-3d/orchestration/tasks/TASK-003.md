## 任务描述

### 可验证结果

仓库内存在一套可离线加载、通过契约校验且具有真实中国地势特征的 4096×4096 高程资产；后续 GPU 地形和 CPU 高程查询无需访问外部网络即可消费同一高程语义。

### 输入

- SPEC §3.1–§3.3、§3.5、§5.1、§7.1–§7.3、§12.1、§13。
- TASK-001 的地形资产契约。
- TASK-002 的可重复 DEM 生成能力。
- 覆盖目标范围的 Copernicus DEM GLO-30 生产输入。

### 输出

- 4096×4096、16 位单通道高程资产及匹配的元数据，覆盖 72°E–136°E、3°N–54°N 和 EPSG:3857 目标坐标系。
- 高程编码严格使用 `minH=-1500`、`maxH=9000`，包含可验证的浅水负高程、东部低地、盆地和青藏高原高地样本。
- 资产来源、生成参数、生成时间或版本、完整性摘要可审计；不得提交来源不明的二进制文件。
- 提供资产级非交互校验命令 `pnpm verify:assets -- --scope terrain`，验证格式、位深、尺寸、元数据和地势抽样不变量。
- 必要文档说明如何依据 TASK-002 重建同一逻辑产物，而不要求在普通前端构建中重复下载或生成大资产。

### 实现约束

- CPU 与 GPU 后续可以采用不同载入表示，但必须由同一编码和同一元数据解码为真实米制海拔。
- 资产不得被浏览器或图像工具静默降为 8 位后仍宣称满足契约；校验必须能够发现精度丢失。
- 运行时零外网；生产源数据缓存和临时拼接结果不得作为产品资产提交。
- 地势真实性抽样只验证稳定的数量级与相对关系，不把某个插值像元硬编码为不可更新的魔法常量。
- 本 TASK 不实现 Three.js 地形、着色、海面或 UI。
- 新增或修改的验证代码必须用多行简体中文注释解释位深、米制解码和地势抽样依据；不得主动格式化无关代码。

### 验证方式

1. 执行 `pnpm verify:assets -- --scope terrain`，预期位深、尺寸、地理范围、CRS、编码上下限和来源信息全部通过。
2. 执行 `pnpm test`，预期解码端到端测试证明编码最小值、海平面、典型正高程和最大值可还原到允许误差内。
3. 正常路径抽样应证明青藏高原整体高于东部平原，塔里木或四川盆地相对周边山地更低，海域包含负高程。
4. 在测试副本中篡改元数据范围、位深或分辨率，预期资产校验失败；不得改动正式资产验证异常路径。
5. 执行 `pnpm lint` 与 `pnpm build`，预期大资产不会导致类型检查或打包失败。

### 完成标准

- 生产高程资产、元数据和来源记录均已交付并通过资产校验。
- 自动化证明 16 位精度和真实米制解码未丢失，关键地势相对关系成立。
- 所有仓库级验证通过，TASK-001 与 TASK-002 的行为无回归。
- 没有下载缓存、半成品、外网依赖或替代平面 fallback。
- 可以创建只包含生产高程资产、资产校验扩展和必要文档的 Git checkpoint，代码库可安全进入 TASK-004。

### 回退边界

回退本 TASK 只会移除生产高程资产及其生产级校验；TASK-001 的契约和 TASK-002 的生成流水线仍可运行，并可用于重新生成资产。
