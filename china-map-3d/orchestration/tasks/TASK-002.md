## 任务描述

### 可验证结果

给定覆盖目标范围的 Copernicus DEM GLO-30 输入或等价测试夹具，仓库能够通过非交互流程确定性生成符合运行时契约的 16 位高程图和元数据，并能拒绝缺瓦片、范围错误或编码错误的输入。

### 输入

- SPEC §3.3、§3.5、§5.1、§7.1、§7.2、§10、§13。
- TASK-001 交付的地形资产契约、验证入口和依赖边界。
- Copernicus DEM GLO-30 公开数据；验证流程使用可纳入仓库的小型确定性夹具，不要求每次测试下载完整生产数据。

### 输出

- 一条可记录输入来源并执行下载或读取本地缓存、拼接、裁剪、EPSG:3857 重投影、双线性重采样、16 位编码和元数据导出的离线流水线。
- 生产参数支持经度 72°E–136°E、纬度 3°N–54°N、4096×4096 输出，以及 `[-1500m, 9000m]` 到 `0–65535` 的编码；低于 -1500m 的值被截断，浅水负高程被保留。
- 元数据明确记录范围、坐标参考系、分辨率、高程上下限、编码和可追溯来源。
- Windows 脚本环境依赖说明，以及无法安装脚本依赖时可人工执行的 QGIS 等价参数清单；两条路径必须产生同一外部契约。
- 自动化测试以小型 DEM 夹具证明重投影、重采样、截断、负高程保留和元数据一致性。

### 实现约束

- 本 TASK 交付的是可重复生产能力，不要求把完整生产 heightmap 作为本 checkpoint 的完成条件；生产资产由 TASK-003 交付。
- 流水线属于离线资产生产层，不得依赖浏览器、React、Three.js 或运行时状态。
- 不得以 8 位图替代 16 位高程精度，也不得把所有负高程钳制为 0。
- 输入不完整或输出与契约不一致时必须失败，不得用默认平面、旧资产或远程运行时请求兜底。
- 具体脚本语言组织、内部函数和依赖封装由 Coding Agent 检查实际代码后决定；已确认的 Python 3、rasterio、numpy 技术约束可以直接使用。
- 新增或修改的代码必须用多行简体中文注释解释投影、采样、编码和截断不变量；不得主动格式化无关代码。

### 验证方式

1. 执行 `pnpm test`，预期小型合法 DEM 夹具可生成可解码的 16 位结果，像元值与期望高程在重采样容差内一致。
2. 自动化验证一个含正高程、浅水负高程和低于 -1500m 值的夹具，预期分别保真、保留和正确截断。
3. 自动化提供缺失覆盖范围、错误 CRS 或损坏栅格输入，预期流水线明确失败且不留下看似有效的半成品。
4. 执行 `pnpm lint` 与 `pnpm build`，预期前端构建不依赖脚本环境，现有行为不回归。

### 完成标准

- 从 DEM 输入到地形资产契约的完整离线数据流已可重复执行并被自动化测试覆盖。
- 正常路径、负高程、边界截断和关键损坏输入均有确定性结果。
- `pnpm test`、`pnpm lint`、`pnpm build` 全部通过。
- 没有提交下载缓存、临时中间文件、重复编码逻辑或运行时网络 fallback。
- 可以创建仅包含 DEM 生产能力、测试夹具和必要文档的 Git checkpoint，代码库可安全进入 TASK-003。

### 回退边界

回退本 TASK 只会移除 DEM 生成能力及其测试，不会移除 TASK-001 的资产契约和验证基线，也不会影响脚手架的运行与构建。
