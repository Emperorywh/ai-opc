title: 提供共享的运行时高程查询能力
---

## 任务描述

### 可验证结果

运行时能够只解码一次 16 位高程资产，并以真实米制海拔对任意合法 UV 或世界平面位置进行双线性查询；省界贴地、标签定位、遮挡判断和海陆判断可以共享同一高程事实源。

### 输入

- SPEC §3.1、§3.5、§3.6、§7.1、§7.5、§13。
- TASK-001 的地形契约。
- TASK-003 的生产高程资产和元数据。
- TASK-007 的统一世界坐标与 UV 约定。

### 输出

- 16 位高程数据的运行时解码和只读查询能力，按元数据还原真实米制海拔并执行双线性采样。
- CPU 查询表示只建立一份并由多个领域消费者共享；GPU 后续纹理可以是另一表示，但二者解码语义必须一致。
- 查询结果能明确区分合法负高程、海平面、正高程和范围外位置，不以魔法 0 混淆异常与海平面。
- 生命周期明确：加载成功后可复用，失败时给出可定位错误，释放时不会遗留大数组引用。
- 自动化测试覆盖像元中心、四角插值、边界、负高程、元数据不匹配和精度丢失。

### 实现约束

- 禁止为 4096² 网格在 CPU 逐顶点写入位移或法线；本能力只负责共享高程查询。
- 高程查询层可以依赖资产与坐标领域层，不得依赖 React 组件、场景对象、标签或省界渲染。
- 4096²×2B 的核心高程数据应保持约 32MB 数量级，不得无意转换为多个高开销 JS 数组副本。
- 不得用 8 位浏览器图像解码结果冒充 16 位数据，不得在查询失败时返回平地 fallback。
- 具体解码方式、缓存容器和错误类型由 Coding Agent 检查实际平台后决定。
- 新增或修改的代码必须用多行简体中文注释解释 16 位解码、双线性采样、共享生命周期和异常语义；不得主动格式化无关代码。

### 验证方式

1. 执行 `pnpm test`，预期已知 2×2 或小型高程夹具在像元中心、边界和中心插值处得到可计算的真实米制结果。
2. 对生产资产抽样，预期 CPU 查询值与 TASK-003 的资产验证值在编码误差内一致，浅水点保持负值。
3. 重复创建多个消费者，预期底层 16 位数据只解码一次；释放后不再持有重复缓存。
4. 使用损坏位深、错配元数据、范围外坐标和非有限输入，预期显式失败或无值结果符合契约，不返回伪造海拔。
5. 执行 `pnpm lint` 与 `pnpm build`，预期无回归。

### 完成标准

- 共享 CPU 高程查询可稳定提供真实米制双线性采样，并覆盖关键异常路径。
- 内存表示和生命周期符合单份共享约束，未产生 CPU 顶点位移逻辑。
- 所有验证命令通过，TASK-001 至 TASK-007 的结果无回归。
- 没有重复解码、隐式全局状态、8 位降级或平地 fallback。
- 可以创建仅包含运行时高程查询、测试和必要文档的 Git checkpoint，代码库可安全进入 TASK-009。

### 回退边界

回退本 TASK 只会移除运行时高程查询能力；统一投影与所有静态资产仍可独立验证，不会受到破坏。
