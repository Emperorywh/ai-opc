## 任务描述

### 可验证结果

页面默认以东南方向斜俯视完整中国地形，用户可以旋转、俯仰、缩放和平移查看地图，但无法看到地底、无限拉近拉远或把观察目标拖出地图有效范围。

### 输入

- SPEC §2“相机/默认视角”、§4.1、§12.6。
- TASK-007 的地图米制包围盒与中心。
- TASK-009 至 TASK-010 的可见地形。
- 已确认使用 `@react-three/drei` 提供 OrbitControls 能力。

### 输出

- 东南上方斜俯视默认相机状态，观察目标指向地图中心，画面体现西高东低。
- 旋转、俯仰、缩放和平移能力，以及由地图包围盒和地形尺度推导的最小/最大距离、最大极角和 target 约束。
- 不允许相机翻到地图背面、观察地底、无限飞远或将 target 拖出版图。
- 相机约束为显式状态/纯计算契约，后续加载状态可以统一启停交互，而不是从 DOM 或组件内部猜测。
- 自动化测试覆盖默认机位、距离钳制、极角钳制、平移边界和 resize 后约束仍成立。

### 实现约束

- 相机约束必须从地图包围盒、中心和明确配置推导，不得散落魔法坐标或逐帧临时修正。
- 相机/控制层可以依赖场景尺寸与交互状态，不得读取行政区业务数据或修改地形资产。
- 禁止 click 下钻、飞焦、业务 tooltip 或省级导航；本系统只有自由受限探索和后续 hover。
- `screenSpacePanning` 必须按 SPEC 禁用或以可证明不会造成方向错乱的方式配置。
- 具体相机参数数值可由 Coding Agent 在实际场景中调试，但必须通过约束不变量和人工验收冻结结果。
- 新增或修改的代码必须用多行简体中文注释解释默认视角、边界推导和交互启停契约；不得主动格式化无关代码。

### 验证方式

1. 执行 `pnpm test`，预期默认机位位于地图东南上方，target 位于地图有效范围，距离与极角合法。
2. 自动化向约束逻辑输入超界 target、过近/过远距离和超过最大极角的状态，预期被确定性限制到合法范围。
3. 执行 `pnpm lint` 与 `pnpm build`，预期控制器依赖和类型检查通过。
4. 人工执行 `pnpm dev` 后自行打开页面；预期初始画面完整、青藏高原在左上方向隆起、东部低地在右下方向，四类相机操作可用。
5. 人工尝试翻面、穿地、无限缩放和平移出地图，预期全部被阻止；不得自动启动浏览器。

### 完成标准

- 默认视角和全部控制边界已实现并通过自动化与人工验收。
- 相机状态可被后续入场状态机统一启停，没有隐式组件状态。
- 构建、lint、测试通过，此前地形和色阶行为无回归。
- 没有魔法修正、click 行为、跨层数据读取或相机约束重复实现。
- 可以创建只包含受约束相机探索结果的 Git checkpoint，代码库可安全进入 TASK-012。

### 回退边界

回退本 TASK 只会移除默认相机编排和 OrbitControls 约束；地形仍可由基础场景相机显示，所有资产与着色能力保持不变。
