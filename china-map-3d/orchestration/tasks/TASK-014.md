---

## 任务描述

### 可验证结果

34 个省级行政区边界以浅青白发光线完整呈现，并沿真实地形连续起伏；跨山脊、盆地、岛屿和多多边形边界时不明显穿山、悬空或产生 z-fighting。

### 输入

- SPEC §3.6、§5.2、§7.2、§12.4。
- TASK-004 的 34 省边界资产。
- TASK-007 的统一投影。
- TASK-008 的共享双线性高程查询。
- TASK-009 至 TASK-013 的可见地形和海面。
- 已确认使用 drei Line/等价 Line2 能力支持屏幕线宽与发光混合。

### 输出

- 对省界折线沿弧长做确定性 densify，采样间距接近地形纹理分辨率（约 1–2km 或等价 `plane 宽/4096`），再统一投影并查询地表 y。
- 所有边界点使用真实地形高度乘同一夸张系数并加最小可解释 epsilon，避免穿山、悬空和 z-fighting。
- 34 个行政区边界完整渲染，支持多多边形、岛屿和内环；线条为浅青白、轻发光且 draw call 保持单个或少量可审计分组。
- densify、高程贴地和渲染数据准备属于领域/适配层，视图层只消费准备好的线数据。
- 自动化测试覆盖长线段重采样、跨纹理边界、负高程、闭环、多多边形和 epsilon 不变量，以及与 TASK-013 海面共存时的透明排序与 z-fighting 边界。

### 实现约束

- 必须先 densify 再对每个点采样高程，禁止只抬升 DataV 稀疏原始顶点后用直线跨越地形。
- 省界准备层单向依赖行政区、投影和高程查询，不得依赖 React hover 状态；hover 由 TASK-018 交付。
- 不得复制 heightmap 解码或投影公式，不得为个别省份在组件中写魔法高度修补。
- draw call 优化不能破坏按行政区寻址的能力，后续 hover 仍须能确定性更新单一省份样式。
- 不在本 TASK 混入十段线、岛礁点、标签或点击行为。
- 新增或修改的代码必须用多行简体中文注释解释 densify 间距、高程采样、epsilon 和分组权衡；不得主动格式化无关代码。

### 验证方式

1. 执行 `pnpm test`，预期稀疏长线段被按配置间距补点，各点 y 与共享高程查询及夸张系数一致。
2. 自动化验证多多边形、闭环和岛屿边界均保留；无效几何或高程查询失败时整条资产准备明确失败，不产生平地边界。
3. 执行 `pnpm lint` 与 `pnpm build`，预期线渲染依赖与类型检查通过。
4. 人工执行 `pnpm dev` 后自行打开页面，重点观察青藏高原、横断山区、四川盆地和岛屿；预期省界紧贴地形且无明显穿山、悬空、闪烁。
5. 在海面已启用场景下观察省界与海面交接处，预期无透明排序错乱、线条闪烁或被海面完全吞没；不得自动启动浏览器。

### 完成标准

- 34 省贴地边界完整可见，关键复杂地形人工验收通过。
- densify、采样和复杂几何异常路径有自动化覆盖。
- 构建、lint、测试通过，此前地图行为无回归。
- 没有稀疏直线跨山、重复高程/投影逻辑、个省魔法修补或不可审计 draw call 膨胀。
- 可以创建只包含省级贴地边界结果的 Git checkpoint，代码库可安全进入 TASK-015。

### 回退边界

回退本 TASK 只会移除省级边界数据准备和渲染；地形、海面及全部静态行政区资产仍保持有效。
