title: 实现大屏长时运行恢复闭环
---

## 任务描述

### 可验证结果

页面面对 WebGL context 丢失、context 恢复和连续 resize 时具有显式、可恢复的生命周期：丢失时停止推进渲染状态，恢复后重建必要 GPU 资源并回到一致画面，resize 不产生更新风暴或尺寸错乱。

### 输入

- SPEC §7.3–§7.5、§12.10、§13。
- TASK-008 的大体积 CPU 高程资源生命周期。
- TASK-009 至 TASK-021 的完整场景、统一帧循环、加载状态和 DOM overlay。

### 输出

- 显式的运行中、context 丢失、恢复中、恢复成功和恢复失败状态及转换规则。
- context 丢失时阻止默认不可恢复行为并暂停会推进视觉状态的渲染更新；恢复时重建 GPU 纹理、材质和必要场景资源，同时复用仍有效的领域/CPU 资产。
- 恢复失败时显示可诊断状态，不进入空白死循环，也不自动请求外部资源或回退旧实现。
- resize 事件经过防抖后更新渲染器、相机和 overlay 所需尺寸，最终尺寸必须等于最后一次输入。
- 统一帧循环继续承载水面、入场和遮挡检查；挂载/卸载、丢失/恢复期间不存在重复监听器、重复 Clock 或运行时几何分配循环。

### 实现约束

- 生命周期状态必须集中编排，场景层和 UI 只消费状态；禁止每个组件各自监听 context 或 resize。
- GPU 资源恢复与 CPU 领域数据生命周期分离，不得因 context 丢失重复解码 32MB 高程数组或重复下载资产。
- resize 防抖不得吞掉最终尺寸，不得依赖浏览器自动刷新解决错乱。
- 恢复失败必须显式暴露，不提供低清、平面、旧资产或远程 fallback。
- 本 TASK 只处理可恢复生命周期，不以主观“运行一会没崩”替代 TASK-023 的性能验证。
- 新增或修改的代码必须用多行简体中文注释解释 context 状态迁移、资源所有权、resize 防抖和监听器清理；不得主动格式化无关代码。

### 验证方式

1. 执行 `pnpm test`，模拟 `running→lost→restoring→running` 和 `running→lost→restoring→failed`，预期状态、暂停、恢复和诊断一致。
2. 自动化连续发送多次 resize，预期只按防抖策略执行有限更新，最终使用最后尺寸；卸载后事件不再生效。
3. 自动化重复 context 丢失/恢复，预期监听器、Clock、CPU 高程缓存和 GPU 资源所有权数量稳定。
4. 执行 `pnpm lint` 与 `pnpm build`，预期完整页面通过。
5. 人工执行 `pnpm dev` 后自行打开页面，使用开发者工具手动触发 context lost/restore 和连续窗口尺寸变化；预期画面可恢复、交互可继续、overlay 尺寸正确。不得自动启动浏览器。

### 完成标准

- context 丢失/恢复/失败和 resize 形成明确、可测试的生命周期闭环。
- 重复事件与卸载路径证明无重复监听、CPU 大资产重复解码或多时钟。
- 构建、lint、测试和人工恢复验收通过，完整地图行为无回归。
- 没有隐式生命周期、刷新兜底、远程 fallback、重复资源所有权或事件泄漏。
- 可以创建只包含长时运行恢复能力及必要生命周期重构的 Git checkpoint，代码库可安全进入 TASK-023。

### 回退边界

回退本 TASK 只会移除 context 恢复、集中 resize 防抖和相关生命周期状态；TASK-021 的完整页面在正常 context 下仍可运行，但重新不满足 24h 大屏稳定性要求。
