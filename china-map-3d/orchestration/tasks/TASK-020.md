title: 编排确定性的加载与入场状态
---

## 任务描述

### 可验证结果

首次进入页面时，用户依次看到静态资产加载进度、地形从平面升起、省名标签错峰淡入、水面和边界随后淡入；动画期间相机交互锁定，全部完成后一次性进入可交互状态，加载失败不会永久卡在假进度。

### 输入

- SPEC §2“加载入场”、§4.3、§7.1、§7.4、§12.8。
- TASK-009 的 GPU 地形和可驱动位移比例。
- TASK-011 的可统一启停相机控制。
- TASK-013 至 TASK-019 的水面、边界、标签、政治要素和附图。
- 已确认可使用 drei Suspense/useProgress 或等价 R3F 资产进度能力。

### 输出

- 显式加载/入场状态模型，至少区分加载中、加载失败、地形升起、标签淡入、边界/水面淡入和可交互状态。
- DOM 加载进度反馈只反映真实受跟踪资产，不伪造计时进度；失败时显示可诊断信息并保持交互关闭。
- 地形通过 shader uniform 或等价 GPU 状态在约 1.2 秒内从平面升至最终夸张高度，不创建第二套几何。
- 省名标签按确定的地理顺序错峰淡入，水面和边界随后淡入；相同阶段输入由各渲染层消费，不由组件私自计时。
- 状态到达可交互后释放 OrbitControls；重复渲染、StrictMode 和资源完成顺序变化不会导致动画多次启动或提前解锁。

### 实现约束

- 入场必须由单一显式状态流编排，禁止在地形、标签、海面和边界组件中各建独立定时器或布尔状态。
- 所有动画使用统一 R3F 帧循环/时钟，禁止多 Clock 漂移和逐帧对象分配。
- 地形升起必须复用 GPU 位移，不得复制或重建 2048² 几何。
- 加载失败必须显式终止状态机并保留诊断，不得自动回退到低清、平面、旧资产或远程请求。
- 2D 附图和合规 UI 的加载不能造成主场景已经可交互却仍覆盖假进度的竞态。
- 新增或修改的代码必须用多行简体中文注释解释状态迁移、交互锁和统一时间源；不得主动格式化无关代码。

### 验证方式

1. 执行 `pnpm test`，驱动 `loading→terrain-rise→labels→scene-layers→interactive`，预期阶段顺序固定、每阶段只进入一次、交互只在最终状态启用。
2. 自动化模拟资产乱序完成、StrictMode 重挂载和加载失败，预期无重复动画、提前解锁、永远 99% 或失败后继续渲染。
3. 执行 `pnpm lint` 与 `pnpm build`，预期状态机和全部层集成通过。
4. 人工执行 `pnpm dev` 后自行打开页面；预期真实进度条、约 1.2 秒地形升起、标签错峰淡入、水面/边界随后淡入，过程顺滑。
5. 人工在动画期间操作相机，预期无响应；完成后四类相机操作恢复。通过测试配置模拟资产失败，预期出现明确错误而非 fallback；不得自动启动浏览器。

### 完成标准

- 加载、入场、失败和交互解锁形成确定性状态闭环。
- 自动化覆盖顺序、乱序完成、StrictMode、失败和交互锁。
- 构建、lint、测试和人工验收通过，所有已完成视觉层与 hover 无回归。
- 没有分散计时器、重复几何、假进度、隐式布尔组合或失败 fallback。
- 可以创建只包含加载/入场编排及必要状态重构的 Git checkpoint，代码库可安全进入 TASK-021。

### 回退边界

回退本 TASK 只会移除进度、入场动画和交互锁编排；地图各层恢复为加载完成后直接可见、相机直接可用的 TASK-019 状态。
