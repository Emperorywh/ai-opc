## 任务描述

### 可验证结果

34 个省级行政区都能通过稳定标识关联到一个省名展示锚点和一个省会、首府、直辖市中心或特别行政区中心点位，坐标可离线验证并可供后续 3D 标签与省会光点直接消费。

### 输入

- SPEC §3.3、§3.7、§5.5、§6、§12.4、§13。
- TASK-001 的地点目录契约。
- TASK-004 的 34 个省级行政区稳定标识和边界几何。

### 输出

- 与 34 个行政区一一对应的省名、展示锚点和省级行政中心目录，包含经纬度、规范名称和稳定行政区关联。
- 台湾省关联台北点位，港澳和四个直辖市均按省级行政区目录完整表达。
- 锚点位于对应行政区的可解释位置；对多岛、狭长或几何中心落海的行政区允许有可审计的人工校正，但不得用组件内魔法偏移承载。
- 提供 `pnpm verify:assets -- --scope places`，验证 34 项一一对应、坐标范围、名称完整性和所属行政区关系。
- 数据来源和人工校正依据可审计，后续字体子集可以从最终字符串集合确定性派生。

### 实现约束

- 地点目录属于地理领域数据，不得放进 React 组件、材质参数或 hover 状态中维护。
- 每个行政区必须恰有一个默认省名锚点和一个省级行政中心；缺失、重复或关联到其他行政区必须失败。
- 默认展示契约只要求“省名 + 省会光点”；省会名称以小字或非业务 tooltip 呈现可由后续 Coding Agent依据拥挤情况决定，不得引入业务 tooltip。
- 不做实时标签碰撞布局，不引入移动端专用坐标，也不兼容旧点位数据。
- 新增或修改的代码必须用多行简体中文注释解释人工锚点、行政区关联和坐标不变量；不得主动格式化无关代码。

### 验证方式

1. 执行 `pnpm verify:assets -- --scope places`，预期 34 个行政区均恰好匹配一个锚点和一个省级行政中心。
2. 执行 `pnpm test`，预期点位落入对应行政区或具有显式校正说明；台湾、港澳、直辖市和多岛行政区用例通过。
3. 在测试副本中制造缺失省会、重复关联、越界经纬度和未知行政区标识，预期验证失败并定位到具体条目。
4. 执行 `pnpm lint` 与 `pnpm build`，预期此前资产能力和默认页面构建无回归。

### 完成标准

- 34 个省名锚点和省级行政中心点位完整、唯一、可追溯。
- 正常路径与缺失、重复、越界、错误关联异常路径均有自动化覆盖。
- 所有验证命令通过，TASK-001 至 TASK-004 的行为未被破坏。
- 没有在视图层复制点位、用数组索引关联或遗留未解释的坐标偏移。
- 可以创建仅包含地点目录及其验证的 Git checkpoint，代码库可安全进入 TASK-006。

### 回退边界

回退本 TASK 只会移除省名锚点、省级行政中心目录及其校验；省级边界和地形资产仍保持有效。
