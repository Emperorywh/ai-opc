id: TASK-017
title: 保持标签与地形遮挡关系可信
---

## 任务描述

### 可验证结果

当省名或岛礁标签被前方山脉遮挡时，其透明度会降低以避免穿透地形的违和感；相机转动使遮挡消失后，标签会稳定恢复，且 34 个以上标签的检查不会造成明显逐帧抖动或分配压力。

### 输入

- SPEC §3.7、§7.4、§7.5、§12.4。
- TASK-008 的共享高程/地形查询语义。
- TASK-011 的相机状态。
- TASK-016 的标签集合与锚点。

### 输出

- 对每个需要遮挡判断的标签，从标签到相机执行地形可见性判断；命中点比标签更近时进入遮挡状态，否则进入可见状态。
- 遮挡状态只驱动标签透明度，不改变地点数据、锚点或相机；状态恢复无残留。
- 可按固定帧间隔或等价策略降频，但结果必须在交互中及时、稳定，且不为每次检查重复创建大对象。
- 遮挡判断能力与标签渲染解耦，可用确定性几何夹具测试正常、遮挡、擦边和相机移动场景。
- 字体加载未完成、地形不可用或标签已卸载时有明确生命周期处理，不产生错误射线或僵尸更新。

### 实现约束

- Billboard 面向相机与地形遮挡是两个独立概念，不得通过关闭深度测试让标签永久穿透地形。
- 遮挡判定层可依赖相机、地形查询和标签位置，不得修改资产数据、hover 状态或 UI overlay。
- 降频必须由统一帧循环驱动，不建立新的计时器/Clock，也不得用随机抽样造成闪烁。
- 透明度降低幅度和过渡可由 Coding Agent调试，但可见/遮挡状态必须确定且可恢复。
- 不在本 TASK 实现实时标签碰撞或相互推开。
- 新增或修改的代码必须用多行简体中文注释解释射线方向、距离比较、降频和生命周期；不得主动格式化无关代码。

### 验证方式

1. 执行 `pnpm test`，对无遮挡、前方山体遮挡、命中点位于标签之后、射线擦边和相机移动夹具，预期状态转换正确。
2. 自动化重复挂载/卸载标签与地形查询，预期没有卸载后更新、重复订阅或共享对象泄漏。
3. 执行 `pnpm lint` 与 `pnpm build`，预期无回归。
4. 人工执行 `pnpm dev` 后自行打开页面，在青藏高原等高差明显区域旋转相机；预期被山体挡住的标签淡化，移开后恢复，无明显闪烁。
5. 人工观察持续旋转时的帧率与标签稳定性，预期遮挡检查无明显卡顿；不得自动启动浏览器。

### 完成标准

- 标签遮挡和恢复形成完整、可测试的状态闭环。
- 生命周期、降频和无分配约束得到自动化或代码级验证。
- 构建、lint、测试和人工验收通过，标签朝向及地点位置无回归。
- 没有关闭深度测试的穿透方案、独立时钟、随机判断或隐式全局状态。
- 可以创建只包含标签遮挡结果的 Git checkpoint，代码库可安全进入 TASK-018。

### 回退边界

回退本 TASK 只会移除标签遮挡判定和透明度反馈；TASK-016 的标签仍面向相机并保持原有默认可见状态。
