## 任务描述

### 可验证结果

仓库具备一套明确、可自动验证的静态地理资产契约：后续生成的地形、行政区、地点与政治边界补充数据能够在进入运行时前被一致校验，非法或互相矛盾的数据会以确定性错误被拒绝。

### 输入

- SPEC §3.1、§3.3、§5、§6、§8、§10、§13。
- 当前代码库仅有 Vite + React + R3F 默认脚手架，已有构建和 lint 命令，尚无领域模块、资产契约或自动化测试入口。
- 仓库全局约束：全新系统，不兼容旧数据；运行时零外部网络依赖；实现须保持高内聚、低耦合和单向依赖。

### 输出

- 定义地形元数据、行政区目录、经纬度几何、地点目录、政治边界补充数据及数据来源声明的外部契约。
- 契约能够表达坐标参考系、地理范围、分辨率、高程编码上下限、稳定行政区标识、名称、几何类型、数据版本与来源。
- 提供非交互自动化验证入口；后续 TASK 可以复用同一入口验证正常资产和损坏资产。
- 建立最小测试基线，使 `pnpm test`、`pnpm lint`、`pnpm build` 都可独立执行。
- 补充必要的开发文档，说明离线生产数据流、运行时消费数据流及契约错误的定位方式。

### 实现约束

- 构建期资产生产层不得依赖 React、Three.js 或渲染层；运行时数据访问层可以依赖契约，但契约层不得反向依赖渲染层。
- 所有外部数据必须先转为仓库内静态资产，运行时禁止请求 DataV、AWS 或其他第三方服务。
- 契约只服务静态地理资产，不引入业务指标、实时数据对接、业务 tooltip 或下钻语义。
- 坐标、高程、行政区标识及数据来源必须显式表达，不得用数组位置、文件名推断或魔法默认值承载领域语义。
- 契约只冻结输入输出和不变量，不冻结具体校验库、测试框架、文件布局、类型名或实现模式。
- 不引入 legacy、fallback、deprecated 或双轨契约。
- 新增或修改的代码必须用多行简体中文注释解释领域不变量、依赖方向和非显然决策；不得主动格式化无关代码。

### 验证方式

1. 执行 `pnpm test`，预期代表性合法夹具全部通过。
2. 在自动化测试中分别提供缺失坐标系、非法经纬度、重复行政区标识、错误高程范围和未知数据版本，预期验证器给出可定位的确定性失败，而不是静默修正。
3. 执行 `pnpm lint`，预期无错误。
4. 执行 `pnpm build`，预期默认页面仍可构建，且测试/脚本依赖未进入不必要的浏览器运行时包。

### 完成标准

- 资产契约覆盖后续 TASK 所需的全部数据类别，并存在正常与关键异常路径测试。
- 三个仓库级验证命令均通过，当前默认页面行为未被破坏。
- 依赖方向清晰，没有把资产校验、渲染和 UI 状态混入同一模块。
- 没有临时逻辑、重复契约、隐式默认值或兼容旧数据的分支。
- 可以创建只包含本 TASK 契约、测试基线和必要文档的 Git checkpoint，代码库可安全进入 TASK-002。

### 回退边界

回退本 TASK 的 Git checkpoint 只会移除资产契约与自动化验证基线，仓库恢复为原始可构建脚手架；不涉及任何业务资产或可见地图能力。
