## 任务描述

### 可验证结果

所有行政区边界、地点、政治边界补充数据和南海附图坐标都能通过同一投影领域能力，从 WGS84 经纬度确定性转换到 EPSG:3857 及以地图中心为基准的米制世界坐标，避免各渲染层出现位置漂移。

### 输入

- SPEC §3.2、§3.3、§3.6、§3.8、§4.2、§5.4、§13。
- TASK-001 的坐标与范围契约。
- TASK-003 的高程元数据范围。
- TASK-004 至 TASK-006 的全部经纬度资产。
- 已确认依赖 `d3-geo` 负责 `geoMercator` 投影。

### 输出

- 单一投影能力处理经纬度到墨卡托米制平面、主图中心化世界 `(x,z)`、必要的反向查询，以及 2D 附图子范围映射。
- 明确世界坐标约定：`x/z` 表示平面米制位置，`y` 专用于米制高程及垂直夸张；地图中心、轴方向和 UV 方向有唯一契约。
- 边界、地点、附图和 hover 反查只能依赖该能力，不得各自重复投影公式。
- 自动化测试覆盖目标范围四角、中心、已知城市点、正反变换容差、轴方向和越界输入。
- 必要文档说明墨卡托高纬放大是已接受特性，不在实现中偷偷加入纬度修形。

### 实现约束

- 投影领域层不得依赖 React、R3F、Three.js 场景对象或 UI 状态；渲染和交互层单向依赖它。
- 所有消费者必须使用同一范围 72°E–136°E、3°N–54°N 和同一中心/轴向约定。
- 不引入另一套阿尔伯斯投影、手写墨卡托近似或按图层微调坐标的魔法逻辑。
- 对越界、不可投影或非有限坐标必须显式返回失败，不得静默映射到世界原点。
- 具体 API、模块位置和缓存方式由 Coding Agent 根据实际代码决定。
- 新增或修改的代码必须用多行简体中文注释解释坐标系、轴向、单位和反向查询不变量；不得主动格式化无关代码。

### 验证方式

1. 执行 `pnpm test`，预期目标范围四角和中心投影到稳定的米制包围盒，中心接近世界原点，轴方向与地图方位一致。
2. 对省会和岛礁代表点执行经纬度→世界→经纬度往返，预期误差在测试声明的数值容差内。
3. 对主图与附图投影同一南海点位，预期二者来自同一墨卡托结果，仅视口映射不同。
4. 输入 NaN、非法纬度或契约范围外坐标，预期得到显式失败，不出现原点标记。
5. 执行 `pnpm lint` 与 `pnpm build`，预期依赖安装和类型检查通过。

### 完成标准

- 统一投影覆盖主图、附图和反查需求，所有测试证明单位、轴向和范围一致。
- 已确认的墨卡托特性被记录，没有引入未经 SPEC 确认的投影修形。
- 所有仓库级验证通过，前六个 TASK 的资产验证无回归。
- 没有重复投影公式、视图层坐标修补或跨层依赖。
- 可以创建仅包含统一投影/坐标能力、测试和必要文档的 Git checkpoint，代码库可安全进入 TASK-008。

### 回退边界

回退本 TASK 只会移除统一投影和世界坐标转换；所有已完成静态资产仍保留原始经纬度和元数据，可在重新实现投影后继续使用。
