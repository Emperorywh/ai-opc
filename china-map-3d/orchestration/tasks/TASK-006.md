## 任务描述

### 可验证结果

基础省界与项目补充数据共同形成一套可审查、可自动做完整性检查的中国地图政治边界资产，明确覆盖十段线画法、南海诸岛、台湾及附属岛屿、藏南、阿克赛钦和港澳；任何红线要素缺失都会阻断后续 TASK。

### 输入

- SPEC §2“政治边界”、§3.8、§5.2–§5.4、§6、§8、§12.3、§13。
- TASK-001 的政治边界补充数据与来源契约。
- TASK-004 的 34 个省级行政区基础边界。
- TASK-005 的行政区关联和地点目录。
- 公开标准地图及其可追溯衍生数据作为人工核对基准；正式发布仍以自然资源主管部门审图结果为准。

### 输出

- 九段线含台湾东侧一段的标准十段画法经纬度线段数据。
- 南海主要岛礁、钓鱼岛、赤尾屿等点位与规范名称数据。
- 藏南、阿克赛钦及其他 SPEC 点名区域按中国主张表达所需的边界修正或补充数据。
- 一份机器可检的政治边界完整性清单和一份人工核对记录，逐项对应 SPEC §6 红线，并记录来源、版本、非官方审图属性和待审图状态。
- 3D 主图与 2D 南海附图后续复用同一补充数据，不维护两套坐标。
- 提供 `pnpm verify:assets -- --scope political`，能够发现缺段、缺点、缺名称、未知关联和来源缺失。

### 实现约束

- 不得自行凭视觉猜测或复制来源不明坐标；若无法获得可追溯核对基准，本 TASK 必须保持阻塞。
- 本 TASK 的阻塞范围仅限于直接消费政治边界补充数据的渲染 TASK：TASK-015（主图十段线/岛礁点位）、TASK-019（南海 2D 附图）以及最终的发布/部署流程。不阻塞通用领域能力 TASK-007（统一投影）、TASK-008（运行时高程查询）、TASK-009（GPU 地形）等基础能力建设，这些 TASK 可在政治数据未最终核对时并行推进。
- 自动化完整性检查不能替代人工地图核对，人工核对也不能替代正式审图；两者的边界必须在交付记录中明确。
- 补充或修正数据必须保持原始来源与变换可追溯，不得悄悄改写为“DataV 官方数据”。
- 运行时禁止外网请求；主图与附图必须通过领域数据层共享同一事实源。
- 不在本 TASK 实现渲染、标签、附图 UI 或审图号界面。
- 新增或修改的代码必须用多行简体中文注释解释红线完整性、数据来源边界和无法自动证明的事项；不得主动格式化无关代码。

### 验证方式

1. 执行 `pnpm verify:assets -- --scope political`，预期十个线段、必需岛礁/附属岛屿、争议区修正、名称和来源记录全部通过。
2. 执行 `pnpm test`，在测试副本中分别删除台湾东侧线段、钓鱼岛、赤尾屿、一个南海岛礁名称或一项争议区修正，预期每种缺失都被明确拒绝。
3. 由人工逐项对照当前公开标准地图完成 SPEC §6 清单，预期核对记录包含基准标识、核对人/日期、结果和未决项；存在未决项时不得完成本 TASK。
4. 执行 `pnpm lint` 与 `pnpm build`，预期资产校验和来源记录不破坏此前能力。

### 完成标准

- SPEC §6 每一项红线均有数据、自动化完整性检查和人工核对结果。
- 明确保留“非官方审图数据、仅供内部展示、正式发布前必须审图”的状态，不产生虚假合规结论。
- 所有验证命令通过，TASK-001 至 TASK-005 的结果无回归。
- 没有重复坐标事实源、来源不明数据、临时补点或绕过校验的 fallback。
- 可以创建仅包含政治边界补充/修正资产、核对记录和验证能力的 Git checkpoint，代码库可安全进入 TASK-007。

### 回退边界

回退本 TASK 只会移除政治边界补充、争议区修正和对应核对能力；TASK-004 的基础 34 省边界与 TASK-005 的地点目录仍然有效。通用领域能力 TASK-007 / TASK-008 等仍可继续推进，但直接消费政治补充数据的 TASK-015 / TASK-019 必须暂停，直至政治边界数据重新完整。
