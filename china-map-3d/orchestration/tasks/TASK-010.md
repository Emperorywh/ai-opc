## 任务描述

### 可验证结果

地形表面按真实米制海拔呈现与 SPEC 一致的深色分层设色和法线明暗，高程颜色不随垂直夸张系数改变；水下、平原、丘陵、高山和雪线区间可直接区分。

### 输入

- SPEC §3.1、§3.2、§3.4、§3.5、§7.1、§9、§12.1–§12.2。
- TASK-003 的 `minH/maxH` 元数据与生产高程资产。
- TASK-009 的 GPU 位移地形和夸张配置。

### 输出

- 一套由真实海拔到颜色的单一领域配置，包含 SPEC 指定的全部断点、基线色和 256×1 颜色查找表示。
- fragment shader 按像素重新采样真实高程并完成归一化查色，不使用位移后的 world-y。
- 地形法线由高程偏导或等价高保真方式得到，并响应方向光形成地势方向感；地形本身不启用高成本阴影贴图。
- 水下高程使用深海近黑颜色，陆地按海拔区间映射；颜色配置可以被 TASK-021 的图例直接复用。
- 自动化测试证明各断点、上下界、插值策略和不同 `k` 下颜色不变。

### 实现约束

- 高程色阶是纯地理语义，不得映射业务数值或省份类别。
- 色阶事实源必须唯一；shader、测试和后续图例不得各自复制断点或颜色。
- 颜色归一化必须使用元数据真实上下限，不能用 world-y、网格包围盒或视觉调参值替代。
- 允许在断点处选择平滑插值或硬切，这是内部实现决策；选择后须有一致测试，不得多套逻辑并存。
- 材质/着色层不得反向依赖 UI 图例组件。
- 色阶配置必须以 TASK-021 可直接消费的格式导出（例如包含断点、基线色和 256×1 ramp 描述的 JSON 或模块），确保图例与 shader 引用同一事实源。
- 新增或修改的代码必须用多行简体中文注释解释真实海拔查色、法线计算和色阶单一事实源；不得主动格式化无关代码。

### 验证方式

1. 执行 `pnpm test`，预期 `<0`、0、200、500、1000、2000、3500、5000、9000 米及相邻值映射到约定色阶。
2. 对同一高程分别设置 `k=1.5`、`2.0`、`3.0`，预期自动化颜色结果完全一致，只有顶点 y 改变。
3. 执行 `pnpm lint` 与 `pnpm build`，预期 shader 与类型检查通过。
4. 人工执行 `pnpm dev` 后自行打开页面；预期青藏高原、雪线、盆地、东部平原和水下区域层次清楚，且没有地形阴影贴图造成的明显性能负担。
5. 临时通过测试夹具提供错误的 `minH/maxH`，预期契约拒绝而非产生偏色结果。

### 完成标准

- 真实海拔分层设色、法线明暗和唯一色阶配置均已交付。
- 自动化证明颜色与夸张系数解耦，全部断点与异常元数据受控。
- 构建、lint、测试和人工视觉验收通过，TASK-009 的地势起伏无回归。
- 没有业务数据映射、world-y 查色、重复色阶或人工阴影贴图。
- 可以创建只包含分层设色与法线结果的 Git checkpoint，代码库可安全进入 TASK-011。

### 回退边界

回退本 TASK 只会移除分层设色与法线明暗，GPU 位移地形仍可运行并显示真实起伏；统一色阶尚未被后续 UI 消费，因此不会破坏此前能力。
