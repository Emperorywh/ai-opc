# SPEC：标准的中国 3D 地图（真实地形版图大屏）

> 适用：`china-map-3d` 独立大屏页面
> 定位：**真实 DEM 地形驱动的中国 3D 地势图，纯地理展示**——不是数据可视化（不映射业务数值到颜色/高度），不是沙盘（不是深色平地+上方实体），不是柱体统计图。
> 技术栈：Vite + React 19 + @react-three/fiber 9 + three 0.185（已有）；需新增 `@react-three/drei`、`d3-geo`（见 §10）。

---

## 1. 背景与目标

当前仓库是一个空的 Vite+R3F 脚手架（`src/App.tsx` 仍是默认模板），git 历史继承自 agv-3d 沙盘项目但代码已重置。

**目标**：在独立大屏页面呈现一张**地理真实、政治边界完整、视觉精致**的中国 3D 地势图——青藏高原隆起、东部平原舒缓、海域半透明流动，配省级贴地描边与广告牌标签，作为可自由旋转的高质感地理展示。

**非目标（明确排除）**：
- ❌ 不做业务数据映射（无 choropleth、无数据色阶、无数据 tooltip）。
- ❌ 不做省→市下钻。
- ❌ 不做卫星影像贴图（地表用分层设色，见 §3.1）。
- ❌ 不做移动端/响应式（仅大屏/高性能机，见 §7.3）。
- ❌ 不做实时数据对接（纯静态地理资产）。

## 3. 视觉规格

### 3.1 地表分层设色

地表为一张覆盖中国范围的连续地形网格，颜色由**真实海拔 `h`**（fragment shader 按像素 UV 重新采样 heightmap 纹理得到，单位米）查色阶渐变得到。**必须用真实 `h`，不要用位移后的 world-y**——world-y 已被垂直夸张系数 `k` 放大（§3.2 的 `y = h·k`），用它查色阶会让整图颜色偏移 `k` 倍（§7.1）。

- **色阶断点**（海拔，米）与基线色（深色科技风适配，可调）：

  | 高程区间 | 地貌 | 基线色（参考） |
  |---|---|---|
  | < 0 | 水下地形（透过半透明海面可见，近岸浅、远海深，见 §3.5） | 深海近黑 `#06121c` |
  | 0 – 200 | 平原 | 深青绿 `#1f4d3a` |
  | 200 – 500 | 丘陵 | 青绿 `#2f6b4a` |
  | 500 – 1000 | 低山 | 橄榄 `#5a7a3a` |
  | 1000 – 2000 | 中山 | 赭黄 `#8a7a33` |
  | 2000 – 3500 | 高山 | 棕褐 `#7a5a2e` |
  | 3500 – 5000 | 极高山 | 深棕紫 `#5e4030` |
  | > 5000 | 雪线以上 | 雪白偏冷 `#d8e4ea` |

- 实现：一张 256×1 的 **ramp texture**（高度→颜色查找表），fragment shader 按 `u = (h - minH) / (maxH - minH)`（`h` 为真实海拔，`minH`/`maxH` 取自 §5.1 meta JSON）归一化后采样；断点处可做平滑插值或硬切。
- 为体现地势方向感，叠加方向光产生的**法线明暗**（见 §3.4）；不在地表另画人工阴影贴图（性能/收益不划算）。
- 色阶整体略压低明度，靠边界线发光与水面反光提亮，避免深色背景下糊成一团。

### 3.2 垂直夸张

- 全局系数 `TERRAIN_EXAGGERATION = 2.0`（可配，范围 1.5–3.0）。
- 真实海拔 `h`（米）→ 世界 y：`y = h * k`，在 vertex shader 中应用（见 §7.1）。
- 注意与投影交互：墨卡托下高纬 x 被放大，若同时大 k，北方地形视觉偏「扁宽」；k=2.0 经验上全境观感平衡。若后续主图范围收窄到不含南海，可适度上调 k。

### 3.3 投影与坐标系

- **Web 墨卡托（EPSG:3857）**：经纬度 → 平面米坐标 `(X, Y)`。
- **主图地理范围**（含南海诸岛真实位置）：
  - 经度：`72°E – 136°E`
  - 纬度：`3°N – 54°N`（南端覆盖到曾母暗沙 ≈ 3.58°N）
- 将该范围的墨卡托坐标线性映射到世界 `(x, z)`（y 为高程），地图中心置于世界原点附近。
- 投影由 `d3-geo` 的 `geoMercator` 完成（边界线、省会点位、附图坐标统一走同一投影函数，避免不一致）。
- **已知特性**：墨卡托在 53°N 放大因子 ≈1.66，北方（黑龙江/内蒙古北部）横向略胖——可接受；若将来需与国家标准阿尔伯斯投影图对照，需知形状不同（见 §13）。

### 3.4 深色氛围（光照 / 天空 / 雾）

- **背景**：纯色或竖向渐变深蓝黑（如 `#070b16` → `#0e1424`），不引入天空盒贴图。
- **方向光**：单盏主光，从西北偏高方位照射（强调青藏—东海的地势梯度），暖白偏冷，开启软阴影**仅用于可选的省界/hover 高亮投影**——地形本身不投递阴影贴图（4096² 级阴影图成本过高）。
- **环境光**：低强度半球光（天/地双色），保证背光面不死黑。
- **雾**：可选极轻微指数雾，柔化地图远缘与背景的衔接（勿过浓，免吞细节）。

### 3.5 海面

- y=0（海平面）一张水平半透明面，覆盖主图海域范围。
- **材质**：半透明（opacity ≈ 0.55–0.7），深蓝青色；fragment shader 用时间驱动的法线扰动（双层流动 noise / gerstner 概念简化）模拟微波。
- **大陆架暗示**：通过半透明可隐约看到水下地形（陆地网格在海面下方延伸），呈现近岸浅、远海深的过渡。为此 §5.1 的 heightmap **保留浅水负高程**（不 clamp 到 0），地形网格在海面下延伸至约 -1500m；水下区域按 §3.1 的深海近黑色着色，透过海面形成由近岸到远海的明→暗深度梯度。
- 海面不参与分层设色（陆地着色仅作用于 y>0 的地形网格）。

### 3.6 边界线（省级贴地描边）

- 数据：DataV 省级 GeoJSON 多边形外边界（见 §5.2），`d3-geo geoMercator` 投影。
- **贴地**：DataV 原始折线顶点稀疏，跨山脊的直线段会穿山或悬空，必须先**沿弧长 densify**（重采样间距接近 heightmap 分辨率，如每 1–2 km 或约 `plane 宽 / 4096` 一个点）；再对每个 densified 顶点投影到世界 `(x, z)`、**采样 CPU 端解码的 heightmap 高度**（见下条）作为 y（`+ epsilon` 避免 z-fighting），使省界随地形起伏紧贴地表。
- **CPU 端 heightmap**：贴地采样与 §7.5 遮挡判定都需要高度查询，运行时须将 §5.1 的 heightmap 解码为一份 CPU 侧数组（4096²×2B ≈ 32MB，双线性采样），供边界 densification / 遮挡射线 / 海面以下判定共用；GPU 位移用的纹理是另一份（见 §7.1）。
- **绘制**：`@react-three/drei` 的 `<Line>`（Line2/LineMaterial），可设线宽、支持 additive 发光。
- **样式**：浅青白 `#9fe8d8` 左右，additive 轻发光；hover 时该省边界加亮加粗（见 §4.2）。
- 合并为尽量少的 draw call（按省分组或整体合并为一条 LineSegments）。

### 3.7 标签（省名 + 省会点位）

- **省名**：`<Billboard>` 包裹 troika `<Text>`，始终面向相机，避免被自身山脉遮挡时也能读到。
- **省会点位**：省会城市坐标处放一个发光光点 sprite（可叠一束细光柱），点位标签用同款 Billboard 文本（或仅 hover 显示，避免拥挤——默认**仅显示点位光点 + 省名**，省会名以 tooltip/小字呈现，最终在实现时定）。
- **字体**：中文需 CJK 字体。为控制体积，**裁剪字体子集**仅含 34 省名 + 省会名 + 附图所需汉字（约百余字），troika 加载该子集 `.ttf`/`.woff`；不打包完整思源黑体。
- **避让**（京津沪港澳密集区）：默认固定于省几何中心/省会坐标，不做实时碰撞推开；当某标签被地形遮挡（raycast 命中地形且距离小于标签距）时降低其透明度，避免视觉穿透的违和感（见 §7.5）。

### 3.8 南海诸岛附图（2D）

- 右下角一个标准 2D 矩形附图（合规惯例），独立于 3D 主图：
  - 九段线（十段画法）、南海诸岛岛礁点、标注。
  - 用 SVG 或 Canvas 2D 绘制（DOM overlay，非 3D），坐标用同一 `geoMercator` 投影的 2D 子范围。
- 主 3D 图中南海诸岛/九段线也已按真实位置呈现（双保险，见 §6）。

## 4. 交互规格

### 4.1 相机与默认视角

- **OrbitControls**（drei）：旋转 / 俯仰 / 缩放 / 平移。
- **默认机位**：东南方向斜俯视——相机置于地图东南上方，看向中心，使青藏高原在画面左上隆起、东部平原在右下，凸显西高东低。
- **范围限制**：
  - 俯仰角：限制最小极角（不允许转到地图背面/看到地底），如 `maxPolarAngle ≈ 88°`。
  - 缩放：`minDistance` / `maxDistance` 限定，禁止无限拉近/拉远飞出版图。
  - 平移：限制 target 在地图包围盒内（防拖出版图）。
  - 禁用 `screenSpacePanning` 或按需，避免平移方向错乱。

### 4.2 hover 反馈

- 鼠标悬停某省（raycast 命中地形后用屏幕坐标反查所属省，或对省边界/区域做拾取）：
  - 该省**边界线加亮加粗**（提升发光强度/线宽）。
  - 该省**标签放大并置顶**（提高透明度/字号）。
  - 其余省份边界可轻微压暗，突出焦点。
- 移出后还原。无 click 行为（纯展示，不点击下钻/飞焦——与「不绑定数据」一致）。

### 4.3 入场动画

- **加载阶段**：drei `<Suspense>` + `useProgress` 显示进度条（DOM overlay）。
- **就绪后**：
  - 地形从 `y=0` 平面动画「升起」至夸张后的真实高度（整体 uniform 缩放或 vertex shader 位移插值，≈1.2s）。
  - 省名标签依次淡入（按地理顺序错峰，如自西向东）。
  - 水面、边界线随后淡入。
- 动画期间锁相机交互，结束后释放 OrbitControls。

## 5. 数据资产与预处理

> 所有外部数据在**构建期/脚本期**处理为静态资产，打进 `public/`，运行时零外部网络依赖。

### 5.1 DEM heightmap 生成 pipeline

- **源数据**：Copernicus DEM GLO-30（30m 分辨率，公开、免费、质量优于 SRTM），AWS Open Data 托管。
- **脚本**（项目内 `scripts/dem/`，Python 3 + `rasterio` + `numpy`）：
  1. 下载覆盖中国范围的 Copernicus DEM tile（按经纬度分块拉取或用 COG 流式读）。
  2. 拼接 → 按 `[lon 72–136, lat 3–54]` 裁剪。
  3. 重投影到 EPSG:3857（墨卡托）。
  4. 重采样到 **4096×4096**（双线性）。
  5. 归一化到 16-bit：编码区间 **[-1500m, 9000m]** → 0–65535。**保留浅水负高程**（呈现大陆架，见 §3.5），仅深海超出 -1500m 处 clamp 到 -1500m；输出 **R16 grayscale PNG**（或 half-float `.exr`/`.raw`）。
  6. 同步导出一份元数据 JSON（范围、分辨率、**高度上下限 `minH=-1500` / `maxH=9000`**），供 §3.1 色阶归一化与 §7.1 位移解码正确还原。
- **Windows 依赖说明**：`rasterio` 在 Windows 可用预编译 wheel（`pip install rasterio`）；若安装受阻，备选用 QGIS 手工导出一次同样的 heightmap（脚本提供参数清单）。
- 输出：`public/terrain/china-heightmap-4096.png` + `public/terrain/china-heightmap.meta.json`。

### 5.2 行政边界 GeoJSON

- **基础**：阿里云 DataV.GeoAtlas 省级边界（`https://geo.datav.aliyun.com/...`，覆盖 34 省、含港澳台）。
- **已知缺陷**：DataV 数据**不含九段线、不含南海诸岛岛礁、部分争议区画法非国标**——必须按 §5.3 / §6 补全。
- 处理：脚本下载后裁剪外层的简化层级，按省切分或整体保留；运行时经 `geoMercator` 投影后送 §3.6 边界线渲染。

### 5.3 九段线与南海岛礁点（项目内补全）

- 由项目内维护一份**九段线（十段画法）经纬度坐标 JSON** + **南海主要岛礁点位 JSON**（坐标取自公开标准地图衍生数据）。
- 九段线作为独立 `LineString` 渲染（贴地/海面），样式与省界区分（如更亮的发光虚线）。
- **声明**：该数据为尽力贴近国标的补充，**非官方审图数据**（见 §8）；正式发布须走自然资源部审图。

### 5.4 南海附图数据

- 复用 §5.2 边界 + §5.3 九段线/岛礁数据，投影到附图 2D 子范围，由 §3.8 的 SVG/Canvas overlay 消费。

### 5.5 省会坐标

- 项目内维护一份 34 省会/首府 `(name, lon, lat)` JSON（公开数据，脚本内置）。

## 7. 渲染与性能工程

### 7.1 GPU 顶点位移（核心策略）

> **纹理分辨率 ≠ 网格分段数**。这是 4096²「高精」能落地的关键。

- **绝对禁止**：在 JS/CPU 端为 4096² 网格逐顶点采样 heightmap 写入 `position`——`4096×4096×(3 pos + 2 uv + 3 normal)×4B ≈ 670MB`，必爆内存且卡顿。
- **正确做法**：
  - 用 `THREE.PlaneGeometry(w, h, SEG, SEG)` 作为基础网格（顶点位置为平面，UV 覆盖 0–1）。
  - 在 **vertex shader** 中按顶点 UV 采样 heightmap 纹理，得高度 `h`，令 `position.y += h * k`（k 为夸张系数，见 §3.2）。
  - 法线同样可在 shader 中通过 heightmap 的偏导（Sobel/有限差分）现场计算，或预烘焙法线贴图。
  - 这样 mesh 分段远低于纹理分辨率也能呈现纹理级起伏细节。
- 入场动画（§4.3）通过一个 uniform `uRise`（0→1）插值位移量实现，零额外几何开销。

### 7.2 网格 / 纹理分辨率落点

| 资产 | 分辨率 | 体积估算 | 说明 |
|---|---|---|---|
| Heightmap 纹理 | 4096² | R16 ≈ 32MB（GPU 纹理） | DEM 高保真细节来源 |
| Plane 分段（默认） | **2048²** | ≈4.2M 顶点，position+uv+normal ≈100MB | 默认档；独显无压力 |
| Plane 分段（上限） | 4096² | ≈16.7M 顶点，≈400MB | GPU 充裕时可上调；临界，需实测 |
| 边界线 | 34 省数千点 | 忽略 | 单/少量 draw call |
| 标签 | 34 Billboard | 忽略 | troika 文本 |

- 默认 `SEG=2048`；通过配置项暴露，大屏独显可上调到 4096 实测帧率后决定。
- 帧率目标：1080p/4K 大屏独显 **≥ 60fps**；若 4096² 分段掉帧，回落 2048²（视觉差异主要在山脊锐利度，纹理细节仍在）。

### 7.3 DPR 与显存预算

- 设 DPR 上限（如 `Math.min(devicePixelRatio, 2)`），避免 4K 屏 ×高 DPR 爆显存（与既有 DPR 经验一致）。
- 高精资产（heightmap 纹理 + 大 mesh）常驻显存，预算单次加载；无流式加载（离线单图方案）。

### 7.4 大屏长时间运行稳定性

- **WebGL context lost**：监听 `webglcontextlost` / `webglcontextrestored`，丢失时暂停渲染、恢复时重建（大屏 24h 运行必备）。
- **resize 防抖**：窗口变化 debounce 后再更新 camera/renderer 尺寸。
- **内存**：无运行时几何分配循环（所有几何/纹理启动期建好），避免 GC 抖动与泄漏。
- **动画时钟**：用统一的 `THREE.Clock` / R3F `useFrame`，水面/入场共用，避免多时钟漂移。

### 7.5 标签遮挡处理

- Billboard 标签虽面向相机，仍可能被前方山脉遮挡。对每个标签做一次 raycast（标签位置 → 相机），若命中地形且命中点更近，则降低该标签透明度；移开/转视角后恢复。
- 34 个标签，raycast 成本可接受（可降频到每 N 帧一次）。

## 12. 验收标准

1. **地形真实**：青藏高原明显隆起、塔里木/四川盆地凹陷、东部平原舒缓，与真实中国地势一致；起伏随垂直夸张 k 可调。
2. **分层设色**：高程→颜色映射正确，色阶图例与地表颜色一一对应。
3. **边界完整（红线）**：九段线（十段）、南海诸岛、台湾、钓鱼岛、藏南、阿克赛钦、港澳全部正确呈现；右下 2D 附图完整。
4. **贴地描边 + 标签**：省界紧贴地形起伏；省名 Billboard 始终可读；省会光点位置正确。
5. **海面**：半透明流动，可透见大陆架。
6. **相机**：东南斜俯视默认机位；旋转/俯仰/缩放/平移受限不飞出、不穿地。
7. **hover**：悬停省份边界加亮加粗、标签放大置顶，移出还原。
8. **入场**：进度条→地形升起→标签淡入，过程顺滑。
9. **性能**：大屏独显 1080p/4K ≥ 60fps（2048² 默认档）。
10. **稳定**：长时间运行无崩溃；context lost 可恢复；resize 正常。
11. **合规**：审图号占位 + 数据源署名角标存在并标注免责声明。

## 13. 风险与权衡

| 风险/权衡 | 说明 | 应对 |
|---|---|---|
| **4096² 顶点爆内存** | CPU 建 geometry 必爆 | 强制 GPU shader 位移（§7.1），默认 2048² 分段 |
| **边界非官方审图** | DataV+自补数据非国标 | 角标声明 + 取得审图号后方可发布（§6/§8） |
| **九段线/岛礁数据准确性** | 自维护数据可能存在偏差 | 以公开标准地图为蓝本核对；正式发布以审图为准 |
| **墨卡托形状差异** | 与国标阿尔伯斯投影图形状不同（北方偏胖） | 已确认接受；主图需与印刷国标图对照时注意 |
| **中文字体体积** | 完整 CJK 字体数 MB | 子集裁剪仅含所需百余字（§3.7） |
| **大字体/大纹理带宽** | 4K 屏高 DPR 下显存/带宽 | DPR 上限 2（§7.3） |
| **高纬+夸张致北方视觉偏扁** | k 与墨卡托叠加效应 | k=2.0 折中；必要时按纬度微调 |
| **WebGL 长时运行** | 大屏 24h 运行 context 丢失 | 监听+恢复（§7.4） |

## 附录 A：建议任务拆分（task 驱动）

> 顺序大致自底向上，资产先行。

1. **TASK 地形资产 pipeline**：DEM 脚本生成 4096² heightmap + meta（§5.1）。
2. **TASK 边界/九段线/省会数据**：拉取 DataV + 补全九段线/岛礁/省会 JSON（§5.2–5.5）。
3. **TASK 投影与数据层**：`lib/projection.ts` 封装 geoMercator，统一投影所有地理数据（§3.3）。
4. **TASK GPU 位移地形**：terrain shader（位移+法线+分层设色）+ 入场 rise uniform（§7.1/§4.3）。
5. **TASK 海面**：半透明流动法线 shader（§3.5）。
6. **TASK 贴地省界 + hover**：Line 描边贴地 + 拾取高亮（§3.6/§4.2）。
7. **TASK 标签 + 省会点**：Billboard 文本 + 光点 + 字体子集 + 遮挡处理（§3.7/§7.5）。
8. **TASK 南海 2D 附图**：SVG/Canvas overlay（§3.8）。
9. **TASK 相机/氛围/场景**：OrbitControls 限位 + 光照/雾/背景（§3.4/§4.1）。
10. **TASK 入场与加载**：进度条 + 升起 + 标签淡入编排（§4.3）。
11. **TASK 外围 UI + 合规**：海拔图例 + 审图号/署名角标（§8/§9）。
12. **TASK 稳定性与性能**：context lost 恢复、resize 防抖、DPR 上限、帧率实测调档（§7.3/§7.4）。
