title: 纳入全部真实运行时资产的加载闭环
---

## 任务描述

### 可验证结果

首次进入页面时，加载进度覆盖所有最终页面必需的外部静态资产，包括高程、行政区、政治边界、地点、实际离线字体及字体清单、来源注册表和其他不可缺少的静态输入；任一资产失败都会进入可诊断错误状态并保持交互关闭，不会在资源尚未就绪时开始入场。

### 输入

- TASK-005 完成后的完整可见场景。
- 当前资产加载 hooks、加载进度、入场状态机、离线字体、合规来源和南海附图输入。
- 运行时零外网、无自动低清/旧资产/fallback 的全局约束。

### 输出

- 唯一必需资产清单和显式 `loading/ready/error` 状态聚合契约。
- 加载进度只反映已登记的真实资产完成情况，不由计时器或固定总数伪造。
- 实际字体文件的可用性纳入加载结果，而不只校验字体清单。
- 来源注册表和合规 UI 必需输入纳入就绪条件，不能在主场景交互后才静默缺失。
- 资源乱序完成、失败和 StrictMode 重挂载下状态仍确定。

### 业务规则与状态不变量

- 只有全部必需外部资产 `ready` 时才允许从加载阶段进入场景准备/入场阶段。
- 首个失败原因和对应资产必须可定位；失败状态不可自动恢复为成功。
- 已完成资产不得因其他资产失败而重复请求。
- 加载进度不能包含非必需装饰资源，也不能遗漏最终必须显示的资产。

### 实现约束

- Coding Agent 必须先检查实际运行时请求和字体加载行为，再自主决定资产编排结构。
- 资产加载层不得依赖具体 3D 组件；页面、场景和 UI 只能消费聚合状态。
- 禁止复制多个同类加载 hook、通过固定常量假设资产数量或在视图组件中私自 fetch。
- 不引入远程重试、在线字体、旧资源或低清 fallback。
- 新增或修改的代码必须使用多行简体中文注释解释资产清单、进度语义、乱序完成和失败不变量；不得格式化无关代码。

### 验证方式

1. 执行 `pnpm test`，模拟全部资产不同顺序完成，预期进度只随真实完成项增长且最终恰好进入 ready。
2. 分别模拟高程、行政区、政治数据、地点、实际字体、字体清单和来源注册表失败，预期均进入可诊断 error 并锁定交互。
3. 自动化重复挂载和 StrictMode 重挂载，预期无重复请求状态、提前入场或永远 99%。
4. 执行 `pnpm lint` 与 `pnpm build`。
5. 人工断网运行本地生产构建，预期全部资产仍可加载；删除测试环境中的任一必需资产时显示明确错误，不得自动启动浏览器。

### 完成标准

- 所有最终必需外部资产均被真实进度和失败闭环覆盖。
- 实际字体与合规来源不会在场景交互后才失败或消失。
- 没有假进度、遗漏资产、重复加载逻辑或外网 fallback。
- 测试、lint、构建和人工断网验收通过。

### Git checkpoint

可以创建只包含资产清单、加载状态编排、测试和必要说明的独立 Git checkpoint；checkpoint 后代码库可安全进入 TASK-007。

### 回退边界

回退本 TASK 恢复此前资产加载聚合方式，不回退地形、深度、海面或高程所有权修复。
