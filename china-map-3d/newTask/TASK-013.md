## 任务描述

### 可验证结果

修复后的完整地图在目标独显设备上以生产默认配置运行时，1080p和4K动态交互场景达到持续60fps目标并保留可复核测量记录；长时间运行、重复hover、相机旋转、标签密集区、南海区域、context恢复和resize均无持续内存增长、资源重复或视觉回归。

### 输入

- TASK-001 至 TASK-012 的完整修复结果。
- 当前生产DPR、地形网格档位、遮挡检查频率、draw call预算、运行时恢复和全部资产验证命令。
- 目标独显设备、浏览器、1080p/4K显示环境及不得隐藏必要地图要素的验收规则。

### 输出

- 记录GPU、浏览器、分辨率、DPR、网格档位、采样时长、fps分布、显存/内存可观测指标、draw call和场景操作路径的最终测量记录。
- 对逐帧分配、重复几何/材质/纹理、标签遮挡频率、边界draw call和透明层成本的最终审计；必要优化纳入本 TASK。
- 完整回归清单，证明真实地形、海面、政治边界、标签、hover、入场、合规UI和恢复能力未被性能优化破坏。
- 无法达到目标时保留真实证据并使 TASK 保持未完成/阻塞，不伪造通过。

### 业务规则与状态不变量

- 生产默认网格精度、政治必需要素、34省标签、南海附图和合规UI不得为帧率被隐藏或删除。
- 不得缩小实际渲染尺寸、自动切换低清、引入运行时流式网络或只测静止空闲帧。
- DPR、网格档位和检查降频必须显式配置；高配档不得自动启用。
- 性能优化不得破坏模块边界、单一事实源或资源所有权。

### 实现约束

- Coding Agent 必须先检查目标设备的真实测量和当前瓶颈，再自主选择必要优化；不得基于猜测提前重写。
- 本 TASK 的结果是“目标场景性能被真实验收”，不是只增加预算常量或测试断言。
- 不自动启动浏览器；所有目标硬件测量由用户手动执行并记录。
- 禁止把资产、领域、交互、渲染和UI合并为巨型组件换取局部调用减少。
- 新增或修改的代码必须使用多行简体中文注释解释预算、缓存所有权、降频和测量边界；不得格式化无关代码。

### 验证方式

1. 执行 `pnpm test`、全部资产校验、`pnpm lint` 和 `pnpm build`，预期全部通过。
2. 人工运行生产构建，在目标设备以1080p持续采样；期间旋转、缩放、平移、hover多个省份并经过标签密集区和南海区域，预期稳定≥60fps。
3. 在同一设备以4K和生产DPR预算重复动态采样，预期稳定≥60fps并记录完整分布，而非单一瞬时值。
4. 重复context lost/restore、连续resize和长时间运行，预期资源数量与内存趋势稳定、画面和交互可恢复。
5. 对比TASK-012验收画面，确认地貌、海面、边界、标签、附图和合规信息无隐藏或降质。

### 完成标准

- 自动化、资产校验、lint和构建全部通过。
- 目标独显设备上1080p与4K生产默认场景持续达到60fps，并保留可复核测量记录。
- 长时间、context恢复和resize路径无持续内存增长、重复资源或视觉状态漂移。
- TASK-001至TASK-012的全部可见结果和架构不变量无回归。
- 若4K未达标，本 TASK 必须保持阻塞，直至基于真实瓶颈完成合法优化并重新验收；不得以隐藏要素、自动低清或虚假记录完成。

### Git checkpoint

可以创建只包含最终性能固化、必要优化、完整回归记录和测量证据的最终 Git checkpoint；checkpoint 后代码库处于完整、一致、可运行、可验证状态。

### 回退边界

回退本 TASK 只移除最终性能优化、预算调整和测量记录；TASK-012 的完整功能与视觉结果仍保留，但系统重新处于4K性能未验收状态。
