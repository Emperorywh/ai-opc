## 任务描述

### 可验证结果

外部资产加载完成后，地形、贴地省界、政治线点、标签与字体覆盖、南海附图、海拔图例和合规角标的派生准备结果全部进入统一场景就绪状态；任一必需层准备失败时页面显示明确诊断且不进入入场或交互，绝不出现“控制器已解锁但地图残缺”的状态。

### 输入

- TASK-006 的完整外部资产加载状态。
- 当前省界、政治要素、标签、南海附图、图例和合规角标准备能力。
- 当前入场状态机、相机交互锁和错误 overlay。

### 输出

- 明确区分“外部资产已加载”和“最终场景已准备”的集中状态模型。
- 所有必需派生层具有 `pending/ready/error` 或等价可推导状态，并向统一编排器报告结果。
- 入场只从完整场景 ready 开始；交互只在入场完成且运行时正常时启用。
- 准备失败的错误层、错误原因和恢复边界可诊断，不再只写控制台后渲染空值。

### 业务规则与状态不变量

- 任一时刻场景只能是准备中、准备失败、入场中或完整可交互之一，不允许隐式布尔组合形成矛盾状态。
- 省界、政治要素、标签、附图或合规信息缺失时不能宣称页面完整。
- 同一准备工作在一次资产版本和配置组合下最多执行一次；配置变化只能重算受影响的派生结果。
- 错误不得自动忽略、降级或用旧派生结果覆盖。

### 实现约束

- Coding Agent 必须先检查当前各层捕获异常和返回空值的路径，再自主设计集中状态边界。
- 领域准备层只返回结果或错误，不直接控制 DOM、相机或加载 UI；编排层只组合状态，不复制领域计算。
- 禁止每个视图组件维护独立“是否可用”布尔值或私自吞错。
- 不通过隐藏失败图层、降低政治完整性或取消字体覆盖校验换取 ready。
- 新增或修改的代码必须使用多行简体中文注释解释两阶段就绪、错误传播和交互解锁不变量；不得格式化无关代码。

### 验证方式

1. 执行 `pnpm test`，驱动“资产加载完成→场景准备完成→入场→交互”状态序列，预期严格有序且每阶段只进入一次。
2. 分别注入省界、政治要素、标签字体覆盖、南海附图和合规角标准备失败，预期进入错误状态、显示对应诊断且交互保持关闭。
3. 自动化验证资产乱序、配置切换和 StrictMode 下无重复准备、旧结果覆盖或提前解锁。
4. 执行 `pnpm lint` 与 `pnpm build`。
5. 人工使用测试夹具触发一个派生错误，预期页面明确报错而不是缺一层后继续运行；不得自动启动浏览器。

### 完成标准

- 外部加载与场景派生形成完整两阶段就绪闭环。
- 所有必需层失败都能阻断入场和交互，并提供可定位错误。
- 不再存在只记录 `console`、返回空层但页面进入 interactive 的路径。
- 测试、lint、构建和人工异常验收通过。

### Git checkpoint

可以创建只包含场景就绪编排、错误传播、交互锁及相关测试的独立 Git checkpoint；checkpoint 后代码库可安全进入 TASK-008。

### 回退边界

回退本 TASK 只移除派生场景就绪闭环；TASK-006 的真实资产加载状态及此前视觉修复保持不变。
