## 任务描述

### 可验证结果

默认完整中国视角下，`k=2.0` 时青藏高原明显高于东部平原，塔里木和四川盆地相对周边山地明显下凹，雪线与主要地势梯度可直接观察；`k=1.5–3.0` 只连续改变垂直起伏强度，不改变地理位置、真实海拔、色阶语义或各图层对齐关系。

### 输入

- TASK-001 完成后的唯一真实米制高程查询能力。
- 统一墨卡托投影、主图地理范围、当前地形位移、边界、政治要素、标签和相机坐标语义。
- 已确认的配置边界：垂直夸张对外仍表达为 `1.5–3.0`，默认 `2.0`；颜色按真实海拔而非显示高度计算。

### 输出

- 一套统一、显式、可测试的“地理米制数据到渲染空间”显示契约，使全国尺度与垂直地貌在视觉上同时成立。
- 地形、边界、政治线点、标签、相机、遮挡和 hover 所有三维消费者使用同一渲染空间语义，不存在分层魔法缩放。
- 默认视角下可辨识地貌的量化基线，例如关键高程样本的屏幕或渲染空间相对差异，但不把设备相关像素写成领域数据。
- 保留真实米制数据层；显示尺度变化不得回写或改造离线地理资产。

### 业务规则与状态不变量

- 真实海拔、显示高度和垂直夸张必须是三个可推导、不可混淆的概念。
- 地表颜色、海拔图例、海陆分类和数据署名只能使用真实海拔。
- 同一地理点的地形、边界、标签和政治要素在任意合法 `k` 下保持重合。
- `k` 变化只影响垂直显示结果，不影响投影、经纬度反查、色阶或资产缓存。

### 实现约束

- Coding Agent 必须先检查实际坐标流和所有消费者，再自主决定显示变换的模块位置与内部形式。
- 显示变换属于坐标/渲染适配边界，不得散落在组件、材质和数据资产中。
- 禁止为个别山脉、盆地、省份或标签加入局部高度补丁。
- 不得通过修改 DEM、伪造海拔、缩小地图范围或隐藏南海区域制造起伏。
- 必要的坐标架构重构必须在本 TASK 完成，后续 TASK 不得成为图层重新对齐的条件。
- 新增或修改的代码必须使用多行简体中文注释解释真实米制与显示空间的关系；不得格式化无关代码。

### 验证方式

1. 执行 `pnpm test`，验证代表性西部高地、盆地、东部平原和海平面样本经过显示变换后顺序与相对关系正确。
2. 自动化分别设置 `k=1.5/2.0/3.0`，验证地理 `x/z`、真实海拔与色阶完全不变，显示高度单调变化。
3. 自动化验证地形、贴地边界、政治线点、标签锚点和遮挡采样在相同位置使用一致显示高度。
4. 执行 `pnpm lint` 与 `pnpm build`。
5. 人工执行 `pnpm dev` 后自行打开页面，在默认全图视角确认青藏高原、主要盆地和东部平原可直接辨认；不得自动启动浏览器。

### 完成标准

- 默认视角的地形体积感达到可辨识结果，且不是依靠颜色或边界假装起伏。
- 所有三维图层保持统一对齐，`k` 的职责边界由自动化证明。
- 真实海拔、显示尺度和色阶之间没有跨层耦合或重复公式。
- 测试、lint、构建及人工地貌验收通过。

### Git checkpoint

可以创建只包含统一显示尺度、必要坐标重构、测试和验收说明的独立 Git checkpoint；checkpoint 后代码库可安全进入 TASK-003。

### 回退边界

回退本 TASK 恢复此前显示尺度，不回退 TASK-001 的高程所有权，也不修改任何离线地理资产。
