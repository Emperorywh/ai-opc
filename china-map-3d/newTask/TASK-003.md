title: 固化全相机范围的深度精度闭环
---

## 任务描述

### 可验证结果

在默认、最近、最远及接近最大俯仰角的全部合法相机状态下，低海拔陆地、海面、水下地形、贴地省界、十段线、地点光点和标签遮挡关系稳定，不出现陆地与海面交替覆盖、规则闪烁、边界穿插或深度量化条带。

### 输入

- TASK-002 完成后的统一渲染空间与可辨识地形。
- 当前受约束相机、地形、海面、边界、政治要素、标签和深度偏移语义。
- 1080p/4K 大屏、默认独显和长期运行约束。

### 输出

- 从地图包围盒、最大显示高度和相机操作范围推导的深度精度预算与相机裁剪契约。
- 对海平面附近、东部低地、岛屿、高原和水下大陆架的最小可分辨深度进行可复核计算或自动验证。
- 所有可见层遵循一致的深度测试、写入和排序语义；局部深度偏移只能用于贴地线等明确场景。
- 相机约束在 resize 和 context 恢复后继续满足同一深度预算。

### 业务规则与状态不变量

- 海拔接近 `0m` 的陆地仍必须稳定遮挡海面，不能依赖偶然的深度缓冲舍入。
- 水下地形必须位于海面之后但保持可透视；陆地不得被透明海面着色。
- 边界与政治线只能通过可解释的统一偏移防止贴面闪烁，不能永久穿透前方地形。
- 相机不得为提高深度精度而破坏既有全图构图、缩放范围或禁止看地底的规则。

### 实现约束

- Coding Agent 必须先检查实际相机矩阵、渲染空间量级和各材质深度语义，再选择内部技术方案。
- 深度策略必须集中管理，不得按图层堆叠互相抵消的魔法偏移。
- 不得以隐藏低地、抬高海平面、删除水下地形或缩短合法相机范围伪造稳定。
- 不冻结具体图形 API 或深度算法选择，但结果必须在目标浏览器和硬件可验证。
- 新增或修改的代码必须使用多行简体中文注释解释深度预算、裁剪面推导和透明层关系；不得格式化无关代码。

### 验证方式

1. 执行 `pnpm test`，验证相机近远裁剪、合法距离和最大显示高度满足明确深度预算。
2. 自动化覆盖 `0–200m` 低地、海平面、负高程大陆架、贴地 epsilon 和最大高地样本，预期深度顺序确定。
3. 自动化执行 resize 与 context 恢复后的相机状态，预期裁剪与深度不变量保持一致。
4. 执行 `pnpm lint` 与 `pnpm build`。
5. 人工在默认、最近、最远和低俯角视角持续旋转观察海岸、东部平原、岛屿和边界，预期无扫描线、闪烁或穿插；不得自动启动浏览器。

### 完成标准

- 合法相机范围内的深度关系全部稳定，并有量化预算与自动化覆盖。
- 截图中陆地大面积横向条带的深度根因已消除。
- 没有图层私有魔法偏移、隐藏要素或相机能力退化。
- 测试、lint、构建和人工深度验收通过。

### Git checkpoint

可以创建只包含深度精度、相机裁剪及必要材质语义调整的独立 Git checkpoint；checkpoint 后代码库可安全进入 TASK-004。

### 回退边界

回退本 TASK 只移除深度精度修复和相关相机/材质约束，不回退统一高程所有权或地形显示尺度。
