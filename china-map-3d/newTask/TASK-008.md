---

## 任务描述

### 可验证结果

藏南、阿克赛钦及政治完整性清单要求的边界修正不再只是“契约中存在但运行时忽略”的资产，而是确定性作用于最终主图行政区边界、所属判断和人工核对产物；缺少、重复、冲突或无法追溯的修正会阻断完整场景就绪。

### 输入

- TASK-007 完成后的场景准备失败闭环。
- 基础 34 省行政区边界、政治边界补充契约、争议区修正和既有来源/人工核对记录。
- 统一投影、高程贴地、行政区稳定标识及“正式发布前必须审图”的合规约束。

### 输出

- 单一、明确的最终行政区几何事实，说明基础边界和政治修正如何形成运行时可消费结果。
- 贴地省界、hover 所属判断及其他行政区消费者统一使用修正后的最终几何。
- 机器可检的必需争议区清单、冲突检查和来源追溯；人工核对记录同步反映最终渲染事实。
- 修正无法确定时任务保持失败/阻塞，不得继续呈现可能错误的完整地图。

### 业务规则与状态不变量

- 藏南、阿克赛钦等必需修正必须恰好存在且来源可追溯。
- 基础边界和修正不得形成两套可被不同图层选择的并行事实源。
- 修正后的行政区稳定 ID、地点关联、投影和高程贴地语义保持不变。
- 自动化完整性与人工核对不能替代正式审图；页面仍为非官方、仅内部展示。

### 实现约束

- Coding Agent 必须先检查实际政治资产、基础几何和运行时消费路径，再自主决定修正应用边界。
- 禁止凭视觉猜测坐标、在组件中补点、复制一份专用几何或把项目补充伪装成 DataV 官方数据。
- 政治数据准备层不得依赖 React、Three.js、hover 状态或 UI。
- 若现有资产缺少可追溯依据，必须明确阻塞，不得生成临时边界。
- 新增或修改的代码必须使用多行简体中文注释解释政治红线、修正合并、来源边界和无法自动证明的事项；不得格式化无关代码。

### 验证方式

1. 执行 `pnpm verify:assets -- --scope political` 与 `pnpm verify:assets -- --scope provinces`，预期必需修正、来源和最终行政区集合通过。
2. 执行 `pnpm test`，分别删除藏南、阿克赛钦修正或制造重复/冲突修正，预期最终几何准备明确失败。
3. 自动化验证贴地省界与省份所属判断消费同一修正后几何，不再读取基础几何旁路。
4. 执行 `pnpm lint` 与 `pnpm build`。
5. 人工逐项对照可追溯公开标准地图基准核对最终主图，并记录核对人、日期、基准和未决项；存在未决项不得完成。不得自动启动浏览器或公开部署。

### 完成标准

- 所有点名争议区修正真实作用于最终主图和交互事实。
- 缺失、冲突和来源不明路径均可阻断场景完整就绪。
- 基础边界与修正没有形成双轨或组件级补丁。
- 资产校验、测试、lint、构建和人工核对通过，仍明确未取得审图号。

### Git checkpoint

可以创建只包含最终边界事实、政治修正消费、校验和核对记录的独立 Git checkpoint；checkpoint 后代码库可安全进入 TASK-009。

### 回退边界

回退本 TASK 只移除政治修正对最终行政区几何的应用及相关核对；基础 34 省边界和政治补充原始资产仍保留，但完整场景必须重新处于不可验收状态。
