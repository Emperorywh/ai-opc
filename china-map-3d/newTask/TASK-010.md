## 任务描述

### 可验证结果

地形、海面、边界、政治线点、标签和地点光点的 GPU 资源具有明确所有者并可复用、恢复和释放；重复挂载、配置切换、WebGL context 丢失/恢复和连续 resize 不会增加重复纹理、重复几何、重复材质、监听器或时钟，也不会重新解码 CPU 高程或重新请求外部资产。

### 输入

- TASK-001 的唯一 CPU 高程资源所有权。
- TASK-007 的完整场景就绪状态。
- 当前 GPU 纹理、地形几何、重复球体/线材质、context 恢复、resize 和统一帧循环能力。

### 输出

- 可审计的 GPU 资源所有权和复用契约，覆盖创建、共享、恢复、配置变更和卸载释放。
- 相同静态几何和材质在适合复用的地点光点、岛礁点等消费者间不重复创建无意义副本。
- context 恢复只重建丢失的 GPU 表示，继续复用有效 CPU 资产和领域派生结果。
- resize 只有一个实际提交路径，最终尺寸等于最后输入，不与框架内部即时更新形成双重所有权。
- 恢复失败进入统一场景错误状态，不空白死循环、不自动刷新或 fallback。

### 业务规则与状态不变量

- CPU 高程解码次数不因 context 恢复增加。
- 同一活动场景中每类共享 GPU 资产的所有者数量稳定且可解释。
- 配置切换只能更新必要 uniform 或重建确有变化的资源，不能重载全部资产。
- 卸载后事件监听、定时器、几何、材质和纹理引用必须可释放。

### 实现约束

- Coding Agent 必须先检查真实 GPU 对象创建点、框架自动生命周期和恢复行为，再自主设计所有权边界。
- 不冻结实例化、共享或缓存的具体实现模式，但禁止隐式全局缓存和永不释放的单例。
- 不得通过刷新页面、重新 fetch、重新解码高程或回退低清资源完成恢复。
- 性能优化必须保持资产、领域、交互和渲染分层，不得合并为巨型场景组件。
- 新增或修改的代码必须使用多行简体中文注释解释 GPU/CPU 所有权分离、复用、恢复和清理；不得格式化无关代码。

### 验证方式

1. 执行 `pnpm test`，重复挂载/卸载、配置切换和 StrictMode 重挂载，预期纹理、几何、材质、监听器和时钟计数稳定。
2. 自动化模拟多次 `running→lost→restoring→running` 与恢复失败，预期 CPU 高程不重新解码、外部资产不重新请求、GPU 资源可恢复或明确失败。
3. 自动化连续输入 resize，预期有限提交且最终尺寸等于最后输入；卸载后不再生效。
4. 执行 `pnpm lint` 与 `pnpm build`。
5. 人工触发 context lost/restore 和连续窗口变化，预期画面、交互与 overlay 恢复一致；不得自动启动浏览器。

### 完成标准

- GPU 资源创建、复用、恢复和释放形成可测试闭环。
- 重复点位资源、重复生命周期监听和 resize 双重所有权已消除。
- context 恢复不重新解码 CPU 高程、不重新下载资产且失败可诊断。
- 测试、lint、构建和人工恢复验收通过。

### Git checkpoint

可以创建只包含 GPU 生命周期、资源复用、恢复/resize 修复和测试的独立 Git checkpoint；checkpoint 后代码库可安全进入 TASK-011。

### 回退边界

回退本 TASK 恢复此前 GPU 生命周期实现，不回退唯一 CPU 高程、视觉、政治边界或 hover 修复。
