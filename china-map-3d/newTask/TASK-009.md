## 任务描述

### 可验证结果

鼠标悬停依据用户实际看到的位移地形表面确定地理位置和所属省份；在高原、盆地、斜视、缩放、不同 `k`、海岸和省界附近，不再因命中 `y=0` 平面造成水平偏移或错误省份焦点。焦点仍保持单一、可恢复且没有 click 行为。

### 输入

- TASK-008 的修正后最终行政区几何。
- TASK-002 的统一地形显示空间、当前相机射线、真实高程和单一 hover 状态。
- 已完成的省界、标签遮挡与 hover 样式合成规则。

### 输出

- 从屏幕指针到可见地形交点、再到经纬度与行政区稳定 ID 的确定性交互契约。
- 海域、地图外、无命中、内环、岛屿和相邻边界具有明确无焦点或唯一焦点结果。
- 地形显示夸张改变后命中仍与可见表面一致，不维护第二套低精拾取平面事实。
- 边界与标签只消费最终焦点状态，不自行执行重复拾取。

### 业务规则与状态不变量

- 同一时刻最多一个 `hovered province`，以稳定行政区 ID 表达。
- 指针命中位置必须对应可见地形，而不是海平面、包围盒或未位移平面。
- 海域和地图外必须恢复无焦点；快速跨省不得残留多个高亮。
- click、下钻、飞焦、业务 tooltip 和数据加载仍然不存在。

### 实现约束

- Coding Agent 必须先检查实际事件射线、位移地形和坐标反查链路，再自主选择拾取方式。
- 拾取领域能力可依赖相机、地形和最终行政区几何，不得修改资产、渲染对象或 UI。
- 禁止保留平面拾取作为隐藏 fallback，禁止按省份增加点击 mesh 或复制一套行政区几何。
- 不得以扩大省界容差掩盖地形交点错误；相邻边界规则必须确定且可测试。
- 新增或修改的代码必须使用多行简体中文注释解释地形命中、坐标反查、单一焦点和恢复不变量；不得格式化无关代码。

### 验证方式

1. 执行 `pnpm test`，覆盖高原、盆地、平原、岛屿、内环、海域、地图外和相邻边界的屏幕射线命中。
2. 自动化在 `k=1.5/2.0/3.0` 和代表性相机姿态下验证命中世界点位于可见地形表面，所属省份一致。
3. 自动化驱动 `无→A省→B省→海域→无` 和 click，预期焦点原子切换且 click 无状态迁移。
4. 执行 `pnpm lint` 与 `pnpm build`。
5. 人工在青藏高原、横断山区、四川盆地、海南和省界密集区快速移动鼠标，预期焦点与视觉位置一致；不得自动启动浏览器。

### 完成标准

- hover 命中与真实位移地形形成完整闭环。
- 高差、相机、`k`、海域和边界异常场景均有自动化覆盖。
- 没有平面拾取 fallback、重复几何、对象引用状态或 click 行为。
- 测试、lint、构建和人工交互验收通过。

### Git checkpoint

可以创建只包含真实地形拾取、焦点状态必要调整及测试的独立 Git checkpoint；checkpoint 后代码库可安全进入 TASK-010。

### 回退边界

回退本 TASK 只移除真实地形 hover 拾取及其焦点反馈；修正后的静态边界、标签、地形和海面仍保持完整，但 hover 重新处于不可验收状态。
